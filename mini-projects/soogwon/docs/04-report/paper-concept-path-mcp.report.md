### 3.2 신뢰성 및 운영 기능

- OpenAlex 응답을 Zod 스키마로 검증하고 내부 도메인 모델로 정규화했다.
- 요청별 타임아웃과 도구 전체 deadline을 적용했다.
- 429, 5xx, 일반 네트워크·JSON 오류의 재시도를 `Retry-After`와 deadline 정책으로 통합했다.
- 일일 요청 예산이 소진되면 호출 내부에서 불필요하게 재시도하지 않는다.
- 성공 응답 TTL/LRU 캐시와 404 음성 캐시를 제공한다.
- 요청 수, 크레딧, 비용 상한을 도구 호출 단위로 적용한다.
- JSON Lines 구조화 로그를 stderr로 출력하고 검색어·API 키는 기록하지 않는다.
- 20,000자 응답 제한 시 구조화된 `CONTENT_TRUNCATED` 경고를 제공한다.
- 제목 없는 OpenAlex 후보는 목록에서 제외하되 정상 후보를 이용한 탐색은 계속한다.
- 개념 경로는 `paths` 배열에 점수순 최대 3개를 반환하며 경로가 없으면 빈 배열과 `PATH_NOT_FOUND` 경고를 제공한다.
- 노드 상한에 도달해도 실제 수용된 논문만 간선으로 연결해 유효한 부분 경로를 안전하게 반환한다.

## 4. 설계 대비 남은 차이

다음 항목은 로컬 프로토타입의 핵심 기능을 막지 않으므로 후속 개선으로 분리했다.

| 항목 | 현재 상태 | 후속 판단 기준 |
|------|-----------|----------------|
| OpenAlex 동시 요청 3개 | 순차 실행으로 안전하게 제한 | 실제 응답시간 측정에서 병목이 확인될 때 도입 |
| 반복 주제 페널티·세부 동률 기준 | 결정론적 기본 기준 구현 | 품질 평가에서 경로 다양성 문제가 확인될 때 개선 |
| 동일 DOI 버전 그룹화 | 그룹 키와 ID 중복 제거 구현 | 사전출판본·출판본 중복이 품질에 영향을 줄 때 확장 |
| 5개 분야 품질 평가 데이터셋 | 미작성 | 원격 또는 공개 배포 전에 수행 |
| Inspector·라이브 OpenAlex 검증 기록 | 실행 방법만 문서화 | 배포 후보 버전에서 기록 생성 |
| Streamable HTTP 원격 전송 | 설계만 완료 | 별도 배포 기능의 PDCA로 진행 |

## 5. 배운 점

### 5.1 잘된 점(Keep)

- Plan과 Design에서 범위와 제외 항목을 먼저 고정해 전문 수집, LLM 판정, UI로 범위가 커지는 것을 방지했다.
- MCP 계층, 서비스, 제공자, 도메인 로직을 분리해 외부 API 없이 대부분의 동작을 검증할 수 있었다.
- 인용 사실과 의미적 추론을 데이터 모델에서 구분해 결과의 근거 수준을 명확히 했다.
- 비용·요청·시간·응답 크기를 함께 제한해 외부 제공자 장애가 전체 도구 실행을 오래 점유하지 않도록 했다.
- 코드 검토에서 발견한 재시도 취소 오류에 회귀 테스트를 추가해 같은 문제가 다시 발생하지 않도록 했다.

### 5.2 개선할 점(Problem)

- 초기 설계의 테스트 목록이 넓어 핵심 구현이 완료된 뒤에도 일부 품질 평가 항목이 남았다.
- PDCA 상태의 `matchRate`가 분석 문서의 90.0%와 자동으로 동기화되지 않아 문서와 상태를 함께 확인해야 했다.
- 실제 OpenAlex 데이터는 계속 변하므로 모의 테스트만으로 검색 품질과 응답시간을 확정할 수 없다.

### 5.3 다음에 시도할 것(Try)

- 배포 전 5개 연구 분야의 고정 평가 데이터셋을 만들고 관련성·직접 인용 비율·응답시간·비용을 측정한다.
- 라이브 검증 결과를 자동화 테스트와 분리해 반복 가능한 인수 기록으로 남긴다.
- 성능 측정 결과에 따라 제한된 동시성과 DOI 버전 그룹화를 작은 독립 기능으로 추가한다.
