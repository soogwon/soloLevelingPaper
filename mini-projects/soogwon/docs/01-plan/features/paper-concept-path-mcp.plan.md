## 1. 개요

### 1.1 목적

AI 클라이언트가 연구 주제가 여러 논문을 거치며 어떻게 발전했는지 탐색할 수 있도록 소규모 로컬 모델 컨텍스트 프로토콜(MCP) 서버를 만든다. 시작 논문, 논문 식별자 또는 개념 검색어를 입력하면 단순한 검색 결과 목록 대신 관련 개념과 이를 뒷받침하는 논문을 연결한 간결하고 설명 가능한 경로를 반환한다.

### 1.2 배경

연구자는 어떤 선행 연구가 개념을 처음 제안했는지, 후속 논문이 이를 어떻게 확장했는지, 이후 어디에 적용됐는지 파악해야 할 때가 많다. 일반적인 논문 검색 도구는 문서와 인용 관계를 제공하지만, 사용자가 직접 개념의 발전 경로를 재구성해야 한다. 이 기능은 AI 도우미가 조사하고 설명할 수 있는 형태로 해당 경로를 구성하는 명확한 MCP 인터페이스를 제공한다.

현재 저장소에는 구현 코드나 별도의 제품 명세가 없으므로, 사용자 계정 없이 하나의 공개 논문 데이터 제공자를 사용하는 로컬 읽기 전용 프로토타입을 전제로 한다. 데이터 제공자, 순위 산정 방식 및 MCP SDK는 Design 단계에서 확정한다.

## 2. 목표

### 2.1 주요 목표

- [ ] 시작 논문 또는 개념 검색어를 받아 관련 논문 메타데이터를 조회하는 MCP 도구를 제공한다.
- [ ] 선택된 각 논문과 관련된 핵심 개념을 추출하거나 정규화한다.
- [ ] 개념이 여러 논문에서 소개, 확장, 대조 또는 적용되는 과정을 짧고 순서가 있는 경로로 구성한다.
- [ ] 논문 식별 정보, 연도, 관계 유형 및 간단한 근거를 포함해 각 경로 단계의 증거를 제공한다.
- [ ] 잘못된 식별자, 제공자 장애 또는 근거 부족 상황에서 예측 가능한 오류와 부분 결과를 제공한다.
- [ ] 초보자가 로컬 환경에서 실행할 수 있는 설치 설명과 대표 예시를 제공한다.

### 2.2 목표가 아닌 항목

- 운영 환경 규모의 학술 검색 엔진을 호스팅하거나 완전한 논문 색인을 유지하는 것
- 유료 논문 전문을 다운로드하거나 출판사의 접근 제한을 우회하는 것
- 사용자 검증 없이 체계적 문헌고찰, 인용 지표 또는 학술적으로 확정된 주장을 생성하는 것
- 사용자 계정, 협업 기능, 데이터베이스 기반 대시보드 또는 그래픽 지식 지도 UI를 만드는 것
- 논문을 자동으로 작성하거나 제출하는 것

## 3. 범위

### 3.1 포함 범위

- 최소한의 읽기 전용 도구를 제공하는 로컬 MCP 서버
- 지원되는 논문 식별자, URL, 제목 또는 개념 검색어를 이용한 시작점 확인
- 제목, 저자, 연도, 가능한 경우 초록 또는 요약, 식별자, 인용·참고문헌 연결 및 출처 URL 등 필수 메타데이터의 조회와 정규화
- 제공되는 메타데이터와 초록을 이용한 가벼운 개념 추출
- 제공자가 지원하는 인용, 참고문헌 및 의미 기반 검색을 통한 후보 확장
- 최대 깊이와 최대 결과 수처럼 설정 가능한 제한을 적용한 경로 순위 산정
- 노드, 관계, 근거, 경고 및 출처 표시를 포함하는 설명 가능한 응답 스키마
- 로컬 개발과 제공자 정책 준수를 위한 캐싱 및 요청 속도 제한
- 입력 검증, 타임아웃 처리, 빈 결과 처리 및 명확한 MCP 오류
- 결정론적 변환·순위 로직의 단위 테스트와 모의 데이터 기반 MCP 종단 간 테스트
- 사전 요구사항, 설정, 실행 방법, MCP 클라이언트 등록, 예시, 제한 사항 및 데이터 출처를 설명하는 README

### 3.2 제외 범위

- 웹 UI, 모바일 UI 또는 시각화 렌더링
- 영구적인 다중 사용자 저장소, 인증, 권한, 결제 또는 분석 기능
- 초기 버전의 논문 전문 PDF 수집·분석, OCR, 임베딩 인프라 또는 로컬 벡터 데이터베이스
- 초기 릴리스에서 여러 학술 데이터 제공자를 동시에 사용하는 기능
- 백그라운드 크롤링 또는 대량 수집
- 생성된 경로가 완전하거나 인과적이며 원문 확인 없이 인용 자료로 사용할 수 있다는 주장

## 4. 기능 요구사항

### FR-1: 상태 및 기능 탐색

서버는 로컬에서 실행되고 선택한 MCP 전송 방식으로 연결되어야 한다. MCP 클라이언트가 도구를 올바르게 호출할 수 있도록 도구 목록과 충분한 설명 메타데이터를 제공해야 한다.

### FR-2: 논문 확인

지원되는 식별자, URL 또는 제목을 정규화된 논문 레코드로 변환해야 한다. 제목 검색 결과가 모호하면 근거 없이 하나를 확정하지 않고 후보 목록 또는 경고를 반환해야 한다.

### FR-3: 개념 검색

일반 문장으로 작성된 개념 검색어를 받아 경로의 시작점으로 사용할 수 있는 제한된 수의 관련 정규화 논문을 반환해야 한다.

### FR-4: 개념 경로 생성

시작점과 선택적인 목표 개념 또는 목표 논문을 입력받아 순서가 있는 경로를 생성해야 한다. 경로 깊이와 후보 수에는 안전한 제한을 적용해야 한다.

### FR-5: 설명 가능한 관계

경로에서 인접한 각 논문 쌍에는 `소개`, `확장`, `대조`, `적용` 등의 관계 유형과 사용 가능한 메타데이터에 근거한 간결한 설명을 포함해야 한다. 추론한 관계는 추론임을 명시해야 한다.

### FR-6: 출처 근거

각 논문 노드에는 데이터 제공자, 가능한 경우 안정적인 식별자, 출처 URL, 제목, 연도 및 관련 개념어를 포함해야 한다. 누락된 필드는 만들어내지 말고 누락 사실을 명시해야 한다.

### FR-7: 오류 및 부분 결과

잘못된 입력, 제공자 오류, 요청 한도 초과, 타임아웃 및 근거 부족에 대해 사용자가 조치할 수 있는 메시지를 제공해야 한다. 유효한 부분 경로는 경고와 함께 반환할 수 있다.

### FR-8: 설정

데이터 제공자 자격 증명, 엔드포인트 옵션, 요청 제한 및 캐시 설정은 문서화된 환경 설정으로 제공해야 하며 비밀값을 저장소에 커밋해서는 안 된다.

## 5. 비기능 요구사항

- **사용성:** 구현 코드를 읽지 않아도 도구 이름, 설명, 매개변수 및 오류를 이해할 수 있어야 한다.
- **성능:** 캐시가 준비된 상태에서 대표적인 단일 논문 조회는 2초 이내, 기본 경로 요청은 제공자 장애 시간을 제외하고 10초 이내 완료를 목표로 한다.
- **신뢰성:** 모든 외부 호출에는 타임아웃과 제한된 재시도를 적용하며, 잘못된 제공자 응답 때문에 서버가 종료되어서는 안 된다.
- **안전 및 개인정보 보호:** 서비스는 읽기 전용이며 사용자 계정 데이터를 수집하지 않고 비밀값을 로그에 남기지 않는다. 제공자에 필요한 검색 데이터만 전송한다.
- **근거 무결성:** 존재하지 않는 논문, 식별자, 인용, 초록 또는 관계 근거를 만들어서는 안 된다. 휴리스틱 결론은 추론임을 표시해야 한다.
- **유지보수성:** 제공자 접근, 정규화, 개념 추출, 경로 생성 및 MCP 전송 계층의 경계를 명확히 하고 각각 독립적으로 테스트할 수 있어야 한다.
- **호환성:** 문서에 명시된 런타임에서 실행되어야 하며 최소 하나의 표준 MCP 클라이언트 설정과 호환되어야 한다.
- **제공자 정책 준수:** 요청, 캐싱, 출처 표시 및 속도 제한은 선택한 제공자의 공개 이용 약관을 따라야 한다.

## 6. 성공 기준(완료 정의)

- [ ] 새 로컬 환경에서 README만 보고 의존성을 설치하고 서버를 실행하며 MCP 도구 목록을 확인할 수 있다.
- [ ] 지원되는 논문 식별자 또는 제목을 추적 가능한 출처 메타데이터가 포함된 정규화 레코드로 변환할 수 있다.
- [ ] 개념 검색 결과에 가능한 경우 안정적인 식별자 또는 출처 링크가 포함된 유용한 논문 후보가 반환된다.
- [ ] 제공자 데이터가 충분하면 대표 시작점에서 근거를 갖춘 논문 노드 3개 이상의 제한된 경로가 생성된다.
- [ ] 모든 경로 간선에 관계 유형, 근거 설명 및 근거·추론 여부가 포함된다.
- [ ] 잘못된 입력, 검색 결과 없음, 제공자 타임아웃 및 요청 한도 초과 상황이 테스트되며 조치 가능한 오류 또는 경고를 반환한다.
- [ ] 순위와 데이터 변환 테스트는 결정론적이며 실제 네트워크 연결 없이 실행된다.
- [ ] 추적되는 파일에 비밀값이 없고 로그에서 설정된 자격 증명이 제거된다.
- [ ] README 예시에 예상 응답 형식, 알려진 제한 사항, 제공자 출처 및 학술적 주장을 원문에서 확인하라는 주의사항이 포함된다.
- [ ] 완료 보고 전에 설계와 구현의 일치율이 90% 이상이어야 한다.

## 7. 아키텍처 고려사항

- 첫 버전은 MCP 전송 계층, 요청 검증, 제공자 어댑터, 정규화 도메인 모델, 개념·경로 서비스, 캐시 및 응답 포맷터로 작게 구성한다.
- MCP 도구 계약을 변경하지 않고 다른 제공자를 추가할 수 있도록 학술 데이터 제공자 접근을 어댑터 뒤에 격리한다.
- 초기 프로토타입은 불투명한 순위 모델보다 결정론적이고 확인 가능한 점수 방식을 우선한다. 각 관계 선택에 영향을 준 요소를 기록한다.
- 그래프 탐색에는 깊이, 후보 수, 타임아웃 및 제공자 요청 예산 제한을 적용해 과도한 탐색을 방지한다.
- 허용되는 경우에만 제공자 메타데이터와 초록을 사용한다. 출처 링크를 보존하고 인용된 메타데이터와 생성된 설명을 구분한다.
- 초기에는 데이터베이스를 사용하지 않는다. Design 단계에서 필요성과 정책 적합성이 확인된 경우에만 소규모 메모리 또는 파일 기반 캐시를 사용한다.
- 런타임, 언어, MCP SDK, 데이터 제공자 및 정확한 도구 이름은 Design 단계의 결정 사항으로 남긴다.

## 8. 구현 규칙 선행조건

구현 전에 Design 단계에서 다음 사항을 정해야 한다.

- 런타임과 지원 버전
- 소스, 테스트, 설정 및 문서 디렉터리 규칙
- MCP 도구, JSON 필드, 모듈 및 오류의 이름 규칙
- 포맷팅, 린트, 타입 검사 및 테스트 명령어
- 환경변수 이름과 `.env.example` 관리 정책
- 정규화된 논문, 개념, 경로 노드, 경로 간선, 경고 및 오류 스키마
- 출처 표시, 추론 문장, 구조화 로그, 비밀값 제거 및 제공자 테스트 데이터 규칙

| 모호한 제목이 잘못된 논문으로 연결됨 | 높음 | 중간 | 안정적인 식별자를 우선하고 신뢰도가 낮으면 후보와 신뢰도를 제시한다. |
| 요청 한도 또는 장애로 탐색이 느려지거나 실패함 | 중간 | 높음 | 캐싱, 속도 제한, 범위 제한, 타임아웃, 제한된 재시도 및 부분 결과를 제공한다. |
| 제공자 약관이 캐시 또는 파생 결과를 제한함 | 높음 | 중간 | Design 단계에서 약관을 검토하고 캐시 기간과 저장 필드를 설정 가능하게 만든다. |
| 경로 탐색 규모가 기하급수적으로 증가함 | 중간 | 중간 | 깊이, 너비, 총 요청 수, 경과 시간 및 응답 크기를 제한한다. |
| 범위가 논문 전문 수집 또는 UI 개발로 확대됨 | 중간 | 중간 | 제외 범위를 지키고 첫 MCP 계약이 안정된 이후로 확장 작업을 미룬다. |
| 런타임 또는 MCP 클라이언트 차이로 설정이 실패함 | 중간 | 중간 | 지원 버전을 고정하고 문서화한 클라이언트 설정을 반복 가능한 방식으로 검증한다. |

## 11. Design 단계에서 결정할 질문

1. 어떤 학술 데이터 제공자가 범위, 이용 약관, 요청 한도 및 인용·참고문헌 데이터 접근성 면에서 가장 적합한가?
2. 첫 버전에서 식별자·제목 시작점만 지원할 것인가, 아니면 자유 형식 개념 검색도 같은 도구에서 지원할 것인가?
3. 시간순 발전, 인용 연결, 의미적 유사성 또는 사용자 선택 방식 중 어떤 경로 의미가 가장 중요한가?
4. 메타데이터만으로 어떤 관계 유형을 신뢰성 있게 지원할 수 있는가?
5. 초기 설정에서 API 키를 허용할 것인가, 아니면 기본 제공자가 자격 증명 없이 작동해야 하는가?
6. 최대 깊이, 후보 너비, 타임아웃 및 응답 크기의 적절한 기본값은 무엇인가?
7. 어떤 MCP 클라이언트와 전송 방식을 인수 테스트 기준으로 삼을 것인가?
