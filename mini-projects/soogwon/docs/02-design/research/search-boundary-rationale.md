# 논문 경로 탐색 기본값의 비용·품질 근거

> 작성일: 2026-08-28
> 관련 기능: `paper-concept-path-mcp`
> 관련 설계: `docs/02-design/features/paper-concept-path-mcp.design.md`
> 문서 성격: 초기 설계 가정 및 검증 계획

## 1. 결정 대상

첫 구현에서 다음 값을 기본값으로 사용한다.

| 항목 | 초기 기본값 | 허용 범위 |
|------|-------------|-----------|
| 탐색 깊이 | 2 | 1~3 |
| 노드별 후보 수 | 6 | 2~10 |
| 최종 경로 길이 | 최대 4편 | 2~5편 |
| 전체 탐색 노드 | 최대 50개 | 고정 안전 한도 |
| 외부 요청 | 기본 최대 20회 | 절대 최대 40회 |
| OpenAlex 크레딧 | 도구 호출당 최대 100 | 응답 헤더로 실제 사용량 확인 |
| 예상 비용 | 도구 호출당 최대 미화 $0.01 | 초과 예상 시 부분 결과 |
| 요청당 타임아웃 | 5초 | 환경변수로 조정 |
| 전체 내부 작업 시간 | 8초 | 부분 결과 허용 |

이 값은 OpenAlex 또는 연구 문헌이 제시한 최적값이 아니다. 초기 프로토타입에서 비용, 응답시간, 결과 다양성 및 설명 가능성을 함께 측정하기 위한 보수적인 출발점이다. 따라서 “비용과 품질의 균형이 검증된 값”이 아니라 “검증 가능한 규모로 제한한 초기 기본값”으로 표현해야 한다.

## 2. 탐색 깊이 2의 근거

노드별 후보를 6개로 제한한 완전한 트리를 가정하면 깊이별 최대 후보 수는 다음과 같다.

```text
깊이 0: 시작 논문                     1개
깊이 1: 시작 논문의 후보              6개
깊이 2: 깊이 1 후보 각각의 후보       36개
합계                                  43개
```

계산식은 `1 + 6 + 6² = 43`이며 전체 노드 안전 한도 50개 안에 들어간다.

깊이를 3으로 늘리면 제한 전 이론적인 노드 수는 다음과 같다.

```text
1 + 6 + 6² + 6³ = 259개
```

실제 구현에서는 중복 논문 제거와 상위 후보 가지치기로 노드 수가 줄지만, 분야와 시작 논문에 따라 감소 폭을 보장할 수 없다. 따라서 첫 버전은 깊이 2를 기본으로 하고, 깊이 3은 사용자가 명시적으로 선택한 경우에만 허용한다.

## 3. 노드별 후보 6개의 근거

후보 수가 적으면 중요한 인용 연결을 놓칠 가능성이 높아지고, 후보 수가 많으면 관련성이 약한 논문과 외부 요청이 빠르게 증가한다.

깊이 2에서 후보 수에 따른 이론적 노드 수는 다음과 같다.

| 후보 수 | 계산 | 이론적 노드 수 |
|---------|------|-----------------|
| 4 | `1 + 4 + 4²` | 21 |
| 6 | `1 + 6 + 6²` | 43 |
| 8 | `1 + 8 + 8²` | 73 |
| 10 | `1 + 10 + 10²` | 111 |

후보 6개는 전체 노드 한도 50개와 자연스럽게 맞지만, 검색 품질이 가장 좋다는 실증 근거는 없다. 구현 후 후보 4·6·8·10개를 비교해 기본값을 조정해야 한다.

후보 구성은 한 종류에 편중되지 않도록 가능한 경우 다음 범주를 섞는다.

- 시작 논문이 참고한 선행 논문
- 시작 논문을 인용한 후속 논문
- OpenAlex가 제공하는 관련 논문
- 목표 검색어와 Topic·Keyword가 일치하는 논문

## 4. 최대 경로 길이 4편의 근거

논문 4편은 세 개의 관계 간선을 제공하므로 다음과 같은 최소한의 발전 흐름을 표현할 수 있다.

```text
선행 연구 → 기반 연구 → 후속 연구 → 최근 적용 또는 관련 연구
```

경로가 너무 짧으면 변화 과정을 설명하기 어렵고, 너무 길면 다음 문제가 커진다.

- 낮은 점수의 약한 관계가 포함될 가능성
- 각 관계의 근거를 확인해야 하는 사용자 부담
- MCP 응답 크기와 모델 컨텍스트 사용량 증가
- 일부 약한 간선이 전체 경로의 신뢰도를 낮추는 현상

따라서 4편을 기본 최대 길이로 사용하되, 분야별 평가에서 3편과 5편도 비교한다.

## 5. OpenAlex API 비용 근거

2026-08-28에 확인한 OpenAlex 공식 문서 기준 비용은 다음과 같다.

| 작업 | 1,000회당 비용 | 호출 1회당 비용 |
|------|----------------|------------------|
| 단일 엔터티 조회 | 무료 | 무료 |
| 목록·필터 조회 | 미화 $0.10 | 약 $0.0001 |
| 키워드 검색 | 미화 $1.00 | 약 $0.001 |
| 의미 검색 | 미화 $1.00 | 약 $0.001 |

무료 API 키는 하루 미화 $1의 사용 예산을 제공하고, 키가 없으면 하루 미화 $0.10의 예산을 제공한다. 비용과 정책은 변경될 수 있으므로 구현과 운영 시 응답의 사용량 헤더를 확인해야 한다.

- [OpenAlex 요금 개요](https://help.openalex.org/access/pricing/)
- [OpenAlex 인증과 요청 제한](https://help.openalex.org/api/authentication/)

### 5.1 경로 요청 1회의 예시 비용

제목 검색 1회와 목록·필터 조회 19회를 모두 사용하는 보수적인 예시는 다음과 같다.

```text
키워드 검색 1회:  1 × $0.001  = $0.0010
필터 조회 19회:  19 × $0.0001 = $0.0019
합계:                            $0.0029
```

이 계산은 예상치를 설명하기 위한 예시이며 고정 비용이 아니다.

- DOI·OpenAlex ID로 시작하면 단일 논문 조회가 무료이므로 검색 비용이 빠질 수 있다.
- 참고문헌 ID를 최대 100개까지 묶어 조회하면 요청 수가 줄어든다.
- 메모리 캐시가 적중하면 외부 호출이 발생하지 않는다.
- 의미 검색을 여러 번 사용하면 비용이 증가한다.
- 재시도나 제공자 정책 변경에 따라 비용이 달라질 수 있다.

외부 요청을 20회로 제한하는 목적은 비용뿐 아니라 장애 전파, 응답시간 및 제공자 부하를 함께 제한하는 것이다. 호출 종류마다 비용이 다르므로 요청 수만으로는 부족하다. 도구 호출당 최대 100크레딧과 예상 비용 미화 $0.01도 함께 적용하며, 어느 한도든 초과할 것으로 예상되면 탐색을 중단하고 부분 결과를 반환한다. 실제 응답에 포함되는 `X-RateLimit-*` 헤더와 비용 메타데이터를 기록해 추정치와 실제 사용량을 비교한다.

## 6. 품질의 정의

이 설계에서 품질은 단순히 논문 수가 많은 것을 의미하지 않는다. 다음 지표를 함께 사용한다.

| 지표 | 의미 | 초기 측정 방식 |
|------|------|----------------|
| 관련 논문 포함률 | 기대 논문이 후보와 최종 경로에 포함되는 정도 | 주제별 기준 논문 목록과 비교 |
| 직접 인용 간선 비율 | 경로 중 실제 인용으로 확인되는 관계 비율 | `referenced_works` 기반 계산 |
| 경로 관련성 | 각 논문이 시작·목표 주제와 맞는 정도 | Topic·Keyword 및 수동 평가 |
| 설명 가능성 | 사용자가 경로 선택 이유를 이해할 수 있는 정도 | 근거 필드 완전성 및 수동 평가 |
| 결정론 | 같은 데이터와 입력에서 같은 결과가 나오는 정도 | 반복 테스트 |
| 응답시간 | 사용자가 기다리는 시간 | p50·p95 측정 |
| API 사용량 | 호출 수와 비용 | 응답 헤더와 요청 통계 |
| 부분 결과율 | 제한에 걸려 완전한 탐색을 못 한 비율 | `truncated` 집계 |

## 7. 검증 실험

구현 후 최소 5개의 서로 다른 연구 분야와 각 분야의 알려진 시작 논문을 준비한다. 기대 논문과 선정 근거는 알고리즘 결과를 보기 전에 고정해 사후 편향을 줄인다. 가능하면 두 평가자가 경로 관련성과 설명 가능성을 독립적으로 평가하고 의견 불일치를 기록한다. 다음 조합을 반복 실행한다.

```text
탐색 깊이:       1, 2, 3
노드별 후보:     4, 6, 8, 10
최대 경로 길이:  3, 4, 5
```

모든 조합을 전부 실행하면 `3 × 4 × 3 = 36개` 설정이며, 5개 주제에서는 180회 실행이 된다. 비용을 통제하기 위해 먼저 모의 OpenAlex 데이터로 알고리즘을 검증한 뒤, 대표 조합만 실제 API에서 비교한다.

### 7.1 기본값 유지 기준

다음 조건을 모두 만족하면 깊이 2, 후보 6개, 경로 4편을 유지한다.

- 대표 주제의 기대 논문 포함률이 사전에 정한 기준을 충족한다.
- p95 응답시간이 10초 이하이다.
- 일반 요청에서 `truncated`가 빈번하게 발생하지 않는다.
- 경로당 실제 API 비용이 정한 예산 안에 들어간다.
- 더 큰 설정이 품질을 의미 있게 개선하지 않는다.
- 1위와 2위 경로의 점수 차이가 작을 때 불확실성 경고가 제공된다.

정확한 품질 합격 기준은 기준 데이터셋을 만든 뒤 확정한다. 현재 단계에서 특정 정확도 수치를 임의로 약속하지 않는다.

## 8. 결론

현재 기본값은 다음 이유로 선택했다.

1. 깊이 2와 후보 6개는 이론적으로 43개 노드로, 전체 한도 50개 안에 들어간다.
2. 경로 4편은 세 개의 관계를 통해 짧은 발전 흐름을 표현할 수 있다.
3. 외부 요청 20회 제한은 경로 요청 하나의 비용·응답시간·장애 범위를 제한한다.
4. 모든 값이 설정 가능하므로 실제 품질 측정 후 조정할 수 있다.

따라서 이 값들은 비용과 품질의 최적 균형을 입증한 결과가 아니라, 그 균형을 측정하기 위한 초기 기준선이다.
