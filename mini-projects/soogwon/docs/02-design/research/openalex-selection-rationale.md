# OpenAlex 데이터 제공자 선정 근거

> 작성일: 2026-08-28
> 관련 기능: `paper-concept-path-mcp`
> 관련 설계: `docs/02-design/features/paper-concept-path-mcp.design.md`
> 결정 상태: 첫 번째 제공자로 선정, 구현 후 품질 재평가

## 1. 결정 요약

`paper-concept-path-mcp`의 첫 번째 학술 데이터 제공자로 OpenAlex를 사용한다.

선정의 핵심 이유는 논문 검색, 논문 식별, 인용·참고문헌 그래프, 관련 논문, Topic·Keyword, 연도 및 출처 정보를 하나의 공개 REST API에서 제공하기 때문이다. 이 조합은 별도 논문 데이터베이스나 임베딩 인프라 없이 초기 개념 경로 프로토타입을 구현하는 데 적합하다.

OpenAlex를 영구적으로 고정하지 않는다. 애플리케이션은 `ScholarlyProvider` 인터페이스를 사용하고 OpenAlex는 첫 번째 어댑터로 구현한다. 품질 평가 결과가 부족하면 다른 제공자를 추가하거나 교체할 수 있다.

## 2. 선정 기준

첫 제공자는 다음 기준을 만족해야 한다.

| 기준 | 필요한 이유 |
|------|-------------|
| 안정적인 논문 식별자 | 경로 노드 중복 제거와 출처 추적 |
| 제목·DOI·주제 검색 | 사용자가 정확한 ID를 몰라도 시작 가능 |
| 참고문헌과 피인용 관계 | 실제 인용 간선을 구성 |
| 주제·키워드 | 인용이 없는 관련 논문 후보와 근거 구성 |
| 발행 연도 | 전후 관계와 시간 방향 검증 |
| 관련 논문 후보 | 인용 데이터가 부족할 때 보조 탐색 |
| 일괄 조회 | 그래프 탐색의 요청 수와 비용 절감 |
| 명확한 사용 정책과 비용 | 로컬 개발 및 향후 배포 비용 예측 |
| 출처 URL | 사용자가 원문 정보를 확인할 수 있게 함 |
| 어댑터 구현 가능성 | 제공자 고유 필드를 내부 모델로 정규화 |

## 3. OpenAlex가 제공하는 핵심 데이터

OpenAlex Work 객체에서 이 프로젝트가 사용하는 주요 필드는 다음과 같다.

| OpenAlex 데이터 | 프로젝트 용도 |
|-----------------|---------------|
| OpenAlex Work ID | 내부 논문 ID와 중복 제거 |
| DOI | 외부 표준 식별자와 정확한 논문 확인 |
| `title`, `authorships` | 사용자 결과와 후보 식별 |
| `publication_year` | 시간 방향과 설명 근거 |
| `referenced_works` | 해당 논문이 인용한 선행 논문 |
| `cites` 필터 | 해당 논문을 인용한 후속 논문 검색 |
| `related_works` | 제공자가 계산한 관련 논문 후보 |
| `topics`, `primary_topic` | 주제 유사도와 설명 근거 |
| `keywords` | 세부 개념의 겹침 계산 |
| `cited_by_count` | 후보 정렬의 보조 정보 |
| `is_retracted` | 철회 논문 경고 또는 기본 제외 |
| `abstract_inverted_index` | 존재할 때만 초록 복원과 용어 근거 보강 |

공식 자료:

- [OpenAlex Works 개요](https://developers.openalex.org/api-reference/works)
- [OpenAlex 단일 Work 조회](https://developers.openalex.org/api-reference/works/get-a-single-work)
- [OpenAlex API 활용 예시](https://help.openalex.org/how-to/api-recipes/)

## 4. 프로젝트 요구사항과의 적합성

### 4.1 논문 시작점 확인

OpenAlex는 Work ID와 DOI를 이용한 단일 조회를 지원하고, 제목이나 일반 문장을 이용한 Works 검색도 지원한다. 따라서 다음 입력을 하나의 제공자에서 처리할 수 있다.

- OpenAlex Work ID
- OpenAlex URL
- DOI 및 DOI URL
- 논문 제목
- 자유 형식 연구 주제

### 4.2 실제 인용 경로 구성

`referenced_works`를 이용하면 논문이 실제로 참고한 선행 논문을 확인할 수 있다. 반대 방향은 `cites:{workId}` 필터를 이용해 해당 논문을 인용한 논문을 찾을 수 있다.

이 관계는 서버가 계산한 의미적 유사성과 구분해 `inferred=false`로 표시할 수 있다. 다만 인용 사실은 논문의 동의, 확장, 반박 또는 적용을 자동으로 증명하지 않는다.

### 4.3 주제 기반 보조 경로 구성

OpenAlex는 각 Work에 Topic과 Keyword를 제공하며 관련 Work ID도 제공한다. 직접 인용 관계가 없거나 인용 데이터가 부족한 경우 다음 근거를 사용해 보조 후보를 만들 수 있다.

- 공통 Topic ID와 점수
- 공통 Keyword와 점수
- OpenAlex의 `related_works`
- 목표 주제 검색 관련도

이 관계는 알고리즘 또는 제공자가 계산한 관계이므로 `inferred=true`로 표시한다.

### 4.4 검색 방식

OpenAlex는 키워드 검색과 의미 검색을 제공한다. 사용자는 논문 제목을 몰라도 연구 질문이나 주제로 시작할 수 있다. 의미 검색은 표현이 다른 관련 논문을 찾는 데 유용하지만, 비용과 결과 재현성을 측정한 뒤 기본 활성화 여부를 결정한다.

- [OpenAlex 검색 가이드](https://developers.openalex.org/guides/searching)

## 5. 비용과 운영 적합성

2026-08-28에 확인한 공식 문서 기준으로 단일 엔터티 조회는 무료이고, 목록·필터와 검색은 사용량 기반 비용이 적용된다. 무료 계정의 API 키는 하루 미화 $1의 사용 예산을 제공하며, 키 없이도 하루 미화 $0.10 범위에서 시험할 수 있다.

이 구조가 초기 프로젝트에 유리한 이유는 다음과 같다.

- 결제 없이 로컬 프로토타입을 시작할 수 있다.
- 단일 DOI·ID 확인은 무료다.
- 목록·필터 조회 비용이 검색보다 낮다.
- 응답 헤더에서 남은 예산과 요청 비용을 확인할 수 있다.
- 일괄 조회와 캐시로 그래프 탐색 요청을 줄일 수 있다.

비용은 변경될 수 있으므로 README에 고정된 요금표를 복사하기보다 공식 링크와 사용량 확인 방법을 제공한다.

- [OpenAlex 비용 예시](https://help.openalex.org/access/example-costs/)
- [OpenAlex 요금 개요](https://help.openalex.org/access/pricing/)
- [OpenAlex 인증과 요청 제한](https://help.openalex.org/api/authentication/)

## 6. 일괄 조회와 응답 최적화

OpenAlex는 OR 필터에 최대 100개 값을 전달할 수 있고 페이지당 최대 100개 결과를 지원한다. 이를 이용하면 참고문헌 ID를 하나씩 조회하지 않고 묶어서 가져올 수 있다.

```text
참고문헌 30개 개별 조회: 최대 30회
OpenAlex ID OR 필터 조회: 1회
```

또한 `select`를 이용해 필요한 필드만 요청하면 응답 크기와 정규화 비용을 줄일 수 있다. 공식 문서도 `per_page=100`, OR 일괄 조회 및 `select` 사용을 권장한다.

### 6.1 API 키 보안

API 키는 환경변수에서 읽어 `Authorization: Bearer ...` 헤더로만 전송한다. URL 쿼리, 캐시 키, 로그, 오류 및 결과 메타데이터에는 포함하지 않는다. OpenAlex 개인 키는 로그인 자격 증명 역할도 할 수 있으므로 노출되면 즉시 회전해야 한다. README에 키 생성·보관·회전 절차를 안내한다.

## 7. 데이터 사용과 출처 표시

OpenAlex의 학술 메타데이터는 CC0로 제공된다. 프로젝트는 각 결과에 OpenAlex ID, DOI, 출처 URL 및 사용한 관계 근거를 보존한다.

다만 다음 항목을 구분한다.

- 데이터가 공개되어 있다는 사실
- OpenAlex가 데이터를 API로 제공하는 서비스 비용
- 논문 전문의 저작권과 접근 권한

이 프로젝트는 OpenAlex 메타데이터를 사용하며 유료 논문 전문을 내려받거나 접근 제한을 우회하지 않는다.

## 8. 대안 대비 판단

첫 버전에서는 여러 제공자를 동시에 연동하지 않는다. 제공자마다 식별자, 인용 방향, 주제 분류, 요청 제한 및 오류 형식이 달라 초기 복잡성이 크게 증가하기 때문이다.

대안은 후속 평가 대상으로 유지한다.

| 대안 | 강점 | 첫 버전에서 보류한 이유 |
|------|------|-------------------------|
| Crossref | DOI 중심의 권위 있는 등록 메타데이터 | 이 프로젝트에 필요한 주제·관련 논문·양방향 그래프를 한 흐름에서 구성하기에는 추가 데이터 소스가 필요할 수 있다. |
| Semantic Scholar | 논문 검색과 인용 그래프 및 의미 기반 기능 | 정책, 필드 범위와 실제 대상 분야 품질을 별도로 비교한 뒤 보조 제공자로 검토한다. |
| 로컬 OpenAlex Snapshot | 전체 데이터와 대규모 분석 가능 | 초기 로컬 MCP에 필요한 저장 공간과 데이터 운영 부담이 과도하다. |
| 자체 PDF·임베딩 색인 | 관계 판정과 설명을 세밀하게 제어 가능 | 전문 수집 권한, 저장소, 임베딩 비용 및 검색 인프라가 필요해 첫 범위를 초과한다. |

이 표는 각 대안의 전체적인 우열을 의미하지 않는다. 현재 기능 범위에서 초기 구현 복잡성과 필요한 데이터의 결합 정도를 비교한 것이다. 대안을 실제로 도입할 때는 당시 공식 문서와 정책을 다시 조사한다.

## 9. 알려진 한계와 대응

| 한계 | 영향 | 대응 |
|------|------|------|
| 인용 데이터가 불완전할 수 있음 | 실제 경로 누락 | 부분 결과 경고와 다른 제공자 검토 |
| `related_works`가 추론 관계임 | 사용자가 실제 인용으로 오해 | `inferred=true`와 근거 유형 표시 |
| Topic·Keyword 품질이 분야별로 다름 | 관련성 점수 편차 | 대표 분야별 평가와 가중치 조정 |
| 평문 초록이 항상 존재하지 않음 | 세부 개념 판정 제한 | 없는 초록을 생성하지 않고 `null` 처리 |
| 인용이 의미 관계를 설명하지 않음 | 확장·반박·적용 오판 | 첫 버전은 `cites`, `cited_by`, `related`, `topic_similar`만 사용 |
| 제공자 정책과 요금이 변경될 수 있음 | 운영 비용과 오류 변화 | API 헤더 관찰, 문서 링크, 설정 가능한 제한 |
| 단일 제공자 장애 | 기능 전체 영향 | 타임아웃, 제한된 재시도, 캐시 및 제공자 인터페이스 |
| 한국어 검색어의 검색 품질 편차 | 관련 논문 누락 | 선택적 `query_en`을 받고 자동 번역은 후속 범위로 분리 |
| DOI·사전출판본·출판본 중복 | 경로 중복과 시간 왜곡 | OpenAlex ID·DOI·제목/저자/연도 기반 버전 그룹 표시 |
| 사용자의 미공개 연구 주제 전송 | 개인정보·연구 기밀 우려 | 전송 사실 고지, 검색어 로그 금지, 민감 검색어 경고 |
| 데이터와 순위의 시간별 변화 | 같은 입력의 결과 변화 | 조회 시각, 점수·스키마 버전, 설정값 기록 |

## 10. 제공자 추상화

OpenAlex 고유 로직은 다음 인터페이스 뒤에 둔다.

```ts
interface ScholarlyProvider {
  searchWorks(input: ProviderSearchInput, signal: AbortSignal): Promise<SearchResult>;
  getWork(identifier: string, signal: AbortSignal): Promise<PaperDetail | null>;
  getWorksByIds(ids: string[], signal: AbortSignal): Promise<PaperDetail[]>;
  getCitingWorks(id: string, limit: number, signal: AbortSignal): Promise<PaperDetail[]>;
}
```

MCP 도구와 경로 알고리즘은 OpenAlex 응답 객체를 직접 사용하지 않고 정규화된 `PaperDetail`을 사용한다. 이를 통해 다음 변경을 국소화한다.

- OpenAlex 필드 변경
- 두 번째 제공자 추가
- 제공자별 결과 병합
- 모의 제공자를 이용한 네트워크 없는 테스트

## 11. 구현 후 재평가 기준

OpenAlex를 최종적으로 유지하려면 최소한 다음을 확인한다.

1. 대표 연구 분야 5개 이상에서 알려진 논문을 식별할 수 있는가?
2. 기준 DOI와 제목이 모호하지 않게 확인되는가?
3. 기대한 직접 인용 관계가 충분히 포함되는가?
4. Topic과 Keyword가 사람이 이해할 수 있는 근거를 제공하는가?
5. 경로 생성의 p95 응답시간과 API 비용이 목표 범위에 들어오는가?
6. 철회·연도 누락·초록 누락을 안전하게 처리하는가?
7. 다른 제공자를 추가했을 때 얻을 품질 향상이 복잡성보다 큰가?
8. 한국어 검색과 명시적 영어 검색어의 결과 차이는 어느 정도인가?
9. 사전출판본·출판본·정정·철회 항목이 안전하게 구분되는가?
10. API 응답의 실제 크레딧과 비용이 도구별 예산 안에 들어오는가?

OpenAlex만으로 기대 품질을 충족하지 못하면 다음 순서로 대응한다.

1. 검색·점수 가중치 조정
2. OpenAlex 쿼리와 일괄 조회 개선
3. Crossref를 DOI·기본 메타데이터 보강용으로 검토
4. Semantic Scholar 등 인용·관련성 보조 제공자 검토
5. 필요할 때만 전문 또는 임베딩 기반 기능을 별도 Plan으로 추진

## 12. 결론

OpenAlex를 선정한 이유는 “무료이기 때문”만이 아니다. 첫 버전에 필요한 검색, 식별자, 인용·참고문헌, 관련 논문, Topic·Keyword, 발행 연도 및 일괄 조회를 하나의 API에서 제공해 별도 데이터 인프라 없이 설명 가능한 논문 경로를 시험할 수 있기 때문이다.

동시에 데이터 완전성과 관계 의미에는 한계가 있으므로 실제 인용과 추론을 구분하고, 제공자 어댑터를 통해 교체 가능성을 유지하며, 구현 후 대표 분야의 품질을 다시 평가한다.
