# #388 원격 MCP 연결 준비 실험

2026-11-15. PR #401과 #388~#400의 선행관계를 기준으로 만든 C 독립 준비 작업이다.
Auth0 설정·공개 배포 전에 실제 MCP SDK의 HTTP 전송 경계를 합성 자료로 확인한다.
**#388 완료나 #399 본 구현이 아니다.** 제품 API, 로컬 stdio, 데이터 저장소는 변경하지 않는다.

## 실행

저장소 루트의 별도 Python 3.12 가상환경에서 실행한다.

```powershell
python -m pip install -r mini-projects/soogwon/remote-mcp-spike/requirements.txt
python -m pytest tests/integration/test_remote_mcp_spike.py -q -p no:cacheprovider
```

실험 SDK는 mcp 1.30.0으로 고정한다. 제품 의존성 범위를 변경하지 않는다.
Windows 검증: 14 passed. Starlette/AnyIO 사용 중단 예정 경고 1건.

## 구현과 경계

- `create_probe`는 HTTPS resource/issuer URL을 명시적으로 받는다. 기본 검증기는 모든 토큰을 거부한다.
- 테스트에서만 합성 검증기를 주입한다. 이 검증기를 공개 서버에 사용하면 안 된다.
- 실제 제공자 검증기는 서명·issuer·audience·만료·폐기를 검사해야 한다. 현재 구현에는 Auth0 JWT 검증,
  로그인·등록·refresh endpoint가 없다. 메타데이터의 issuer 표시는 인증 제공자 구현을 의미하지 않는다.
- 추가 경계는 resource 일치, subject 존재, 만료를 검사하고 SDK가 scope를 검사한다.
- 등록 도구는 `whoami`, `probe_card`, `probe_delay`뿐이다. 다른 도구 호출은 거부된다.
- whoami는 인증 성공 여부만 반환한다. 사용자 ID·이메일·토큰을 반환하지 않는다.
- 카드 리소스는 외부 네트워크나 스크립트가 없는 합성 HTML이다. 텍스트 결과도 함께 제공한다.
  리소스 전달 테스트가 실제 Claude의 카드 표시를 증명하지는 않는다.
- 지연은 최대 5초로 제한한다. 300초 호스트/프록시 경계 측정 기능은 아직 아니다.
- 상태 없는 전송만 사용한다. 모든 `Mcp-Session-Id`를 거부하며 서버 세션을 생성하지 않는다.
  따라서 다른 사용자 세션 재사용, 세션 만료·재연결·다중 인스턴스 지원은 **미구현/미검증**이다.
- 합성 인증 실패의 응답·로그에 토큰이나 제공자 오류 본문이 없는지 확인한다. 실제 인증 제공자와
  프록시·운영 서버의 로그 검사까지 완료한 것은 아니다.

공개 실행 명령이나 기본 개발 토큰을 제공하지 않는다. 테스트는 in-process ASGI이며
네트워크 포트를 열거나 PDF·AI·worker를 호출하지 않는다.

## 실제 연결 전에 A와 정할 항목

1. published identity의 Auth0 호환성, 대안 등록 방식, 전용 audience·최소 scope.
2. 승인된 테스트 도메인과 HTTPS 443·프록시·허용 호스트 설정. 실험의 기본 loopback 보호를
   임의로 해제하지 말고 실제 호스트를 명시한다.
3. JWT/토큰 검증 adapter와 사용자 세션 결합 방식, 테스트 계정, 임시 자격 폐기 담당.
4. 긴 합성 요청의 허용 시간·동시성·취소 측정 방법.
