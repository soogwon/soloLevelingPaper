SOLO LEVELING PAPER · 학습 교재

어텐션만으로 번역하기: Transformer 핵심 정리

Attention Is All You Need · Vaswani et al. · arXiv 1706.03762v7 · NIPS 2017

  • 목적: 이해
  • 수준: RNN과 행렬 곱을 아는 학부생
  • 2026-11-16

학습 목표

  • RNN의 순차 계산이 왜 병렬화를 막는지, 트랜스포머가 이를 어떻게 피하는지 설명할 수 있다.
  • 스케일드 닷-프로덕트 어텐션의 계산 순서와 sqrt(d_k)로 나누는 이유를 설명할 수 있다.
  • 멀티헤드 어텐션이 트랜스포머 안에서 쓰이는 세 가지 방식을 구분할 수 있다.
  • 위치 인코딩이 필요한 이유와 논문이 고른 방식을 말할 수 있다.

학습 순서

팀이 검수한 개념 지도의 학습 순서를 묶어 줄였습니다. 아는 개념(RNN, 행렬 곱)은 뺐습니다.

  1. 단어 임베딩→ 인코더-디코더 구조에 필요 (p.5)
  2. 인코더-디코더 구조→ 어텐션 메커니즘에 필요 (p.2–3)
  3. 내적 · 소프트맥스→ 어텐션 점수를 계산하고 가중치로 바꾸는 데 필요 (p.4)
  4. 스케일드 닷-프로덕트 어텐션→ 셀프 어텐션에 필요 (p.4)
  5. 셀프 어텐션 · 멀티헤드 어텐션→ 트랜스포머 인코더에 필요 (p.4–5)
  6. 위치 인코딩→ 순환이 없어 순서 정보를 따로 넣어야 함 (p.6)
  7. 트랜스포머논문의 목표 개념 (p.2–3)

1.왜 RNN을 버렸나

RNN은 순서대로 계산해야 해서 병렬 처리가 막힌다. 트랜스포머는 순환을 빼고 어텐션만 쓴다.

RNN은 t번째 은닉 상태를 t−1번째 은닉 상태로 계산한다. 앞 단어가 끝나야 다음 단어를 계산할 수 있어서, 한 문장 안에서는 병렬로 처리할 수 없다. 문장이 길수록 이 제약이 커진다.

논문 p.2 · 1 Introduction
This inherently sequential nature precludes parallelization within training examples, which becomes critical at longer sequence lengths
순차 계산이라는 성질이 학습 예제 안의 병렬화를 막는다고 지적한다.

트랜스포머는 순환과 합성곱을 모두 빼고, 입력과 출력 사이의 관계를 어텐션만으로 잡는다. 그래서 훨씬 많이 병렬화할 수 있다.

논문 p.2 · 1 Introduction
The Transformer allows for significantly more parallelization and can reach a new state of the art in translation quality after being trained for as little as twelve hours on eight P100 GPUs.

확인 문제

RNN이 긴 문장에서 특히 불리한 이유는 무엇인가요?

순서대로 계산하는 성질 때문에 한 예제 안에서 병렬 처리가 안 되고, 메모리 제약으로 예제끼리 묶는 것도 제한되기 때문이다 (p.2).

2.스케일드 닷-프로덕트 어텐션

쿼리와 키의 내적으로 관련도를 재고, 소프트맥스로 만든 가중치로 값을 섞는다.

어텐션은 쿼리 하나와 키-값 쌍 여러 개를 받아 출력을 만든다. 출력은 값들의 가중합이고, 각 값의 가중치는 쿼리와 해당 키가 얼마나 맞는지로 정한다.

  • 쿼리(query): 지금 찾고 있는 것
  • 키(key): 각 위치가 가진 '찾아질 수 있는 특징'
  • 값(value): 실제로 가져올 정보
\mathrm{Attention}(Q,K,V)=\mathrm{softmax}\left(\frac{QK^{\top}}{\sqrt{d_k}}\right)V
논문 식 (1). 모든 쿼리를 행렬 Q로 묶어 한 번의 행렬 곱으로 계산한다.

왜 sqrt(d_k)로 나눌까? d_k가 크면 내적 값이 커지고, 소프트맥스가 기울기가 거의 0인 구간으로 밀려 학습이 잘 안 된다. 논문은 이를 추정(suspect)으로 설명한다.

논문 p.4 · 3.2.1 Scaled Dot-Product Attention
We suspect that for large values of dk, the dot products grow large in magnitude, pushing the softmax function into regions where it has extremely small gradients
각주 4: q와 k의 성분이 평균 0, 분산 1인 독립 확률변수라면 내적의 분산은 d_k가 된다.
팁

수식이 낯설면 '내적 = 얼마나 비슷한가, 소프트맥스 = 비율로 바꾸기'라고만 기억하고 넘어가도 된다.

확인 문제

덧셈 어텐션(additive attention) 대신 내적 어텐션을 쓰면 실무에서 어떤 이점이 있나요?

이론적 복잡도는 비슷하지만, 최적화된 행렬 곱 코드로 구현할 수 있어 훨씬 빠르고 메모리 효율이 좋다 (p.4).

3.멀티헤드 어텐션과 세 가지 쓰임

어텐션을 8개 헤드로 나눠 병렬로 하고, 트랜스포머 안의 세 곳에서 다르게 쓴다.

헤드 하나로 어텐션을 하면 여러 위치를 평균 내는 과정에서 정보가 뭉개진다. 멀티헤드는 쿼리·키·값을 h번 서로 다르게 투영해 서로 다른 표현 부분 공간을 동시에 보게 한다. 이 논문은 h = 8, 헤드마다 d_k = d_v = 64를 쓰며, 전체 계산 비용은 헤드 하나와 비슷하다.

논문 p.5 · 3.2.2 Multi-Head Attention
Multi-head attention allows the model to jointly attend to information from different representation subspaces at different positions. With a single attention head, averaging inhibits this.

트랜스포머는 멀티헤드 어텐션을 세 가지 방식으로 쓴다 (p.5, 3.2.3).

  • 인코더-디코더 어텐션: 쿼리는 디코더에서, 키·값은 인코더 출력에서 온다. 디코더의 모든 위치가 입력 문장 전체를 본다.
  • 인코더 셀프 어텐션: 쿼리·키·값이 모두 인코더 이전 층에서 온다.
  • 디코더 셀프 어텐션(마스킹): 각 위치는 자기 자신과 그 앞 위치까지만 본다.
논문 p.5 · 3.2.3
We implement this inside of scaled dot-product attention by masking out (setting to −∞) all values in the input of the softmax which correspond to illegal connections.
−∞를 넣으면 소프트맥스 뒤 가중치가 0이 되어, 미래 단어를 볼 수 없다.
예시

"나는 학교에 간다"를 번역하며 세 번째 단어를 만들 때, 디코더는 이미 만든 앞의 두 단어만 볼 수 있다. 아직 만들지 않은 뒤 단어를 보면 시험 중에 정답을 보는 것과 같다.

확인 문제

디코더 셀프 어텐션에서 마스킹을 하는 이유는 무엇인가요?

왼쪽으로 정보가 흐르는 것(미래 위치 참고)을 막아 자기회귀(auto-regressive) 성질을 지키기 위해서다 (p.5).

4.위치 인코딩

순환이 없으니 단어 순서를 알려 줄 정보를 입력에 더한다.

어텐션은 순서를 따지지 않고 모든 위치를 한꺼번에 본다. 그래서 단어 순서 정보를 입력 임베딩에 더해 준다. 위치 인코딩은 임베딩과 같은 차원 d_model이라 그대로 더할 수 있다.

PE_{(pos,2i)}=\sin\left(pos/10000^{2i/d_{model}}\right),\quad PE_{(pos,2i+1)}=\cos\left(pos/10000^{2i/d_{model}}\right)
pos는 위치, i는 차원. 차원마다 주파수가 다른 사인파가 된다.
논문 p.6 · 3.5 Positional Encoding
We chose the sinusoidal version because it may allow the model to extrapolate to sequence lengths longer than the ones encountered during training.
학습형 위치 임베딩도 시험했지만 결과가 거의 같았고(표 3 (E)), 더 긴 문장으로 확장할 가능성 때문에 사인 방식을 골랐다.

확인 문제

학습형 위치 임베딩과 사인·코사인 방식의 성능은 어땠나요?

거의 같은 결과를 냈다. 사인 방식을 고른 것은 학습 때보다 긴 문장으로 확장할 수 있을 것이라는 기대 때문이다 (p.6).

5.전체 구조와 결과

같은 층 6개를 쌓은 인코더·디코더. 번역 품질 최고 기록을 더 적은 비용으로 냈다.

인코더 한 층 = 멀티헤드 셀프 어텐션 → 위치별 피드포워드 네트워크. 각 하위 층을 잔차 연결로 감싸고 층 정규화를 한다. 디코더는 여기에 인코더 출력을 보는 어텐션 층을 하나 더 둔다. 인코더와 디코더 모두 같은 층 N = 6개를 쌓는다 (p.3, 3.1).

\mathrm{LayerNorm}(x+\mathrm{Sublayer}(x))
각 하위 층의 출력. 잔차 연결 뒤 층 정규화.
논문 p.8 · 6.1 Machine Translation
outperforms the best previously reported models (including ensembles) by more than 2.0 BLEU, establishing a new state-of-the-art BLEU score of 28.4
WMT 2014 영어→독일어, Transformer (big). 8개 P100 GPU로 3.5일 학습.
팁

영어→프랑스어 BLEU는 초록·표 2(p.1, p.8)에 41.8, 6.1절 본문(p.8)에 41.0으로 서로 다르게 적혀 있다. 인용할 때는 어느 쪽을 쓰는지 밝혀 두자.

확인 문제

인코더의 각 하위 층 출력은 어떤 식으로 계산되나요?

LayerNorm(x + Sublayer(x)), 즉 잔차 연결 뒤 층 정규화 (p.3).

핵심 정리

  • RNN의 순차 계산을 없애고 어텐션만으로 입력·출력 관계를 잡아 병렬화를 크게 늘렸다 (p.2).
  • 스케일드 닷-프로덕트 어텐션은 내적을 sqrt(d_k)로 나눠 소프트맥스 기울기 소실을 막는다 (p.4).
  • 멀티헤드(h = 8)는 서로 다른 표현 부분 공간을 동시에 보게 하며, 트랜스포머 안의 세 곳에서 쓰인다 (p.5).
  • 순서 정보는 사인·코사인 위치 인코딩을 입력 임베딩에 더해 넣는다 (p.6).
  • 영어→독일어 28.4 BLEU로 앙상블 포함 기존 최고를 2.0 BLEU 넘게 앞섰다 (p.8).
