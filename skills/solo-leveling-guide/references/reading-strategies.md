# 목적별 논문 읽기 전략

어떤 논문에도 쓰는 일반 전략이다. 단계 이름과 목표 문구는 서비스(MCP)의 읽기 가이드와 같다.

## 4단계

| 단계 | 목표 | 읽을 곳 (절 제목·쪽으로 찾기) |
|---|---|---|
| 1. 미리보기 | 논문 전체의 윤곽을 잡는다. 무엇을 풀려는 논문인지 먼저 확인한다. | 제목, 초록(Abstract), 서론(Introduction), 결론(Conclusion). 절 구분이 없으면 앞 2쪽 |
| 2. 구조 파악 | 논문이 어떤 순서로 전개되는지, 어떤 방법을 쓰는지 구조를 파악한다. | 절 제목 전체, 그림·표와 캡션, 방법 절의 첫 문단 |
| 3. 정독 | 본문을 차례대로 꼼꼼히 읽고 방법과 결과를 이해한다. | 초록·참고문헌·감사의 글을 뺀 본문 |
| 4. 복습 | 결과와 한계를 다시 확인하고 이미 아는 개념과 연결해 정리한다. | 실험(Experiments)·결과(Results)·논의(Discussion)·한계(Limitations)·결론 |

## 목적별 덧붙임

| 목적 | 순서 | 단계별 덧붙임 |
|---|---|---|
| 이해 (understand) | 1 → 2 → 3 → 4 전부 | 없음. 각 단계 끝에 이해 확인 질문을 하나씩 던진다. |
| 구현 (implement) | 1 → 2 → 3 → 4, 3단계에 시간을 가장 많이 씀 | 2단계: 구현에 필요한 구성 요소와 입력·출력을 눈여겨본다. 3단계: 수식, 설정값(하이퍼파라미터), 학습 조건을 놓치지 않는다. 마지막에 "구현 체크리스트"(구성 요소 → 입력·출력 모양 → 손실 → 설정값 → 재현에 필요한 데이터)를 만든다. |
| 훑어보기 (skim) | 1 → 2, 필요하면 3의 핵심 절만 | 2단계: 시간이 부족하면 이 단계까지만 읽어도 흐름을 알 수 있다. 3단계: 핵심 절만 읽는다. 결과는 5분 안에 읽을 분량의 요약으로 끝낸다. |

## 아는 개념 반영

- 사용자가 이미 안다고 한 개념은 설명을 짧게 하고 넘어간다. 건너뛴 것은 "아는 것"으로 판정하지 않는다.
- 모른다고 한 개념이나 처음 나온 용어는 키워드 설명에서 먼저 다룬다.
- 수준을 모르면 한 번만 묻는다: "이 분야 논문을 처음 읽나요, 몇 편 읽어 봤나요?"

## 키워드 뽑기

1. 후보: 제목·초록·절 제목·그림 캡션에 나온 전문용어, 본문에서 굵게·기울여 정의된 용어, 약어 정의(예: "Transformer (…)")
2. 5~10개만 고른다. 논문의 핵심 기여에 필요한 용어를 먼저, 일반 배경 용어는 사용자가 모른다고 했을 때만 넣는다.
3. 키워드마다: 한 줄 정의(쉬운 말) → 이 논문에서의 역할 → 처음 나오는 쪽 → 선수 개념(있으면).
4. 개념 지도가 있는 논문이면 지도에 있는 이름과 설명을 우선하고, 지도에 없는 용어만 따로 설명한다.
