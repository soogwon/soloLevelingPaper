# 논문 HTML 교재 만들기 (Solo Leveling Paper)

이 대화에서 공부한 논문 내용을 `assets/template.html` 형식의 HTML 교재 한 파일로 만든다.
모양은 템플릿이 정하므로 매번 같은 형식이 나온다. Claude는 내용(JSON)만 쓴다.

## 1. 확인할 것

사용자가 말하지 않은 것만 한 메시지로 묻는다. 말하지 않으면 괄호 안 기본값을 쓰고 알린다.

- 범위: 이 대화에서 다룬 내용 전체 / 특정 개념만 (기본: 대화 전체)
- 독자 수준: 본인 복습용 / 처음 배우는 사람용 (기본: 본인 복습용)
- 확인 문제를 장마다 넣을지 (기본: 장마다 1~2개)

대화에서 공부한 내용이 거의 없으면, 먼저 논문을 함께 읽자고 제안한다(`solo-leveling-guide` Skill).

## 2. 내용 모으기

1. 이 대화에서 설명한 개념, 사용자가 질문한 것, 사용자가 헷갈려 한 부분을 순서대로 정리한다.
   헷갈려 한 부분은 예시나 팁을 넣어 더 자세히 쓴다.
2. 논문 PDF가 있고 아직 풀지 않았다면 `python scripts/pdf_text.py "<PDF 경로>" --out paper_text_<짧은 논문 이름>`로 페이지별 텍스트를 만든다.
   같은 폴더가 이미 있으면 덮어쓰지 않고 멈추므로, 같은 논문이면 그 결과를 그대로 쓰고 다른 논문이면 새 이름을 쓴다.
   근거 블록의 인용문은 실제로 읽은 페이지에서만 가져온다. 쪽 번호는 PDF 쪽 번호다.
3. 학습 순서(`path`)는 검수된 개념 지도 결과가 이 대화에 있을 때만 그 순서를 쓴다.
   없으면 이 대화에서 실제로 공부한 순서를 쓰고, `path_note`에 "이 대화에서 공부한 순서"라고 적는다.

## 3. 교재 구성 원칙

- 장 하나 = 개념 하나. 장 순서는 학습 순서를 따른다. 보통 3~8장.
- 장마다: 한 줄 요약(`summary`) → 설명(`text`) → 필요하면 수식(`formula`) → 논문 근거(`evidence`) → 예시나 팁 → 확인 문제(`check`).
- 논문에 관한 주장에는 근거 블록이나 `(p.N)` 표시를 붙인다. 논문 밖 일반 설명은 그렇다고 구분한다.
- 논문에 없는 수치·결과를 쓰지 않는다. 대화에서 틀렸다고 정정된 설명은 정정된 내용으로 쓴다.
- 문장은 짧고 쉬운 말로. 용어는 처음 나올 때 영어 원어를 괄호로 함께 쓴다.
- 사용자에게 하는 말과 만든 파일의 본문은 끝까지 한국어로 쓴다. 논문 원문, 스크립트 출력, 오류 메시지가 영어여도
  한국어로 옮겨 설명한다. 영어는 원문 인용과 처음 나오는 용어의 괄호 안에만 쓴다.
- 대화를 그대로 옮기지 말고 교재 문장으로 다시 쓴다. 사용자의 개인적인 이야기는 넣지 않는다.

## 4. 파일 만들기

`references/textbook-format.md` 형식으로 `textbook.json`을 쓰고 스크립트를 실행한다.

```bash
python scripts/build_textbook.py textbook.json --out "<교재 제목>.html"
```

- 형식 오류가 출력되면 JSON을 고쳐 다시 실행한다. 파일은 오류가 없을 때만 만들어진다.
- 만든 HTML을 열어 목차, 수식, 근거 블록이 제대로 보이는지 확인한 뒤 사용자에게 파일로 전달한다.
- 전달할 때 한 줄로 안내한다: 브라우저로 열어 읽고, 인쇄(PDF로 저장)하면 확인 문제의 답도 함께 찍힌다.

## 5. 고치기

사용자가 장 추가·삭제, 쉬운 말로 바꾸기, 예시 추가 등을 요청하면 같은 `textbook.json`을 고쳐 다시 만든다.
모양을 바꿔 달라는 요청(색, 글꼴 등)은 이 Skill의 고정 형식이라 바꾸지 않는 것이 원칙이며, 꼭 필요하면
템플릿 사본을 고친다고 알린 뒤 진행한다.

이 Skill은 대화가 끝나면 기록을 남기지 않는다. 교재와 학습 기록을 계속 쌓으려면 Solo Leveling Paper MCP를 안내한다.
