# #215 PDF 업로드·열람 검증

기준: 2026-11-14, main `fce94f4`. 이 문서는 티켓 종료나 운영 검증 완료를 의미하지 않는다.

## 현재 구현

- `interfaces/http/file_routes.py`: 별도 동의가 있는 기기의 업로드 준비·완료 확인, 웹 세션의 열람 URL 발급, 기기의 URL 없는 상태 조회.
- `interfaces/http/file_uploads.py`: 소유자·원문 버전 확인, 저장 한도 예약, 완료 기록 재사용, 파일 상태 관리.
- `interfaces/http/object_storage.py`: 파일 크기·형식·SHA-256 확인, 확정 객체 복사, 임시 다운로드 URL.
- `application/server_sync/pdf_upload.py`와 MCP 업로드 카드: 기록 동기화와 구분된 PDF 전송 동의 및 재시도·중복 업로드 안내.

파일당 50 MiB, 사용자당 기본 1 GiB이다. 임시 객체의 1일 수명주기와 확정 객체 보존은
[스테이징 운영 문서](../setup/render-staging.md)의 설정 절차를 따른다. 코드에 규칙이 적혀 있다는
사실만으로 실제 버킷에 적용됐다고 판단하지 않는다. 운영 백업·사용자 삭제 정책은 미확정이며
삭제 후속은 #368과 연결된다.

## 자동 검증

```powershell
python -m pytest tests/unit/test_http_file_uploads.py tests/unit/test_pdf_server_upload.py tests/unit/mcp/test_pdf_upload_tools.py -q
```

기존 테스트는 준비·검증 실패·완료 재시도·소유권 조회·S3 호출·MCP 응답을 확인한다.
Windows에서 위 3개 테스트 파일은 74개 통과했다. Starlette의 AnyIO 별칭 사용 중단 예정 경고 1개가 있었다.
이번 추가 테스트는 FastAPI TestClient로 실제 HTTP 라우팅, 인증 의존성, 입력/응답 모델을 통과한다.
미인증 401, 기기/웹 권한 분리 403, 정상 응답 직렬화, 상태 조회의 URL 미노출,
미업로드·진행 중·실패 상태의 열람 URL 미발급, 조회 응답의 no-store를 확인한다.

인증 제공자·저장소·객체 서비스는 대역이다. 이 테스트는 실제 PostgreSQL 소유권 격리,
실제 S3/R2 다운로드, 다른 PC의 로그인, Claude Desktop 카드 표시를 증명하지 않는다.

## 종료 전 실제 환경 검증

1. 공개 테스트 PDF와 별도 테스트 계정을 사용한다. 배포 커밋·OS·호스트 버전과 결과를 기록한다.
2. PC A에서 기록만 동기화하고 웹에서 PDF 미업로드 상태를 확인한다. 메모·학습 기록은 조회 가능해야 한다.
3. PDF 전송에 별도 동의한다. 준비 중에는 URL이 없고, 서버 검증 완료 후에만 ready가 되는지 확인한다.
4. PC B에서 같은 계정으로 로그인해 PDF를 연다. 원본 SHA-256·파일명·크기를 비교한다.
5. 만료된 URL 대신 새 접근 주소를 요청해 열람한다. URL이나 인증 토큰 자체를 검증 기록에 게시하지 않는다.
6. 다른 계정에서 같은 논문·버전 및 업로드 ID로 접근하면 404이며 URL이 발급되지 않는지 확인한다.
7. 다른 PDF 버전을 등록해도 기존 버전의 PDF·메모·인용 연결이 유지되는지 확인한다.
8. 업로드 실패·중단 후에도 기록 저장/조회가 가능하고, 완료 재시도·중복 업로드가 새 버전을 만들지 않는지 확인한다.
9. 임시 객체 하나의 수명주기 삭제와 확정 객체 보존을 실제 버킷에서 확인한다. 예약 만료 표시만으로 객체 삭제를 판정하지 않는다.

위 실제 검증과 운영 정책 결정이 남아 있으므로 #215는 열린 상태로 유지한다.
