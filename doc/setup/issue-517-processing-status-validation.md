# #517 C 처리 작업 조회 연결

## 구현 범위

기준 main: `bf80f2bac1514a513feed07001c1a5c9dfc93891`.
웹 `/uploads`에 기존 처리 작업 조회 버튼을 연결한다.
`GET /v1/remote-uploads/intents/{intent_id}/processing`만 사용하며
처리 접수 POST, PDF 전송, AI 호출을 이 버튼에서 실행하지 않는다.
등록 준비를 저장해 현재 화면이 알고 있는 업로드 의도의 작업을 조회한다.
새로고침 이후 의도 복구와 기존 작업 목록은 이번 구현에 포함하지 않는다.

## 표시 계약

- `queued`: 대기, `running`: 처리 중, `succeeded`: 서버 작업 성공 보고.
- `failed`·`cancelled`: 실패·취소를 표시하며 자동 재접수하지 않는다.
- 현재 응답에는 게시 revision·검색 가능 여부가 없으므로 성공만으로 학습 준비 완료를 단정하지 않는다.
- B의 내부 결과 `prepared`·`translation_incomplete`와 알 수 없는 상태는 공개 완료 상태로 매핑하지 않는다.
- paper/version과 기존 job ID 불일치는 표시하지 않는다. 오류 뒤에도 동일 작업 ID 제약을 유지한다.
- 404는 미접수로 단정하지 않고 없거나 접근 불가로 표시한다. 503·통신 오류 뒤 같은 의도로 재조회할 수 있다.
- 오류 원문·추가 응답 필드는 표시하지 않는다. 새로운 파일 선택·취소·로그아웃·인증 만료·화면 이동 뒤 늦은 응답을 버린다.

## 검증

macOS, Node 22.14.0:

```sh
cd web
node --test tests/*.test.mjs
```

웹 전체 **110 passed, 0 failed, 0 skipped**. 공개 상태 5종, 내부 상태 거부,
출처/작업 ID 불일치와 비문자열 ID 거부, 오류 후 복구, 이전 파일의 늦은 실패, 중복 클릭, 파일 변경/취소와 세션 종료 뒤 늦은 응답,
제품 화면 이벤트 및 API GET 경로를 검증했다. `git diff --check` 통과.
테스트는 합성 응답·fetch 대역·DOM 대역이다. 실제 브라우저 배포본, R2, PostgreSQL worker,
Claude Desktop 또는 유료 API 검증 결과가 아니다.

## A·B 연결 후 남은 범위

- A: 공개 진행 단계·안전한 실패 코드·재시도 가능 여부와 게시/검색 가능 상태 계약.
  실패/취소 후 같은 업로드 의도의 작업 ID 유지 여부, 재접수의 새 키 허용 조건도 확정이 필요하다.
  현재 C는 조회 중 job ID 변경을 거부하며 POST를 호출하지 않는다.
- A: 큐·R2·원장·저장·게시 연결과 실제 인증 사용자 격리, lease·동의 철회 경합 검증.
- B: 내부 prepared와 공개 작업/게시 완료의 경계를 유지하고 단계별 안전한 결과 계약 제공.
  translation_incomplete의 공개 실패/부분 성공 매핑, usage unknown과 provider 실패의 구분,
  동의/예산 오류에서 사용자에게 허용할 후속 행동을 A의 영속 상태와 함께 합의해야 한다.
- C: 확정 계약에 맞춘 상세 안내, 명시적 처리 접수, 기존 의도/작업 복구 및 실제 배포본 종단 검증.
- 동의 철회·예산 부족·사용량 확인 중을 현재 API로 구별할 수 없어 실패 사유를 추정하지 않는다.

이 변경만으로 #517을 종료하지 않는다.
