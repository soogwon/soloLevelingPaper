# #99 진단 로그 보관 정책과 미리보기

작성일: 2026-10-28. 상태: 보관 정책 제안 및 삭제 없는 1단계 구현.
관련 티켓: [#99](https://github.com/soogwon/soloLevelingPaper/issues/99).

## 현재 가능한 작업

```powershell
python -m solo_leveling.interfaces.cli.log_inventory --log-dir ./runtime/diagnostics
```

별도 CLI에서만 실행하며 MCP 서버의 stdout에는 연결하지 않는다.
로그 본문을 열지 않고 이름·크기·수정 시각으로 목록을 만든다. 디렉터리도 생성하지 않는다.
인식하는 이름은 현재 실행기가 생성하는 `mcp-시간-UUID.log`, `worker-UUID.log`,
`worker-stack-UUID.log`, `import-stack-요청ID-spanID.log` 형식으로 제한한다.
하위 폴더, 다른 이름, 링크·Windows 재분석 지점·하드 링크는 제외한다.
DB·PDF·벡터 저장소를 탐색하거나 수정하지 않는다.

기본 검토 기준은 30일·100 MiB·100개이며 옵션으로 변경할 수 있다.
이는 미리보기용 제안값으로, 자동 삭제나 운영 보관 기간 합의를 뜻하지 않는다.
수정 시각이 30일 이상 지난 파일은 `age_review`, 크기·개수 한도 초과는
`bytes_exceeded`와 `count_exceeded`로 표시한다. 총량은 인식한 일반 파일만 집계한다.
종료 코드는 정상 목록 0, 일부 파일 검사 실패 1, 경로·설정 오류 2이다.
오류에는 원본 예외나 절대 경로를 넣지 않는다.

## 결과의 한계

- 기존 MCP/worker 로그는 안전·원본 모드가 같은 이름을 사용한다. 본문을 읽어 추측하지 않고 `kind: unknown`으로 표시한다.
- 스택 로그만 `raw_stack`으로 분류한다. 기본 안전 로그와 상세 안전 로그도 현재 이름으로 구별되지 않는다.
- 오래됐다는 사실은 사용 종료를 뜻하지 않는다. 모든 파일의 `activity`는 `unknown`이며 삭제 허가 목록이 아니다.
- 조회 중 파일 변경·삭제·잠금이 생길 수 있다. 메타데이터 조회 실패는 집계하고 계속하며, 잠금 없는 조회 성공도 비활성 증거가 아니다.
- 경로 검사 직후 교체 경쟁까지 원자적으로 막는 구현은 아니다. 본문 읽기·삭제가 없으며, 이 결과를 나중에 그대로 삭제 입력으로 사용해서는 안 된다.
- 정렬된 목록은 현재 시점의 관찰 결과이지 실행 중 파일을 포함한 원자적 스냅샷이 아니다.

## 다음 단계의 정책 제안

| 종류 | 제안 보관 기간 | 비고 |
|---|---|---|
| 기본 안전 로그 | 30일 | 허용 코드만 기록하는 현재 필터 유지 |
| 상세 안전 로그 | 7일 | 기본 안전 로그와 생성 시점에 구분 필요 |
| 명시적으로 수집한 원본·스택 로그 | 1일 | 민감정보 가능성, 별도 명시적 정리 선택 필요 |
| 종류 미확인 기존 로그 | 자동 정리 제외 | 사용자 확인 없이 안전 로그로 간주하지 않음 |

위 표는 B·C 협의안이다. 1단계 CLI는 종류별 기간을 적용하지 않고 공통 검토 기간만 적용한다.
전체 100 MiB·100개 상한도 검토 기준이며 현재 기록량을 제한하지 않는다.

## 남은 구현과 담당 경계

1. B·C가 종류별 기간·용량·파일 수·설정 위치와 적용 시점을 확정한다.
2. 생성 시 종류와 활성 상태를 신뢰할 수 있게 구분한다. PID만으로 종료 여부를 단정하지 않고 재시작·동시 프로세스를 고려한다.
3. A의 임베딩 worker 로그 생성 방식을 바꿔야 하면 먼저 협의한다. 이번 단계는 해당 파일을 수정하지 않는다.
4. 네이티브 stderr는 파일 설명자에 직접 쓰므로 Python 로거 교체만으로 순환되지 않는다. 원본 로그의 순환 방식은 별도로 설계한다.
5. 명시적 정리 기능은 실행 시 대상·경로·활성 상태를 재검증하고 잠긴 파일은 건너뛴다. 로그 디렉터리 밖 접근과 링크 교체도 방어한다.
6. 크기 순환·보관 만료·동시 실행·Windows 잠금·재시작 및 로깅 실패 시 MCP 통신 유지 테스트를 추가한다.

자동 삭제·파일 순환·용량 강제 제한은 아직 구현되지 않았다. 이 단계만으로 #99를 종료하지 않는다.
