# 메모 생성 요청 중복 방지 — #371

상위 작업은 #214이며 이 변경만으로 상위 티켓을 종료하지 않는다.

## 요청과 응답

`create_annotation.request.request_key`는 선택 문자열이다. 새 생성 의도마다 UUID 등
영문·숫자·밑줄·하이픈으로 된 1~128자 키를 발급하고, 응답을 잃었을 때는 **같은 키와
같은 입력**으로 재전송한다. 키가 없는 기존 호출은 매번 새 메모를 생성한다.
이 호환성 때문에 MCP의 `idempotentHint`는 계속 `false`이다.

- 같은 키·같은 입력: 동일 annotation_id의 **현재 상태**를 반환하고 `reused=true`로 표시한다.
- 같은 키·다른 입력: `CONFLICT: REQUEST_KEY_CONFLICT`. 기존 기록을 바꾸지 않는다.
- 이전 기록이 삭제됨: `NOT_FOUND: ANNOTATION_DELETED`. 재생성하지 않는다.
- 잘못된 위치·인용문·맥락 또는 트랜잭션 실패: 키도 저장하지 않는다. 수정 후 같은 키로 재시도할 수 있다.
- 새 저장·수정·삭제의 `reused`는 `false`이다. 새 생성은 revision=1이다.

입력 일치는 종류, 본문, 학습 단계, 구간 목록 전체로 판단한다. 공백·유니코드와 구간 순서를
변경하지 않는다. 생략된 선택 값과 명시적인 기본값은 같은 것으로 처리한다.
재전송은 생성 시 본문으로 이후 수정을 덮지 않으며, 저장 후 원문이 변경돼도 기존 메모를 반환한다.
현재 원문 위치의 유효성은 기존 `get_annotation` 계약으로 확인한다.

## 저장 범위와 보존

`annotation_create_requests`의 기본 키는 `(context_id, request_key)`이다.
현재 로컬 기록은 계정별 DB가 아니므로 범위는 **로컬 DB + 학습 맥락**이며 서버 로그인 계정으로
나누지 않는다. 별도 DB 간 중복 또는 서로 다른 키를 사용한 요청의 중복은 방지하지 않는다.

요청 이력에는 입력 SHA-256, 메모 ID, 생성 시각만 추가하며 본문·인용문 스냅샷은 중복 저장하지 않는다.
메모·구간·요청 이력을 하나의 `BEGIN IMMEDIATE` 트랜잭션으로 기록하므로 동시 재시도에서도
하나만 생성된다. 이력은 자동 만료하지 않고 맥락 삭제 때 제거한다. 메모 삭제만으로는 이력을
지우지 않아 삭제 후 늦게 도착한 재전송을 차단한다. 기존 DB에는 테이블만 추가하며 기존 메모에
요청 키를 추정해서 붙이지 않는다. 서버 동기화 payload에는 이 로컬 요청 이력을 포함하지 않는다.

## 상세 카드

카드는 클릭 시 입력 해시와 임의 요청 키를 호스트의 `localStorage`에 보관한 뒤 호출한다.
본문·인용문 자체는 카드 저장소에 넣지 않는다. 응답 유실 시 키를 유지하며, 상세 카드 재조회 또는
재시작 후 동일 입력을 다시 저장하면 같은 키를 사용한다. 백그라운드 자동 재전송은 하지 않는다.
정상 응답 확인 후 키를 제거하므로 이후의 명시적인 새 저장은 새 요청이다.
사용자는 응답 유실 후 메모 내용을 동일하게 다시 입력해야 하며 초안 복원 기능은 아니다.

호스트가 저장소 또는 Web Crypto를 제공하지 않거나 저장에 실패하면 **전송하지 않고** 채팅에서
요청 키를 지정하도록 안내한다. 호스트가 저장소를 초기화하거나 다른 저장소를 사용하는 클라이언트로
이동하면 키 복원은 보장되지 않으므로 목록을 확인한다. 실제 Claude Desktop의 저장소 유지 여부는
별도 수동 확인 대상이다. 자동 검증은 재생성된 카드에 같은 저장소를 제공해 재시작을 재현한다.

## 검증 범위

- 실제 SQLite 동시 생성·재시작·키 충돌·삭제 뒤 재전송·잘못된 참조 수정·트랜잭션 롤백.
- 기존 DB 업그레이드·맥락별 키 분리·기존 키 없는 호출 호환.
- MCP 메모리 전송을 통한 재시작과 고정 오류 코드·민감 본문 비노출.
- 카드 응답 유실·키 재사용·중복 목록 방지·저장소 차단 시 무전송.
- 기존 메모 CRUD·페이지 조회·원문 위치·HTTP 조회·서버 동기화 회귀.
