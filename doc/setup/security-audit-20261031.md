# #64 후속 보안 현황 조사

기준: 2026-10-31, main `4531cf4`. 실제 API·모델 다운로드·사용자 DB를 사용하지 않는다.
기존 구현과 누락 범위를 조사한 뒤 입력 오류 경계를 보완했다. 전체 보안 보증은 아니다.

## 기존 구현 확인

- 기존 #64 브랜치의 안전 로그·보안 검증 변경은 main에 포함돼 있다.
- `external-data-transfer.md`에 번역·답변·보완·의미 검증·요약의 전송 내용을 설명한다.
  등록 시 누적 전송이 논문 전체에 이를 수 있고, LOCAL_ONLY가 호스트 통신·모델 다운로드까지
  차단하지 않는다는 제한도 있다. 설치 문서와 MCP 실행 문서에서 안내로 연결한다.
- 번역·생성·의미 검증 어댑터에 허용/로컬 전용 설정 검사가 있고, 요청은 store=False와
  리다이렉트 비허용을 사용한다. 제공자 측 보관이나 호스트 통신 정책의 실측은 아니다.
- LocalPdfStore는 상대 경로·루트 포함·PDF 확장자·크기를 확인한다. 경로 검사 후 교체와
  하드 링크 원본 위치는 기존 위협 모델에서 보류된 제한이며 해결됐다고 판단하지 않는다.
- 기본 진단 실행기의 부모 필터와 자식 원본 비수집이 구현돼 있다. 직접 MCP 실행의 부모
  stderr에는 같은 필터가 없으며, 원본 수집은 opt-in이다. 보관·삭제는 #99 범위다.

## 확인된 보완 후보

### 1. 도구 함수 진입 전 입력 오류의 입력값 재노출

실제 FastMCP create_server에 대역 서비스와 합성 입력을 연결하고 call_tool을 호출했다.
ask_paper의 question에 문자열 대신 합성 표식을 담은 객체를 넣으면 ToolError 문자열에
그 표식이 포함됐다. answer 서비스는 호출되지 않았다. 외부 API·DB 호출은 없었다.

이는 서버 내부 서비스의 고정 오류 변환보다 앞선 검증 경로다. 추가로 SDK 메모리 전송의
ClientSession으로 initialize 후 tools/call을 보내, CallToolResult 오류 콘텐츠에 합성
입력값이 포함되는 것을 수정 전 재현했다. Desktop 저장 로그나 stdio 실측은 아니다.

보완: SafeInputServer에서 SDK 입력 모델과 JSON 문자열 전처리를 재사용하여 입력을 먼저
검증하고, 고정 INVALID_ARGUMENT 오류로 반환한다. 원래 예외를 연결하거나 기록하지 않는다.
미등록 도구 이름은 SDK 경고 로그보다 앞선 요청 처리 경계에서 차단한다.
공개 스키마·기본값·정상 반환 모델은 유지한다. 허용되던 최상위 추가 필드 정책도 바꾸지 않는다.
잘못된 타입·필수 필드 누락·중첩 금지 필드·미등록 이름·다음 정상 호출과 JSON 문자열 배열
호환성을 테스트한다. SDK 내부 도구 메타데이터와 요청 핸들러를 사용하므로 SDK 갱신 시
이 프로토콜 테스트를 실행해야 한다. JSON-RPC 자체가 손상된 메시지의 오류는 이번 범위 밖이다.
#127 병합 시 ReflectionInputServer의 별도 스키마 제한은 보존하면서 이 공통 보호를
상속하도록 통합해야 한다. 해당 PR의 파일을 이 브랜치에 미리 가져오지는 않았다.

### 2. 출력 검증 오류의 데이터 재노출과 보완

합성 list_paper_jobs 서비스가 jobs 또는 next_cursor에 잘못된 타입을 반환하면 SDK의
출력 모델 검증 오류가 해당 값을 포함하는 것을 MCP 세션으로 재현했다.
입력 검증 후 SDK에서 발생한 출력 모델 검증 오류를 본문 없는
`INTERNAL_ERROR: 요청을 처리하지 못했습니다.`로 변환한다.
하위 계층의 출력 JSON 스키마 검사도 같은 스키마로 먼저 검증해 안전하게 변환한다.
입력 오류의 INVALID_ARGUMENT와 기존 서비스 오류 코드는 그대로 유지한다.
출력 오류 뒤 같은 세션의 정상 호출, 오류 응답과 캡처 로그의 본문 비노출을 검증한다.
추가 검토에서 잘못된 UTF-8 바이트의 JSON 직렬화 오류가 출력 모델 검사 전에 발생하는
것을 확인했다. SDK가 감싼 PydanticSerializationError도 같은 고정 INTERNAL_ERROR로
변환한다. 합성 바이트 응답의 비노출과 같은 세션의 후속 정상 호출을 회귀 테스트로 확인했다.

### 3. 도구 사용 시점의 외부 전송 안내

문서 고지는 있지만 main의 add_paper 도구 설명은 로컬 복사·등록만 설명하며,
HOST_INSTRUCTIONS에도 외부 전송 안내가 없다. 문서만 읽지 않는 사용자를 위한 보완 후보다.

다음 최소 보완: 등록 시 원문 청크 번역, 질문 시 질문·근거 전송과 추가 호출 가능성을
도구 설명/호스트 지침에 간결하게 연결한다. 설정 허용을 매 호출의 사용자 동의 증명으로
표현하거나 LOCAL_ONLY를 완전한 네트워크 차단으로 안내하지 않는다.

### 실제 stdio 호출 확인

- 로컬 DB를 읽기 전용으로 복사하고 별도 데이터 루트에서 수정 코드의 서버를 실행했다.
- initialize·도구 목록 조회 후 작업 1건 조회 → 잘못된 입력 → 미등록 도구 → 작업 재조회를
  실행했다. 두 오류는 고정 INVALID_ARGUMENT였고 앞뒤 정상 조회는 모두 성공했다.
- 별도 대역 서비스 서버에 잘못된 UTF-8 출력을 주입했다. 실제 stdio 응답은 고정
  INTERNAL_ERROR였고 같은 세션의 다음 정상 호출도 성공했다.
- 오류 응답과 확인한 로그에 합성 표식이 없었다. Desktop 화면 테스트는 아니다.
- 원본 DB·Desktop 설정은 변경하지 않았고 외부 API 호출도 하지 않았다.
