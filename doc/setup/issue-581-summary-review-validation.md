# #581 요약 준비·목적별 동의·접수 검증

요약 검토 테이블은 질문과 분리한다. 같은 요청 키와 입력은 같은 검토를
반환하며 만료 시각을 연장하지 않는다. 다른 범위·판본·설정은 충돌로 거부한다.
준비 시 고정 범위의 서버 원문을 저장하지만 외부 전송이나 예산 예약은 없다.

- A: owner/context 연결, 검토 만료, 정책 변경 차단, 두 목적 동의 후 원자 접수,
  동시 제출 1건, 삭제 시 context 종속 행 제거를 제공한다.
- B: 준비된 입력의 해시·서버 설정을 접수 시 다시 대조한다. 고지에는 범위,
  모델과 입력/출력/호출 상한을 포함하며 요약 원문 전문은 응답하지 않는다.
- C: 웹 세션 전용 조회·동의·철회·접수 라우트를 추가했다. 모델이 보낸
  `confirmed` 필드는 동의로 인정하지 않는다. 실제 UI와 MCP 등록은 후속이다.

철회한 검토는 다시 grant해도 동의를 부활시키지 않는다. 재동의·재생성에는
새 요청 키가 필요하다. 접수 후 같은 키 제출은 기존 실행을 조회할 뿐이다.

격리 PostgreSQL과 웹 대역, migration·제한 계정·백업/복구 회귀 41개 통과.
Ruff와 diff 검사 통과. 외부 API 호출·staging 변경은 없다.

## 남은 범위

운영 앱은 서비스를 기본 조립하지 않으므로 라우트는 비활성(503)이다.
준비 URL은 후속 웹 화면의 계약이며 현재 공개된 작동 화면이 아니다.
MCP 도구·웹 화면·전용 역할·환경 설정·실제 Desktop/다기기·유료 생성 검증이
남아 있다. migration 0053과 실제 권한·배포는 별도 승인 후 적용한다.
