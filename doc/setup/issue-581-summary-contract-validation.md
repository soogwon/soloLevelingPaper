# #581 원격 요청형 요약 계약 검증

## 이번 범위

요약 준비·실행·저장 연결에서 공유할 입력·동의·결과 계약을 추가한다.
이 변경만으로 제품 도구가 활성화되거나 유료 생성이 실행되지 않는다.

- A: owner/context 및 고정 publication·parse·translation·embedding 판본을 입력 해시에 포함한다. 요약 저장과 AI 전송을 각각 `summary_storage`, `summary_ai`로 구분하고 질문·번역·메모 동의를 거부한다.
- B: 범위의 전체 청크 수와 입력 수가 다르면 거부한다. 선두 일부만으로 논문 전체 요약이라고 표시하지 않는다. 각 결과 항목은 입력의 근거 ID를 인용해야 하며 하나라도 잘못되면 결과 전체를 거부한다. 이는 구조 검증이며 의미 검증 통과로 표시하지 않는다.
- C: 준비 안내에는 판본·범위·제공자·모델·별도 동의 필요 여부와 자동 생성 비활성 상태를 제공한다. 원문은 안내나 객체 repr에 포함하지 않는다.

## 자동 검증

`PYTHONPATH=src python -m pytest tests/unit/summary/test_remote_contract.py -q`

51개 통과: 재시작 직렬화, 판본·본문·모델·프롬프트 변경 해시, 범위 누락,
잘못된 JSON, 타인·다른 맥락·철회·만료·다른 목적 동의, 잘못된 근거,
결과의 방어적 복사와 구조 검증 표시. Ruff 통과.

추가로 `PostgresSummaryPreparation`은 인증 owner의 고정 context에서 전체 또는 섹션
청크를 읽는다. 1,000개 초과는 앞부분만 전달하지 않고 거부한다. 요약 전용 근거 ID는
context·publication·번역 판본·청크에 고정된다. 기존 답변 근거 ID로 위장하지 않는다.

로컬 PostgreSQL 통합 테스트 7개도 통과했다. 재게시·재시작 후 입력 해시 보존,
타인·삭제·미존재 차단, 섹션 전체 조회, 원문 유지 상태의 번역문 오표시 방지,
실행·동의 행을 생성하지 않는 것을 확인했다. 단위 포함 총 58개이다.

실제 API 호출·staging 변경·PDF 전송은 0회이다.

## 후속 연결

이 계약 자체는 인증이나 예산 승인을 증명하지 않는다. 다음 연결 전에는
클라이언트의 binding/source/청크 수를 신뢰하지 않고 인증된 owner로 DB에서
조회해야 한다. 준비 시에는 실행을 시작하지 않는다.

1. 준비한 입력의 요청 키·동의·결과 저장. 새 요약 근거 ID의 전용 재조회 연결.
2. 같은 키 동시 접수의 단일 실행, 철회·삭제·lease·예산 검사와 결과 원자 저장.
3. 전송 모델·호출 수·토큰/비용 상한을 동의 화면에 구체적으로 표시하고 서버 정책과 결합.
4. MCP·웹 준비/동의/접수/취소/복구 및 기존 저장 요약 표시.
5. 실패·불충분 결과가 기존 요약을 덮어쓰지 않는 DB 검증, 두 계정 격리.
6. 별도 승인 후 실제 환경 및 Claude Desktop 검증.

현재 준비 안내는 호출 수나 금액을 확정하지 않으므로 그 안내만으로
동의를 접수하거나 실행할 수 없다. DB 권한·배포·유료 호출은 별도 승인 대상이다.
