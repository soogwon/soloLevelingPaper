# #393 제품 웹 보관·AI 동의 연결

기준 main `90da7b9` (#512 동의 계약 포함), 2026-11-16.

## 연결 범위

- `#/uploads`의 파일 정보 전송 확인, PDF 보관 동의, OpenAI 전송 동의를 구분한다.
- 업로드 의도를 생성한 뒤 사용자가 동의 안내·상태 조회를 누르면 서버 고지와 두 동의를 읽는다.
- 승인마다 해당 고지 확인란을 다시 선택한다. 서버 고지 내용은 textContent로 표시한다.
- GET `.../intents/{id}/consents`, POST `.../consents/{purpose}`, POST `.../consents/{purpose}/revoke`만 추가한다.
- 승인은 현재 표시된 `notice_version`과 목적별 Idempotency-Key, 철회는 조회한 `expected_revision`을 사용한다.
- AI 동의는 서버 의도 상태가 verified인 경우만 가능하다. current는 중복 승인하지 않고 stale/revoked는 명시 재승인을 허용한다.
- 승인 응답 유실은 같은 키를 유지한다. 조회로 상태를 확인할 수 있고, 철회 유실·revision 충돌은 먼저 재조회한다.
- 고지 변경/409는 고지와 확인을 초기화하고 재조회를 요구한다. 선택·계정·화면 세대가 바뀌면 늦은 응답을 무시한다.
- 파일 선택 취소는 동의 철회가 아니며 동의 철회도 파일 삭제가 아니다. 이미 전송된 작업의 취소로 안내하지 않는다.

PDF prepare/PUT/complete와 처리 접수는 연결하지 않았다. 보관·AI 동의가 모두 있어도 PDF 업로드 버튼은 비활성화이고 provider 호출은 없다.

## 실제 macOS Chrome + 로컬 HTTP 대역

1. `python3 web/tests/upload-consent-server.py` 실행 후 `http://127.0.0.1:8794/#/uploads`를 연다.
2. 합성 PDF를 선택하고 파일 정보 확인 → 등록 준비 저장을 누른다.
3. 동의 안내 조회: 별도 고지 표시, 보관 확인란만 활성화, AI 확인란 비활성화를 확인한다.
4. 보관 확인 → 저장: 보관만 동의됨, AI는 동의 기록 없음이어야 한다.
5. 기존 요청 상태 확인을 누른다. **대역은 실제 업로드 없이 verified를 반환한다.** 다시 동의 조회 후 AI만 확인·저장한다.
6. 보관만 철회해도 AI는 동의됨으로 남는지, AI도 별도로 철회한 뒤 조회하면 두 상태가 철회됨인지 확인한다.
7. `curl -s http://127.0.0.1:8794/__report`로 메타데이터 생성 1건·별도 목적 승인 2건·철회 2건과 본문을 확인한다. 서버를 Ctrl+C로 종료한다.

위 순서로 합성 `c375-fresh-workflow.pdf`(1,808 bytes)를 사용해 모두 확인했다. 승인 키는 목적별로 달랐으며 두 승인 모두 표시된 `synthetic-v1`, 두 철회 모두 revision 1을 보냈다. prepare/complete/processing이나 PDF 바이트 전송 요청은 없었다. 대역의 메타데이터·동의는 프로세스 메모리에만 있으며 서버는 종료했다.

이 서버는 localhost 단일 합성 계정 UI 검증용이다. 실제 인증·원장·멱등 동시성·고지 정책을 대체하지 않는다. 공개 포트나 실제 자료로 사용하지 않는다. 고지 충돌·유실·늦은 응답 사례는 자동 대역 회귀 결과이며 이번 브라우저에서 오류를 주입한 것은 아니다.

- R2/두 계정/다른 브라우저·플랫폼, 실제 동의 철회와 provider 전송 경합 검증
