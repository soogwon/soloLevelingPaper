# #595 웹 처리 작업 상태 연결 검증

웹 논문 상세의 학습 상태와 처리 작업 상태를 분리한다. 선택 판본의 작업 목록은
`GET /v1/papers/{paper_id}/processing-jobs?version_id=...`로 조회하며,
원격 MCP와 같은 상태 투영을 사용한다. UUID 커서 순서는 시간순을 의미하지 않는다.

## 구현 및 권한

- 기존 원격 제품 조회 기능이 활성화된 경우만 웹 조회 경로를 등록한다.
- 기존 MCP 조회 전용 DB 풀을 사용한다. 웹 세션의 owner·논문·원문 판본으로 제한한다.
- 다른 계정·없는 판본·삭제된 논문은 404, 조회 장애는 503으로 처리한다.
- 상태·revision·안전한 오류 코드만 표시하고 lease·요청 키·자격은 반환하지 않는다.
- 웹에는 취소/실행/재시도 버튼을 추가하지 않는다. 새로고침은 GET 조회만 한다.
- 더 보기에서 중복 작업을 합치고, 로그아웃·세션 만료·페이지 이동 뒤 늦은 응답을 버린다.
- DB migration·추가 권한·worker 변경은 없다. 기존 조회 역할의 테이블 SELECT를 사용한다.

## 로컬 검증

- PostgreSQL: 계정·판본·삭제 격리, 페이지 조회, 취소 후 MCP와 같은 cancelled/revision 2,
  조회 시 실행 횟수 0을 검증한다.
- 웹: 취소·학습 완료 구분, HTML 이스케이프, 더 보기/새로고침, 범위 불일치 응답 차단,
  로그아웃 후 늦은 응답 차단을 검증한다.
- 설정 테스트 대역에 실제 제품 조회 객체와 같은 pool 속성을 반영한다.

## 실제 검증과 남은 범위

2026-11-19, 기존 배포본에서 합성 대기 작업 1건을 Claude 카드로 취소했고,
같은 키 조회와 Desktop 재시작 뒤 cancelled/revision 2 복구를 확인했다.
읽기 전용 DB 검사에서 취소 기록 1건, attempt 0, 기존 완료 작업 보존을 확인했다.

이 PR의 웹 표시 자체는 staging에 아직 배포하지 않았다. 병합 후 별도 배포 승인을 받아
동일 합성 작업의 웹 상태와 MCP 상태를 대조해야 한다. 실제 두 계정 원격 MCP 격리와
실행 중 취소·worker 재시작은 별도 실제 검증 범위다. #595를 자동 종료하지 않는다.
