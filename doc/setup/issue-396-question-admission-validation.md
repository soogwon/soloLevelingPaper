# 질문 접수 동의·예산 예약 검증

- A: 실행 생성과 사용자/서비스 전체 질문 토큰 상한 예약을 같은 transaction에 결합한다. 같은 요청 키는 기존 실행과 예약을 재사용한다. intake 중지나 예산 부족은 실행 생성도 rollback한다.
- B: 물리 전송은 기존 질문 예약에서 할당하며 전체 예산을 이중 예약하지 않는다. 실제 사용량은 기존 원장으로 정산한다. 다른 정책/window로 전송하여 한도를 우회할 수 없다.
- C: 취소 요청·종료·삭제 시 아직 할당하지 않은 예약만 반환한다. reserved/unknown 전송 사용량을 0으로 추정하지 않는다. 응답 유실 뒤 같은 키 조회는 추가 예약을 만들지 않는다.

격리 DB에서 동시 다른 키의 상한 경쟁, 동일 키 단일 예약, 취소 반환, 실제 usage 정산, 불확실성 보존, 잘못된 window 거부를 검증했다. 새 테이블·trigger에 맞춰 복구 객체 목록과 리허설을 갱신했다. 관련 69개 회귀 통과 후 접수 중지 rollback·삭제 반환 사례도 추가 검증한다.

운영 토큰/비용 수치나 대상 사용자를 임의 설정하지 않았다. migration 0040·최소 권한과 운영 설정은 staging 승인 전 미적용이다. 제품 동의 화면·MCP 제출 연결은 다음 단계다. 신규 API 호출이나 실제 데이터 삭제는 없다.
