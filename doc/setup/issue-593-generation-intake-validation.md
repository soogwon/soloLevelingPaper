# #593 퀴즈 생성 접수·예산 예약 검증

## 이번 연결

`PostgresQuizIntake`는 서버가 인증한 사용자와 서버 정책을 받아 생성 요청을 접수한다. 공개 HTTP/MCP 경로나 worker에는 아직 연결하지 않는다. 기존 완료 답변의 인용을 `PostgresQuizPreparation`으로 다시 조회하고 요청 전체 해시를 대조한다. 클라이언트가 바꾼 본문·모델·토큰 상한은 접수하지 않는다.

생성 전용 `remote-quiz-generation-v1` 고지와 입력 해시에 묶인 저장·AI 동의 두 개가 필요하다. 공통 DB 목적 이름은 `storage`·`ai_provider`이며 답안 제출 저장 동의와 구분된다. 이 접수 계층은 동의를 새로 만들지 않는다. 만료 시간이 있는 생성 검토 화면과 그 동의 발급·만료 처리는 후속 작업이다.

migration 0057은 생성 입력을 별도 불변 테이블에 저장한다. 실행·입력·사용자 및 서비스 예산 예약은 한 트랜잭션이다. 같은 키는 같은 실행으로 복원하며 입력·동의 ID·정책 snapshot·예산 창이 달라지면 충돌이다. 동의 철회 후 기존 접수 결과 조회는 허용하고 새 요청은 차단한다. 취소 시 공통 실행 저장소가 미사용 예약을 반환하며, 재조회는 다시 예약하지 않는다.

## 검증 결과

- A: 로컬 PostgreSQL 18개. 같은 키 4개 동시 요청의 실행·예약 1건, 다른 키/다른 맥락의 예산 초과 방지, 계정 격리, 동의 철회, 잘못된 고지/해시, 삭제 논문, 접수 차단, 예산 누락/소진의 전체 롤백, 취소 반환과 재조회, 입력 불변성·실행 삭제 시 종속 입력 삭제.
- B: 저장된 고정 인용·판본을 서버에서 재구성하고 위조 본문/모델을 거부한다. 구조 계약·기존 퀴즈 준비 회귀 포함. 실제 생성이나 정답 품질 평가는 수행하지 않았다.
- C: 같은 키 재시도에서 기존 실행을 복원하는 서버 기반만 검증했다. 공개 도구·생성 동의 화면·Desktop 검증은 아직 연결하지 않았다.
- 퀴즈 접수/저장/준비/도구/웹 계약, 요약 접수/실행, migration 단위 검사 및 로컬 Docker DB 백업·복구를 합쳐 **138 passed**. 백업 검사는 새 테이블/트리거의 스키마 복원을 포함하며 실제 퀴즈 생성 데이터의 운영 복구 실측은 아니다.
- CI의 비슈퍼유저 복구에서 새 테이블·함수 허용 목록 누락을 발견했다. 로컬에서 같은 `restore_table_manifest_mismatch`를 재현한 뒤 검토된 새 객체만 복구 목록에 추가했다. 제한 웹 계정·백업·비슈퍼유저 복구 **7 passed**로 재검증했으며, 알 수 없는 테이블/함수 거부와 실패 롤백도 유지된다.
- Ruff와 `git diff --check` 통과. API 호출·staging 변경 없음.

## 재현

격리 로컬 PostgreSQL DSN을 `SOLO_TEST_POSTGRES_DSN`에 설정한 뒤:

```sh
python -m pytest tests/integration/test_remote_quiz_intake_postgres.py -q
```

DB 테스트는 고유 임시 schema에 migration 전체를 적용하며 종료 시 제거한다. 실제 서비스 DB를 지정하지 않는다. 백업 리허설은 별도 opt-in인 `SOLO_BACKUP_DOCKER_CONTAINER`와 `SOLO_TEST_DOCKER`가 필요하다.

## 남은 범위와 적용 경계

생성 검토의 동의 발급/만료·전용 권한, 생성 worker의 lease/전송/사용량/의미 검증·문항 저장, 생성·제출·복습 카드, 내보내기/삭제와 두 실제 계정·다기기 검증이 남는다. 접수만으로 생성 완료 또는 #593 완료로 판단하지 않는다.

이번 migration은 로컬과 CI에만 적용한다. staging 배포 보류를 유지하며, 다음 실제 배포 전에는 0057을 포함한 미적용 migration·권한·배포 범위를 별도로 승인받아야 한다. 실제 AI 실행은 전송 데이터·모델·횟수·비용 상한을 승인받은 뒤 진행한다.
