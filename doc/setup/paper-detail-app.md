# #62 논문 상세 MCP App — 요약·근거 조회 및 기록 작성

## 구현 범위

메모·하이라이트의 서비스 응답과 상세 카드 동작은
[논문 상세 기록 조회 계약](paper-detail-annotations.md)을 따른다.
아래는 기존 상세 뷰어의 구현·검증 기록이다.

`ask_paper`, `get_evidence`, `get_paper_detail`에 `ui://solo-leveling/paper-detail.html`을 연결한다.
기존 도구의 입출력 JSON·검색/생성/검증·DB 저장은 변경하지 않는다. 저장 요약 조회 도구만 추가한다.

- 답변과 주장별 근거 버튼, 근거 목록을 표시한다.
- 버튼을 누르면 같은 화면의 저장 인용문 패널로 이동한다. 선택한 근거의 원문·번역과 물리 PDF 페이지 번호를 함께 표시한다.
- 논문 버전·파싱·번역 리비전과 근거·청크 ID를 함께 표시한다.
- 번역 누락과 인쇄 페이지 번호 부재를 명시한다.
- 원문·번역·파일명은 textContent로 출력하고 외부 요청·자동 도구 호출을 하지 않는다.
- 오류·취소·새 입력에서는 이전 본문을 제거한다. 호스트 미지원 시 기존 JSON을 사용한다.

저장 요약 상세에서 원문 인용 전체에 메모·하이라이트를 작성한다. 같은 맥락·청크·인용 위치에 저장된 기록을 다시 표시한다. 인용 위치가 중복되거나 저장 길이 제한을 넘으면 작성을 비활성화한다.

## M1 지원 범위

- Claude Desktop 시크릿 대화에서는 상세 카드에 저장 요약과 근거를 표시한다. 요약 항목의 근거 버튼으로 해당 인용문을 선택할 수 있다.
- **일반 대화의 M1 지원 범위는 텍스트 폴백까지다.** 카드가 표시되지 않아도 도구 응답으로 저장 요약, 근거별 원문·번역, PDF 페이지 번호, 근거·청크 ID, 리비전과 검증 수준을 확인할 수 있어야 한다. 일반 대화의 카드 표시 문제는 [#242](https://github.com/soogwon/soloLevelingPaper/issues/242)에서 추적한다.
- 실제 PDF 파일 열기와 좌표 이동은 #232, 키워드·중요 문장은 #229, 섹션 제목·목차는 #230, 상세 카드의 메모·하이라이트는 #231에서 다룬다.

## 자동 테스트

```powershell
cd ui/paper-detail
npm ci --ignore-scripts
npm test
npm run build
cd ../..
python -B -m pytest tests/unit/mcp tests/unit/test_paper_detail.py tests/integration/test_mcp_stdio.py -q
```

HTML은 빌드 산출물이며 직접 수정하지 않는다. 기존 package-data 규칙으로 wheel에 포함된다.
DOM 테스트는 실제 Claude Desktop 표시 검증을 대체하지 않는다.

## Claude Desktop 수동 확인

1. 이 브랜치로 wheel을 빌드해 테스트 환경에 설치하고 MCP를 재시작한다.
2. 기존 답변의 context_id와 evidence_id로 `get_evidence`를 한 번 호출한다. 재등록·번역 불필요.
3. 원문·번역·PDF 페이지·출처 ID가 JSON과 동일한지 확인한다.
4. 두 근거 이상이면 목록 버튼을 눌러 페이지와 인용문이 함께 바뀌는지 확인한다.
5. `ask_paper`의 기존 테스트 응답에서는 주장별 버튼으로 해당 근거에 이동하는지 확인한다.
   실제 ask_paper 호출은 모델 사용·비용을 수반하므로 별도 승인된 테스트에서만 수행한다.
6. 번역 없는 근거, 빈 답변, 조회 오류에서 이전 내용이 정상 결과처럼 남지 않는지 확인한다.

자동 테스트에는 합성 데이터만 사용한다. 이후 수행한 Desktop 수동 확인 범위는 문서 하단에 기록한다.

## 2026-10-28 자동 검증 결과

- UI DOM 테스트 6개 통과, HTML 번들 빌드 성공.
- MCP 단위 테스트 및 실제 stdio 통합: 196개 통과, 2개 건너뜀.
- 제한 환경의 asyncio 로컬 소켓 생성 지연을 확인하여 정상 실행 환경에서 재검증했다.
- 합성 원문·번역만 사용하는 브라우저 미리보기에서 주장 버튼의 6→7페이지 전환을 확인했다.
- 실제 Claude Desktop·실제 모델/API 호출은 하지 않았다.

## 저장 요약 조회 테스트

기존 context_id로 다음 입력을 `get_paper_detail`에 전달한다. 등록·번역·생성 API 호출은 없다.

```json
{"context_id":"기존 context_id","scope":"paper","offset":0,"limit":20}
```

- 저장 요약이 있으면 주장·방법·결과·한계와 근거 버튼을 확인한다. 버튼 선택 시 JSON과 같은 페이지·원문·번역·리비전인지 비교한다.
- 요약이 없으면 `summary=null`과 부재 안내가 정상이다. 테스트를 위해 자동 생성하거나 DB를 수정하지 않는다.
- 섹션별 조회는 반환된 `section_ids` 중 하나를 `scope`로 전달한다. 섹션에 저장 요약이 없을 수 있다.
- `limit=1`로 조회해 `next_offset`이 있으면 같은 context·scope, 반환된 `summary_id`, 해당 offset으로 다음 항목을 조회한다. UI에는 이 인자를 안내하며 자동 호출하지 않는다.
- `structural_only`는 저장 근거 연결 검사다. 요약의 의미 일치를 모델로 검증했다는 뜻이 아니다.

## 2026-10-28 저장 요약 연결 검증 결과

- UI DOM 테스트 8개 통과, HTML 번들 빌드 성공.
- MCP·stdio·상세 조회·요약 회귀 테스트 240개 통과, 2개 건너뜀.
- 합성 DB의 실제 요약·근거를 MCP 응답 모델에 전달하는 추가 테스트 1개 통과.
- 요약 없음, 페이지 분할·요약 교체, 다른 섹션/맥락/리비전, 변조된 인용문을 검사했다.
- 읽기 전후 합성 DB 파일이 동일하고 없는 DB가 생성되지 않음을 확인했다.
- 실제 API 호출·사용자 DB 변경·Desktop 환경 재설치는 하지 않았다.

## Desktop 표시 확인 및 빈 상태 보완

- 사용자 Desktop에서 상세 화면 연결과 저장 요약 부재 안내를 확인했다.
- 요약이 없으면 검증 안내와 빈 근거 항목 제목을 숨기고, 부재 원인을 명시한다.
- UI 테스트 10개 통과. 합성 요약의 근거 선택과 빈 상태에서 정상 상태로의 복원을 검증했다.

## 초기 수동 검증 기록

사용자가 수정 wheel을 설치한 Claude Desktop 및 합성 요약 미리보기에서 다음 동작을 확인했다.

| 환경 | 확인 범위 | 결과 |
|---|---|---|
| Claude Desktop | get_paper_detail 연결, 파일명·조회 범위, 저장 요약 부재 안내 | 확인 완료 |
| Claude Desktop | 요약이 없을 때 빈 근거 제목·검증 수준 안내 숨김 | 확인 완료 |
| 합성 HTML 미리보기 | 요약 항목의 근거 선택에 따른 페이지·원문·번역·ID 전환 | 사용자 동작 확인 완료 |
| 레이아웃 | 화면 크기별 배치와 사용성 | 추후 추가 점검 가능 |

합성 미리보기의 통과를 실제 Desktop의 저장 요약 통합 테스트 통과로 해석하지 않는다.
미리보기와 wheel은 runtime 아래의 로컬 산출물로 커밋하지 않는다.

## 2026-11-08 macOS Claude Desktop 검증 결과

main `d298f03`에서 빌드한 wheel과 합성 SQLite DB를 사용했다. 제품의 외부 번역·생성 API를 비활성화하고 `get_paper_detail`을 호출했다.

| 대화 | 확인한 동작 | 결과 |
|---|---|---|
| 시크릿 | 저장 요약 조회 | 주장과 결과 각 1건, 연결 근거 2건, 검증 수준 `structural_only`가 표시됐다. |
| 시크릿 | 요약 항목에서 근거 선택 | 두 번째 근거를 선택하면 PDF 2쪽의 `Second.` / `둘째.`가 표시됐다. 첫 번째 근거를 다시 선택하면 1쪽의 `First.` / `첫째.`로 돌아왔다. |
| 시크릿 | 요약이 없는 학습 맥락 | 저장된 요약과 표시할 근거가 없고 요약을 자동 생성하지 않는다는 안내가 표시됐다. |
| 시크릿 | 존재하지 않는 학습 맥락 | 도구가 `NOT_FOUND: 요청한 자료를 찾을 수 없습니다.`를 반환했다. |
| 일반 | 카드가 표시되지 않은 상태의 텍스트 폴백 | 요약 2건, 두 인용문의 원문·번역·페이지, 근거와 청크 ID(`e1/c1`, `e2/c2`), 리비전(`v1/p1/t1`), 검증 수준이 저장값과 일치했다. |

조회 전후 SQLite 파일의 SHA-256이 같았다. 같은 커밋에서 Python 상세 조회·MCP 테스트 40개와 상세 카드 DOM 테스트 20개가 통과했다.
