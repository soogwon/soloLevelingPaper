# 회전 문자 제외량 점검 (#26)

기존 파서는 pdfplumber의 `upright` 판정에 따라 회전 문자를 제외합니다.
그림 레이블뿐 아니라 회전된 표 헤더·본문의 고유 정보도 빠질 수 있습니다.
이번 변경은 제외량을 관찰하기 위한 것으로, 필터 정책·청킹·번역·색인을 바꾸지 않습니다.

## 집계 기준

`extract_pages()`의 각 `ExtractedPage.rotation_metrics`에서 다음을 읽습니다.

| 필드 | 의미 |
|---|---|
| `total_chars` | 회전 필터와 쪽 번호 제거 전 `page.chars` 객체 수 |
| `excluded_chars` | 그중 기존 `_is_upright` 필터가 제외하는 객체 수 |
| `excluded_ratio` | 제외 수 / 전체 수, 소수점 6자리 반올림. 전체가 0이면 0.0 |

- PDF에 명시된 공백·숫자도 char 객체이면 셉니다. 추출기가 추가한 공백·줄바꿈,
  선·사각형·이미지는 세지 않습니다. Python 문자열 길이·단어 수와 다른 지표입니다.
- 쪽 번호 제거 전 집계이므로 본문 문자열 길이와 직접 비교하지 않습니다.
- `rotation_metrics=None`은 미집계입니다. 기존 호출자가 직접 만든 페이지·HTML 경로는
  미집계이며 “회전 문자 없음”으로 해석하지 않습니다.
- 이 지표는 `upright` 필터의 제외량입니다. 모든 회전 각도의 탐지나 OCR 품질을 보장하지 않습니다.
- 이미지뿐인 페이지도 0/0일 수 있습니다. 낮은 비율은 정보 유실이 없다는 뜻이 아닙니다.

## 안전 로그

추출된 페이지마다 `stderr`에 `event=pdf_rotation` JSON 한 줄을 남깁니다.
필드는 `parse_id`, `pdf_page`, `total_chars`, `excluded_chars`, `excluded_ratio`뿐입니다.
`parse_id`는 추출 호출마다 새로 발급한 32자리 임의 ID이며 DB의 `parse_revision_id`가 아닙니다.
한 호출의 여러 페이지를 묶는 용도이고, 파일명·내용·API 키에서 계산하지 않습니다.

기본/상세 안전 로그 필터가 모두 이 고정 필드를 허용합니다. 본문·경로·추가 필드,
잘못된 ID·개수·비율은 버립니다. 출력 실패는 본문 추출에 영향을 주지 않고 stdout을 사용하지 않습니다.
집계 로그는 페이지 추출 시점의 관찰이며 등록·게시 성공 기록이 아닙니다.
기존 파싱 결과를 재사용하는 등록은 추출하지 않으므로 새로운 집계가 생기지 않습니다.

## B와 A의 범위

- B: 파서의 페이지별 집계, 안전 로그, 합성 PDF·기존 파싱 회귀 검증.
- A 확인 필요: 집계를 영속 저장할지, 파싱 리비전과 어떻게 연결해 조회할지.
- DB 스키마·기존 청크·context·등록 상태·MCP 응답은 변경하지 않습니다.
- 높은 비율의 자동 경고 임계값, 제외 문자의 복원·재파싱, 회전된 표 헤더 분류는 포함하지 않습니다.
  비율만으로 정상/오류를 단정하지 않고 해당 페이지를 확인해야 합니다.
