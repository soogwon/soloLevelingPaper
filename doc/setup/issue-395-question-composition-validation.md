# 원격 질문 검색·생성·원자 저장 조립 검증

## 역할별 구현

- A: 기존 실행·provider 원장을 공유해 매 물리 전송의 예약과 정산을 수행한다. 답변·인용은 기존 원자 저장 경로로 게시한다.
- B: 저장된 모델·프롬프트·provider profile·정책 버전을 현재 서버 조립 설정과 대조한다. 생성과 의미 검증은 같은 영속 gate를 사용한다. 논리 전송 슬롯은 실행 ID·단계·순서로 고정한다.
- C: 재조회는 실행과 호출을 늘리지 않는다. 질문 입력·사용량 불확실성·완료 상태를 기존 조회 계약으로 유지한다.

## 검증

격리 PostgreSQL에서 실제 검색·출처 읽기·원장·저장을 사용하고 HTTP와 임베딩만 합성 대역으로 실행했다. 실제 네트워크 전송은 테스트에서 차단했다.

관련 60개 회귀 통과: 정상 답변·인용 저장, 같은 실행 재조회, 네트워크 불확실성, 모델/profile/prompt 불일치, 예산 부족, 동의 철회 후 저장 거부, queue 복구·전송 이력 보호.

재검토에서 생성 이후 실행 허용을 잃는 경계를 확인하여 저장 직전 scope/허용 검사를 추가했다. 저장 transaction의 lease·동의·삭제 검사는 그대로 유지한다.

## 남은 범위

제출 시 동의·작업 예산 admission, 제품 MCP 입력, Render worker bootstrap과 운영 profile 설정이 남아 있다. 현재 factory만으로 외부 API를 실행하거나 Render 설정을 바꾸지 않는다. 실제 staging 적용·유료 호출은 별도 승인 후 진행한다. 운영 제한값과 토큰 상한 추정기는 서버 bootstrap에서 명시적으로 공급해야 한다.
