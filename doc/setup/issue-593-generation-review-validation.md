# #593 퀴즈 생성 동의·만료 검증

## 연결 범위

`prepare_remote_quiz_generation`은 저장된 인용 ID·학습 단계·문항 수/유형을 받아 서버 고정 입력과 검토 링크를 만든다. `get_remote_quiz_generation_review`는 같은 키의 상태만 읽는다. 두 도구는 검증된 owner와 `quizzes:write`를 요구하며, 동의 기록·접수·생성 도구를 노출하지 않는다. 기존 읽기 전용 MCP의 필수 scope는 늘리지 않는다.

웹 `#/quiz-generation/{requestKey}`는 판본·출처 개수·문항 범위·제공자/모델·호출/토큰 상한과 비용 발생을 표시한다. 퀴즈·정답 저장과 AI 전송에 각각 별도 체크·저장이 필요하며, 답안 제출 저장 동의와 구분한다. 동의 요청에는 고지 버전과 화면의 입력 해시를 보낸다. 두 동의가 저장된 뒤 명시적으로 접수 버튼을 누른다.

웹 세션·CSRF 검사를 거친 `/v1/remote-quiz-generation/reviews/{key}`의 조회·동의·철회·접수·취소만 제공한다. 모델의 `confirmed` 또는 임의 owner는 입력받지 않는다. 서비스 객체를 명시적으로 주입하지 않으면 HTTP는 503, 새 MCP 도구는 비노출이다. 운영 DB 역할·Auth0 설정·환경변수 자동 조립은 추가하지 않았다.

## 기한과 복구

- migration 0058은 준비 당시 입력·정책·예산 창·고지·기한과 목적별 동의 ID를 저장한다. 같은 키로 준비해도 입력을 교체하거나 기한을 연장하지 않는다.
- 서버는 검토 행 잠금을 획득한 뒤 현재 시각으로 검사하고, 동의 저장·예산 예약 후에도 다시 검사한다. 그 사이 만료되면 동의 또는 실행·입력·예산 예약을 트랜잭션 전체로 되돌린다.
- 만료·모델/정책 변경·철회된 요청은 새 접수를 허용하지 않는다. 기존에 접수된 실행의 재조회와 동의 철회·취소는 허용한다. 검토 기한은 **새 동의와 접수의 기한**이며, 접수된 실행의 종료 기한은 기존 실행 정책이 담당한다. 후속 worker 연결에서 실행 직전 권한·철회·deadline 검사를 별도 검증해야 한다.
- 화면은 서버가 알려준 남은 시간을 단조 시계로 계산해 만료 시 버튼을 비활성화하고 클릭 직전에도 검사한다. 최종 허용 판단은 서버가 한다.
- 응답 유실 시 자동 재전송하지 않고 같은 키 GET으로 상태와 실행 ID를 복원한다. 새로고침은 기존 동의 상태를 읽으며 체크를 자동 선택하지 않는다. 로그아웃·인증 만료·화면 이동 후 늦은 응답은 버린다.
- 철회된 동의는 같은 요청에서 재활성화하지 않는다. 취소는 미사용 예약을 반환하되 이미 발생한 비용을 취소한다고 안내하지 않는다.

## 검증

A: 실제 로컬 격리 PostgreSQL에서 목적별 동의, 같은 키 동시 접수, 계정 격리, 입력 해시/정책 변경, 만료 후 조회·철회·취소, 기한 연장 차단, 잠금 대기/저장/예약 중 만료 rollback을 검사했다. 기존 접수·퀴즈·요약과 비슈퍼유저 복구를 포함한 결합 검사는 93개다.

B: 기존 고정 인용을 재구성하는 준비·접수 계약을 유지한다. 새로운 논문 전송·생성 결과·의미적 정답 품질을 검증한 것은 아니다.

C: 신규 웹 대역 17개를 포함한 전체 웹 212개 통과. 두 목적 체크, 명시적 접수, 상한 불일치, 열린 화면의 만료, 유실 후 GET 복구, 늦은 인증 응답 차단, HTML 이스케이프를 확인했다. HTTP·MCP 단위 11개에서 웹 세션/CSRF·선택적 scope·모델 동의 주장 거부·안전한 오류를 검사했다.

Ruff·diff 검사 통과. 로컬 Docker 이미지에서 네트워크를 차단하고 실제 검토 서비스의 import·조립과 준비/조회 도구 등록을 확인했다. 운영 이미지에 필요한 계약·도메인 파일만 추가했다. migration 0058은 복구 SQL 허용 목록에도 반영했으며 미검토 객체 차단을 유지한다.
