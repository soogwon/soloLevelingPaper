# 재파싱 카드의 제출 전 조회와 재동의 (#267)

## 변경 범위

준비 카드를 열고 제출 전에 상태를 조회하면 서버는 `PREPARED`를 반환한다.
이 조회는 작업을 접수하거나 확인 토큰을 소비하지 않는다. 카드가 이 상태를 알지 못하고
토큰을 지우던 문제를 수정해, 같은 카드에서 사용자가 다시 동의할 수 있게 했다.

- 아직 제출하지 않은 카드가 보유한 토큰만 메모리에 유지한다.
- 조회 뒤 동의 체크를 해제한다. 사용자가 다시 체크해야 제출 버튼이 활성화된다.
- 조회만으로 준비 토큰을 재발급하거나 작업·요청 키를 새로 만들지 않는다.
- 제출 시도 후 응답 유실, 조회 오류, 대상 변경, 취소, 접수·차단 상태에서는 토큰을 복구하지 않는다.
- 다른 카드나 재시작 후 `PREPARED`를 조회해도 토큰이 없다면 안내를 다시 열도록 표시한다.
- 서버의 일회성 확인·만료·기준 색인 검사는 그대로 적용된다.

수정 대상은 C의 카드 소스·배포 HTML 및 테스트다. A 저장소와 B worker는 변경하지 않는다.
첫 임베딩 준비 시간은 이번 수정 범위가 아니며 #267을 닫지 않는다.

## 자동 검증

- UI: `ui/paper-detail`에서 `npm test`와 `npm run build` 실행.
- MCP: `python -m pytest tests/integration/test_reparse_mcp.py -q` 실행.
- 제출 전 반복 조회에서 접수·번역 호출이 0건인지 확인한다.
- 원래 토큰으로 명시적 제출한 뒤 요청은 1건만 남고 토큰 재사용은 거부되는지 확인한다.
- 조회 실패·다른 맥락·호스트 취소·늦은 응답·제출 응답 유실의 재접수 차단도 확인한다.

## 실제 호스트 후속 확인

자동 테스트는 합성 카드 DOM과 MCP 세션 기준이며 실제 Claude Desktop 검증을 대신하지 않는다.
관리 PDF와 외부 전송 조건을 확인한 테스트 환경에서 다음 순서로 확인한다.

1. 준비 카드를 열고 동의한 뒤, 제출하지 않고 상태 조회를 누른다.
2. 접수 전 안내와 해제된 동의 체크를 확인한다. 이때 작업·외부 호출이 없어야 한다.
3. 같은 카드에서 다시 동의하고 한 번만 제출한다.
4. 접수된 요청이 하나인지 확인하고, 기존 맥락은 사용자 선택 전까지 유지되는지 확인한다.

실제 PDF 번역을 포함하는 3~4단계는 자료·비용 범위를 승인한 환경에서 수행한다.
