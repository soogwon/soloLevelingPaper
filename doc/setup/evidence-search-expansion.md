# 근거 부족 시 추가 검색

## 기본 동작

검색 대상은 context에 고정된 논문·번역·게시 색인이다. 페이지·섹션을 지정하지 않으면
검색 가능한 전체 청크에서 관련도를 계산한다. 전체 논문 원문을 매번 모델에 보내는 방식은 아니다.

AnswerService는 기본 top_k=5로 생성하고, 정상적인 빈 claims가 반환되면 같은 질문으로
top_k를 두 배로 늘려 한 번만 추가 검색한다. 기본 경로는 5개 → 최대 10개다.
질문 재작성, 키워드 검색, 앞뒤 청크 추가는 이번 구현에 포함하지 않았다.

## 실행 조건과 종료

- 최초 생성 성공: 바로 반환하고 추가 검색하지 않는다.
- 최초 검색이 비었거나 top_k보다 적은 결과: 범위 내 후보가 소진된 것으로 보고 추가 검색하지 않는다.
- 형식·근거 검증 실패 또는 생성 제공자 장애: 추가 검색하지 않고 기존 실패 처리를 따른다.
- 최초 초안만 정상적으로 비었고 후보가 더 있을 수 있는 경우: 한 번 추가 검색한다.
- 확장 검색에도 새 청크가 없으면 첫 근거 부족 응답을 반환하고 모델을 다시 호출하지 않는다.
- 새 청크가 있으면 기존 청크를 포함한 확장 근거 전체로 한 번 더 생성한다.
- 두 번째도 빈 초안이면 insufficient_evidence / evidence_not_found를 반환한다.

추가 검색 상한은 생성자 인자 `max_expanded_top_k=20`이다.
확장 값은 `min(top_k * 2, max_expanded_top_k)`이며 기존 top_k보다 커야 실행한다.
이는 추가 검색의 상한이고, 호출자가 지정한 최초 top_k를 강제로 줄이는 정책은 아니다.
예를 들어 최초 top_k=15이면 확장은 20, 최초 top_k가 20 이상이면 확장하지 않는다.

## 범위와 저장 안전성

- 최초 생성·재사용한 context ID를 두 번째 검색에서도 사용한다.
- 논문 버전·파싱·번역·색인·검색 방식·페이지·섹션·질문이 바뀌면 거부한다.
- 기존 근거가 확장 검색에서 사라지거나 본문·페이지 등 청크 내용이 변경되면 거부한다.
- 두 번째 검색에서 사용자 지정 범위 밖으로 자동 확장하지 않는다.
- 성공한 최종 답변에서 사용한 근거만 한 번 저장한다. 보류한 첫 시도의 근거는 저장하지 않는다.
- 각 시도의 근거 ID는 새로 발급하며 한 요청 안에서 ID 중복을 거부한다.
- 최종 답변의 검증·인용은 그 답변을 생성한 검색 스냅샷을 기준으로 한다.

## 비용과 한계

한 사용자 질문에서 생성 호출이 최대 2회가 될 수 있다. 이는 통신 실패 재시도가 아니라
새 근거를 제공하는 두 번째 생성이다. 추가 검색 시 질문 임베딩과 검색 비용도 늘 수 있다.
직접 OpenAIClaimGenerator만 호출하는 합성 샘플 실행기는 검색 서비스가 없으므로 이 정책을 사용하지 않는다.

추가 검색은 더 낮은 순위의 근거를 확인할 기회를 제공할 뿐, 논문 전체에 정보가 없음을
증명하지 않는다. 미추출·미번역 청크는 여전히 검색되지 않는다. 의미 검증은 추가하지 않았으며
모델이 잘못된 비어 있지 않은 주장을 만들면 추가 검색이 자동 실행되지 않는다.
모델 입력 토큰 예산 기반 절단·질문 재작성·반복 검색 최적화는 후속 과제다.
