# 기존 논문 재파싱과 학습 맥락 전환 (#116)

## 현재 구현

저장 계층은 명시적 재파싱 요청 키와 입력 해시, 기준 파싱 리비전·기본 색인을 원자적으로 고정한다. 같은 입력의 별도 키만 진행 중 작업을 공유하며, 다른 입력은 작업 ID나 완료 결과에 연결하지 않는다. 새 파싱 결과의 모든 청크와 섹션은 작업이 만드는 새 파싱 리비전에 속해야 하고, 게시 경쟁 시 기존 기본 색인을 유지한다. 기본 학습 맥락 조회는 현재 게시된 기본 색인을 선택하고, 이미 생성된 학습 맥락은 자신의 파싱·번역·색인 ID를 보관한다.

완료 상태에는 새 파싱 리비전 ID와 해당 작업이 게시한 `embedding_set_id`가 함께 포함된다. `get_reparse_request`는 등록된 요청 키만 읽는 조회 경계이며, 미등록 키를 조회해도 작업이나 요청 행을 만들지 않는다. C는 완료 응답의 게시 색인 ID를 사용해 새 context를 명시적으로 만들고, 버전의 현재 기본 색인을 다시 선택해서는 안 된다. 제품 MCP 도구와 B 실행 작업자 연결은 후속 범위다.

macOS에서 임시 SQLite와 합성 번역기로 같은 버전 v1에 파싱 p1/p2, 서로 다른 청크 ID, 번역 t1/t2를 저장했다. 기존 p1 기본 색인이 있는 상태에서 일반 작업 접수는 `version already published`로 거부됐다. 게시 경계만 독립적으로 검사하기 위해 테스트 DB에 처리 중 작업을 넣고 일반 게시 함수를 호출하자 기본 색인의 버전별 고유 제약으로 거부됐다. 기존 색인만 기본으로 남았고 기존 context와 evidence ID로 조회한 인용문·페이지 등 응답 전체가 전후 동일했다. 새 기본 색인의 성공적 게시, 실제 PDF 재파싱 및 Desktop 전환은 후속 검증 대상이다.

## C가 제안하는 MCP 입력과 출력

아래는 A/B 검토용이며 도구 이름과 상태 코드는 아직 공개 API로 확정하지 않았다.

| 사용자 동작 | 입력 | 응답과 화면 동작 |
|---|---|---|
| 재파싱 안내 열기 | 기존 context ID | 신뢰된 저장소에서 논문 버전과 기준 색인을 확인한다. 파일의 표시 이름, 기존 학습 맥락 보존, 수행 단계, 예상 비용의 불확실성을 카드와 텍스트에 안내한다. 작업은 생성하지 않는다. |
| 확인 또는 취소 | 안내에서 발급한 확인 정보와 요청 키 | 명시적 확인 후에만 작업을 접수한다. 취소·만료·대상 변경 시 새 작업 없이 안내를 닫거나 다시 표시한다. |
| 진행 상태 또는 응답 유실 후 조회 | 기존 요청 키 또는 작업 ID | 같은 요청의 접수 여부·단계·결과와 계속 사용할 기존 context를 반환한다. 재시작 후에도 같은 키로 상태를 조회할 수 있어야 한다. |
| 새 리비전으로 학습 시작 | 기존 context ID와 게시 완료한 작업 ID | 작업이 게시한 정확한 색인을 검증한 뒤 새 context ID를 반환한다. 사용자가 선택하기 전에는 기존 context를 계속 사용한다. |

동의 화면에는 다음과 같이 안내한다. “같은 PDF를 다시 파싱하고 새 청크를 번역·임베딩합니다. 외부 번역이 허용된 환경에서는 원문 청크와 대상 언어가 번역 제공자에게 전송되며, 합치면 논문 전체가 될 수 있습니다. 비용과 처리 시간은 분량과 설정에 따라 달라집니다. 기존 메모와 인용은 기존 학습 맥락에 남습니다.”

등록 카드의 일회성 확인 패턴을 참고하되, 재파싱 확인은 재파싱 목적·버전·기준 색인·요청 키·전송 조건에 묶는다. 모델이 전달한 확인 불리언만으로 실행하지 않는다. 카드 미지원 호스트는 같은 안내와 상태를 텍스트로 제공하며, 신뢰할 수 있는 사용자 확인 수단이 없으면 실행 가능한 호스트로 안내한다. 동의는 외부 API 차단 설정을 변경하지 않는다.

## 접수·게시·전환 검증 기준

- 같은 키와 입력을 다시 제출하면 기존 작업을 반환한다. 같은 키의 입력이 다르면 충돌을 반환한다. 응답 유실 시 기존 키를 먼저 조회하고 유료 작업을 중복 시작하지 않는다.
- 실행 직전 파일 동일성·기준 색인·외부 전송 조건을 다시 확인한다. 안내 이후 조건이 달라지면 재확인을 요구한다. 질문·상태 조회·동일 PDF 재등록·취소만으로 시작된 **재파싱 작업 및 그에 따른 외부 호출**은 0건이어야 한다.
- 실패·중단·게시 경쟁에서는 이전 기본 색인을 유지한다. 새 색인이 준비돼도 검증과 게시가 완료되기 전에는 전환 동작을 제공하지 않는다. 게시 직후 기본 색인이 또 바뀌어도 완료된 작업과 다른 색인으로 사용자를 보내지 않는다.
- 성공 후 구 context와 evidence ID에서 인용문·물리 페이지·섹션·메모 연결이 유지되고, 새 context에서는 새 청크·번역·색인만 조회되는지 비교한다. 기존 annotation을 새 오프셋으로 자동 복사하지 않는다.
- 실제 문제 PDF에서 새 파싱의 단어 경계·겹침 시작점과 공백 없는 긴 수식·URL의 강제 분할 예외를 확인한다. 이 검증은 같은 청크의 번역만 복구하는 #30과 별도로 기록한다.

## A/B 인계 요청

1. **A** — 파일 해시가 같은 관리 PDF는 기존 version ID를 유지하는 정책을 제안한다. 새 파싱·청크·색인의 소유권, 기준 색인 비교와 원자적 기본 전환, 등록·번역 복구와의 동시 실행 규칙 및 중단 후 미게시 데이터 정리 범위를 확정해 달라. 기존 맥락이 참조하는 리비전은 보존해야 한다.
2. **B** — `prepare_reparse`로 접수하고 `get_reparse_request`로 읽기 전용 상태를 조회한다. 실행 작업자는 완료 응답의 `new_embedding_set_id`를 C에 전달하고 부분 번역 실패의 게시 허용 조건을 확정해야 한다.
3. **C** — 위 결과를 받으면 안내·확인·취소·상태 조회·명시적 새 context 전환을 연결한다. 합성 작업으로 중복·재시작·실패·이전 맥락 보존을 검증한 뒤 Desktop에서 실제 사용자 동작을 확인한다.

## C 구현과 검증 (#260 기반)

기존 학습 맥락과 요청 키로 `prepare_paper_reparse`를 호출하면 파일명·번역 제공자·모델·전송 범위와 비용 안내가 반환된다. 기존 맥락의 파싱 리비전과 색인이 현재 기본과 다르거나 외부 번역이 차단된 경우 동의 토큰을 발급하지 않는다. 안내 결과만으로 호스트의 카드 표시 여부를 판단할 수 없다.

- 동의 카드에서 확인하면 요청 키를 보관하고 `submit_paper_reparse`를 호출한다. 토큰은 일회성이며 사용자 화면 전용 메타데이터에만 전달한다. 새로 접수된 작업만 백그라운드에서 실행한다. 부분 번역 게시를 허용하지 않는다.
- 취소는 `cancel_paper_reparse`, 응답 유실·재시작 뒤 조회는 기존 맥락과 같은 요청 키의 `get_paper_reparse`를 사용한다. 미등록 키는 `NOT_FOUND`, 다른 작업이 선점한 경우는 작업 ID가 없는 `IN_PROGRESS`이며 조회로 작업을 생성하지 않는다.
- 완료 조회는 새 맥락을 생성하지 않는다. 카드에서 새 학습 맥락을 명시적으로 선택하면 `select_reparsed_context`가 작업 ID와 게시 결과를 다시 대조하고 해당 색인에 고정된 맥락 ID를 반환한다. 같은 선택을 반복하면 같은 ID를 반환한다. 과거 인용·메모는 기존 맥락에서 계속 조회한다.

합성 검증은 `python -m pytest tests/integration/test_reparse_mcp.py`와 `ui/paper-detail`의 `npm test`로 실행한다.
