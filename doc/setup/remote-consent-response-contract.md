# #396 C 동의·응답 계약 초안

기준: main `ef31be2`, #396 A/B/C 회신(2026-11-15),
[호출 예산 제안](../architecture/26-remote-execution-budget-proposal.md).
**내부 연결 초안이며 공개 API 확정·원격 유료 실행 허용이 아니다.**

이번 변경은 제품 도구에 연결하지 않은 읽기 전용 표시 모듈과 대역 테스트다.
웹 화면, 동의 저장소, 접수/예약 트랜잭션, 제공자 호출은 구현하지 않는다.
기존 로컬 RegistrationGate/ConfirmationStore의 일회성 토큰을 원격 동의로 재사용하지 않는다.

## 인증된 승인 기록과 접수 — A 확인 필요

| 항목 | 계약 제안 |
|---|---|
| 인증 owner | 검증된 issuer/raw subject를 A의 명시적 매핑으로 해석. payload owner를 믿지 않음 |
| 보관 승인 | PDF의 서버 보관 대상·목적·보존/삭제 안내에 대한 별도 consent ID |
| AI 전송 승인 | 제공자·전송 자료·목적·추가 비용을 보여 준 뒤 별도 consent ID |
| 결합 | owner, 대상 버전/업로드 의도, operation, canonical input hash, 고지 버전, consent revision·시각 |
| 접수 입력 | 서버 request key, 대상/입력, consent 참조. confirmed나 consent ID 자체는 권한이 아님 |
| 원자 접수 | 저장된 현재 승인·철회·고지·대상/입력 검사와 사용자/서비스 예산 예약 및 job 생성을 같은 원자 경계에서 처리 |
| 재접수 | owner+operation+request key는 같은 입력이면 기존 실행 재생, 다른 입력이면 충돌. input hash를 유일 키에 추가하여 충돌을 새 작업으로 허용하지 않음 |
| 전송 직전 | B/A가 현재 실행 세대·동의/철회·고지·잔여 예산을 재검사. 새 시도는 기존 논리 실행 예산에 귀속 |

동의는 인증된 웹의 명시적 변경 요청으로만 기록한다. 웹 요청에는 기존 세션/CSRF 방어를 적용한다.
링크 GET, OAuth 성공, 상태 조회, 모델의 confirmed는 승인·예약·작업을 만들지 않는다.
카드가 없으면 같은 인증된 웹으로 안내한다. 웹 링크에는 access token, presigned PUT,
질문·본문을 넣지 않는다. 링크의 의도 ID만으로 다른 계정이 접근할 수 없어야 한다.

입력 해시의 정규화/버전은 A/B와 고정한다. 질문은 context·question·focus·strict_pages·top_k 등을 포함하고,
PDF 처리에는 검증된 업로드/SHA-256·대상·처리 옵션을 포함한다. C는 자체 해시 알고리즘을 만들지 않는다.
동의에 사용할 대상·제공자·전송 자료·목적·비용·고지 텍스트도 서버의 승인된 고지에서 받아야 한다.
초기 사용자/금전 한도와 삭제 기한은 Soo 결정 전 숫자를 넣지 않는다.

## 읽기 전용 C 포트

`remote_consent_contract.py`의 Intent는 인증된 owner와 검증된 의도의 범위다.
`ConsentStatusReader.read(intent)`는 승인이나 요청 키를 소비하지 않는다.
서버는 대상 접근 권한, 보관/AI 승인 각각의 최신 고지·철회·결합을 검사한 Snapshot을 반환한다.
`CURRENT`를 클라이언트의 boolean이나 화면 체크 상태에서 만들면 안 된다.

Snapshot의 실행 ID는 동일 owner/대상/입력/키의 영속 실행을 가리킨다.
`access_allowed`는 조회 권한이며 AI 전송 동의와 별개다. 생략 시 기본 거부하며 서버의 명시적인 true만 허용한다. 삭제·계정 접근 철회는 결과 조회를 막는다.
`saved_result_available`은 서버가 조회 가능한 저장 결과를 확인했다는 뜻이다. 답변의 품질·완전성 판정이 아니다.
완료/실패 상태와 usage unknown은 별개로 유지한다. 완료라도 저장 결과 가용성이 확인되지 않으면 결과 조회를 권하지 않고 상태 재확인을 안내한다. 저장된 일부 검증 결과가 있으면 조회 안내는 가능하되
기존 답변의 partial·검증 상태를 덮어쓰지 않는다. 이 모듈은 답변 본문을 반환하지 않는다.

`recover_guidance`는 이 포트만 호출하고 새 키·submit·reserve·provider 호출 경로가 없다.
서버 오류 원문과 식별자를 표시 모델에 복사하지 않는다. 다른 범위의 응답과 접근 불가/없음은 같은 표시다.
서버 adapter 자체의 권한 검사와 로그 마스킹을 대신하는 것은 아니다.

## 표시 의미 — wire status/reason은 합의 전

| 관측 | 사용자 안내/다음 행동 | 자동 유료 재시도 |
|---|---|---|
| 보관 동의 없음/변경/철회 | 서버 보관 동의·재동의 확인, 인증 웹 | 없음 |
| AI 동의 없음/변경/철회 | 외부 전송 동의·재동의 확인, 인증 웹 | 없음 |
| 한도 부족 | 처리 제한 안내. 저장된 기록은 별도 조회 가능 | 없음 |
| usage unknown | 사용량 확인 대기. 비용 0·환급·취소를 단정하지 않음 | 없음 |
| 기존 실행 중/처리 불명 | 같은 키의 상태 조회 | 없음 |
| 기존 완료/실패 | 조회 가능한 저장 결과 또는 같은 실행 상태 확인 | 없음 |
| 저장소 장애 | 안전한 일시 오류, 같은 의도 상태 재조회 | 없음 |
| 없음/접근 불가 | 조회 불가. 새 키로 자동 제출하지 않음 | 없음 |
| 동의 current·예산 available | 명시적 제출을 검토할 수 있음. 서버 재검사가 필요 | 없음 |

표시 모델의 snake_case 문자열은 내부 테스트용이며 MCP/HTTP 응답 코드로 공개하지 않는다.
한도/동의 변경 뒤에도 기존 실행 조회를 우선한다. 새 유료 동작을 허용한다는 의미는 아니다.
동의 조회와 실제 접수 사이에 철회가 생기면 A 트랜잭션에서 거부해야 한다.
응답 유실 후 새 Presenter가 떠도 같은 Intent를 전달한다. 키의 안전한 영속 보관은 #395 연결에서 구현한다.

## 대역 테스트와 한계

```sh
python -m pytest tests/unit/mcp/test_remote_consent_contract.py -q
```

- 보관/AI 동의 분리, 고지 변경·철회, 서버 상태 재조회
- owner/대상/작업/입력/키 혼입 거부
- 완료 응답 유실 뒤 동일 실행 안내와 제출 호출 0회
- 한도/동의 변경 중 저장 결과 조회, 접근 철회 시 결과 비노출
- usage unknown·한도 부족과 근거 부족 구분, 기존 실패/불명 자동 재실행 금지
- 오류 원문 비노출, 잘못된 snapshot의 실패 처리

테스트는 네트워크 연결을 차단하고 FakeReader만 사용한다. 실제 Desktop 재시작, 동시 예약,
서버 멱등 접수, 동의 철회 경합, Auth0·DB·웹 CSRF·제공자 API를 검증한 것이 아니다.

## 합의/구현이 남은 것

- A: 동의 저장·revision·고지 조회 포트, 접수 트랜잭션 및 철회/전송 경합 처리, 조회 권한
- B: canonical input hash·제공자 전송 직전 동의/예산 검사, 제한 상태와 저장 답변 품질의 분리
- C: 확정 포트→제품 카드/인증 웹 연결, 같은 키 영속 복원, wire 응답 매핑 및 실제 호스트 검증
- Soo: 대상 사용자·초기 한도·월 비용·보관/삭제 정책

#396/#395는 열어둔다. 이 초안을 근거로 유료 도구를 allowlist에 추가하지 않는다.

## C 카드·텍스트 대역 미리보기

`remote_consent_preview.render_consent_preview`는 기존 Guidance를 동일한 문구의 HTML/텍스트로
변환한다. HTML에는 미리보기 표시와 비활성화한 type=button만 있고 스크립트·링크·폼은 없다.
현재 인증 웹 URL, consent 제출, 상태 조회 이벤트를 만들지 않는다. 페이지 출력 자체가 승인/접수가 아니다.
미지원 상태, 조회 가능 여부와 행동 불일치, 자동 유료 재시도 응답은 고정 재조회 안내로 바꾼다.
HTML 문구는 escape하며 owner/의도/실행 ID는 표시 모델에 추가하지 않는다.

대역 조회→Guidance→HTML 파싱 테스트로 문구·버튼·HTML 삽입 방어를 확인한다.
브라우저 레이아웃·클릭·실제 카드 렌더링·공개 wire 응답 검증은 아니다.
제품 연결은 A/B 포트 및 공개 응답 매핑 확정 뒤 진행한다.

```sh
python -m pytest tests/unit/mcp/test_remote_consent_preview.py tests/unit/mcp/test_remote_consent_contract.py -q
```

### 대기·취소 표시

내부 실행 복구와 동일하게 `queued`, `cancel_requested`, `cancelled`를 구분한다.
취소 요청은 취소 확정이 아니며 취소 확정도 이미 전송된 요청의 무과금·환급을 뜻하지 않는다.
기존 결과 조회는 현재 접근 허용과 저장 결과 가용성으로 결정하며, 동의 철회·usage unknown이나
취소 상태를 이유로 새 키 접수를 만들지 않는다. 이 추가 상태도 공개 wire 계약 확정은 아니다.
