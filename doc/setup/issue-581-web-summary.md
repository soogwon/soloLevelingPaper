# 웹 논문 상세의 원격 저장 요약

Refs #581. staging 변경·API 호출 없이 코드와 대역·격리 DB만 검증했다.

- 논문 상세의 기존 동기화 요약을 유지하고 별도 원격 저장 요약 영역을 추가한다. 현재 논문·판본의 성공 요약이 있는 맥락을 20개씩 조회하고 맥락별 최신 성공 요약을 표시한다. 원격 요약을 임의의 로컬 학습 기록에 연결하지 않는다.
- 웹 세션 전용 GET `/v1/remote-summaries/papers/{paper}/contexts?version_id=...&after=...` 및 `/v1/remote-summaries/contexts/{context}/latest`를 기존 요약 서비스에 연결했다. 기존 `/reviews/...` URL·동의/접수 동작은 유지한다. 기능 비활성은 503이며 새 생성·동의·작업 접수를 하지 않는다.
- owner·판본·삭제와 완료 결과 검증을 서버에서 적용한다. 화면에서도 맥락·논문·판본·게시 ID를 대조한다. 실패한 재생성은 최신 성공 요약을 바꾸지 않는다.
- 범위(전체/섹션)·판본·게시·생성 시각·항목·근거 ID를 표시한다. 구조/근거 ID 검증을 의미적 정확성으로 표시하지 않는다. 근거 ID 표시는 원문 인용을 조회했다는 뜻이 아니다.
- HTML을 이스케이프하고 로그아웃·세션 만료·화면 이동·페이지 종료 후 응답을 버린다. 조회 오류는 요약 없음과 구분하며 이전 요약을 지운다.

필수 테스트: Python HTTP/격리 PostgreSQL 3개 + 웹 10개(기존 동기화 요약 표시 회귀 포함), 총 13개 통과. Ruff·diff 검사 통과. 조회 전후 provider 시도가 증가하지 않음을 확인했다.

실제 운영 권한·설정·배포, Desktop↔웹·다기기·두 계정 실기기 검증, 실제 요약 생성·품질/비용 실측은 남는다. 이번 구현은 웹 표시 연결이며 운영 적용·실측 완료가 아니다. #581은 열어둔다.
