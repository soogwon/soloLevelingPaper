# #83 C 검증 이력 상태 응답 연결

기준 main: `ea84aa9`. C의 MCP 응답과 호스트 안내만 변경한다.
A의 저장소와 B의 답변 생성·이력 저장 서비스는 변경하지 않는다.

## 공개 계약

기존 ask_paper 응답 필드에 선택적인 verification_history 객체를 추가한다.
객체를 제공할 때 status는 not_used, saved, failed 중 하나다.

| 상태 | 호스트 안내 |
| --- | --- |
| 필드 없음 | 이력 상태 미제공. 미사용이나 저장 성공으로 추정하지 않음 |
| not_used | 검증 이력 미사용 |
| saved | 검증 이력 저장됨. 의미 검증 성공과는 별개 |
| failed | 이력 저장을 확인하지 못했습니다. 답변·근거·검증 수준은 유지 |

실패한 검증 실행이나 전부 제외된 판정도 저장됐다면 saved가 될 수 있다.
저장 오류로 질문을 자동 재실행하지 않는다. 전용 이력 화면은 이번 범위에 없다.

## B 서비스 인계 경계

현재 AnswerResponse에는 이력 상태가 없다. 따라서 기존 서비스 응답에서는 필드를
생략한다. C 어댑터는 향후 응답 객체의 verification_history 속성이
`{'status': 'saved'}` 형태의 사전일 때 상태만 복사한다. 추가 필드는 전달하지 않는다.
B의 내부 반환 타입이 달라지면 서비스 연결 시 어댑터를 맞춰야 한다.
공개 상태 계약의 합의가 내부 Python 반환 타입의 확정까지 의미하지는 않는다.

누락, None, 잘못된 타입, 알 수 없는 상태는 필드를 생략해 상태 미제공으로 처리한다.
잘못된 부가 상태로 이미 생성한 답변을 도구 오류로 바꾸지 않는다.
duplicate_run은 C가 saved로 변환하지 않는다. B가 같은 context에서 이력 동등성을
확인한 뒤 saved 또는 failed로 매핑해야 한다.

MCP SDK 1.30.0에서 선택적 TypedDict 필드가 누락되면 직렬화 결과에 None이 들어가는
경우를 회귀 테스트에서 확인했다. 출력 모델의 직렬화 단계에서 누락된 이력 필드를
제거하여 기존 일곱 필드 응답과 텍스트/구조화 응답의 일치를 유지한다.

## 검증

macOS 26.7.1 arm64 / Python 3.12.14 / MCP 1.30.0:

```sh
python -m pytest tests/unit/mcp tests/integration/test_mcp_stdio.py -q
```

결과: 378개 통과. 신규 49개 사례를 포함한다.
메모리 전송의 실제 MCP 세션에서 정상·부분·빈 답변, 두 검증 수준과
이력 세 상태/누락/잘못된 값의 조합을 확인했다. 구조화·JSON 텍스트 응답의 일치,
추가 필드의 합성 민감정보 비노출, 기존 답변과 근거 보존, 추가 생성 호출 없음도 확인했다.
기존 stdio 테스트도 통과했지만 신규 이력 상태의 실제 Desktop 화면 검증은 아니다.
