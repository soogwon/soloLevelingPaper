# #371·#372 macOS Claude Desktop 검증

검증일: 2026-11-16. 기준 main: `542ed8f`. Claude Desktop: `5.11492.5`.
별도 worktree의 wheel 설치본과 합성 SQLite를 임시 MCP 연결에서 사용했다.
실제 논문·기존 DB·외부 생성 API는 사용하지 않았다.

## #371 — 실제 카드의 응답 유실과 재시작

1. 상세 카드에서 정상 메모를 저장하고 DB와 카드의 1건 표시를 확인했다.
2. 합성 서버에서 제품 AnnotationService의 커밋 직후 응답만 120초 지연했다.
   카드가 저장 중인 동안 DB 커밋을 확인하고 Desktop을 완전 종료했다.
3. 재시작 후 새 시크릿 대화의 상세 카드에서 저장된 메모가 조회됐다.
4. 같은 입력을 다시 저장하자 별도 ID가 생성됐다. 메모와 요청 이력이 각각
   2건에서 3건으로 증가했다. 응답 유실 메모 본문이 같은 두 ID가 실제 DB에 남았다.

시크릿 대화를 새로 만들 때 카드의 `claudemcpcontent.com` origin이 달라졌다.
따라서 동일 localStorage를 주입하는 자동 테스트는 이 호스트 동작을 재현하지 못한다.
위 시험은 주입한 응답 지연 후 앱 종료이며 실제 네트워크 패킷 손실 시험은 아니다.

### 보완과 재검증

- 요청 키가 없으면 새 기록 확인 전 키 발급·생성 전송을 차단한다.
- 기존 요청 키가 남아 있으면 같은 키로 재시도한다.
- 본문으로 생성 의도를 추정하거나 같은 본문을 자동 병합하지 않는다.
- 보완 wheel을 재설치하고 Desktop을 재시작했다. 같은 입력의 저장 버튼만 누르면
  ‘이전 요청 키가 없습니다. 전체 기록을 확인하세요’가 표시됐다.
- 이때 DB 메모와 요청 이력은 각각 3건을 유지했다.
- 다른 새 메모를 입력하고 확인란을 선택하면 정상 저장되고 확인란이 해제됐다.

실제 Desktop에서 사용한 보완 wheel SHA-256:
`8f867f871528356952510ce2d48345bcb49df460da7af088e9ca0d56efc18a48`.

**남은 제한:** 새 시크릿 대화 사이에서 이전 요청 키가 자동 복원되는 것은 아니다.
사용자가 새 기록이라고 확인하면 동일 내용도 별도 생성한다. 이 최초 검증에서는
일반 대화 재개와 호스트 저장 공간 삭제 후 복구를 확인하지 않았다.

실패 기록을 대체하지 않으며 저장소 유실·새 origin·원격 계정·여러 기기 복구도 보장하지 않는다.

## #372 — 명시적 읽기 상태

- Desktop 조회: `not_started`, revision 1.
- 명시적 완료 요청: `completed`, revision 2, 기준 원문 버전 `v1`.
- Desktop 완전 종료·재시작 후 같은 상태·revision·기준 버전을 조회했다.
- `start_learning(v1)`으로 학습을 다시 열어도 `completed`, revision 2가 유지됐다.
  합성 초기 맥락과 별도 학습 맥락이 반환됐으며, 기존 메모를 자동 이관한 것은 아니다.

- 오래된 revision 1의 완료 취소는 `CONFLICT: READING_STATE_CONFLICT`로 거부됐다.
  Desktop이 자동으로 revision을 올려 재시도하지 않았으며, 조회와 DB 모두 completed/2를 유지했다.

- 최신 revision 2로 명시적 완료 취소 후 `reading`, revision 3, `action=reopen`,
  기준 버전 `v1`을 Desktop 응답과 DB에서 확인했다. 메모 4건의 ID·본문·revision은 유지됐다.

최종 재검토에서는 늦은 이전 응답이 새 화면의 확인란을 바꾸지 않도록 세대 검사를
추가하고, 원문·번역문 하이라이트의 확인 전 무전송 테스트를 보강했다. 이 추가 변경은
자동 테스트와 번들 빌드로 검증했으며 위 Desktop wheel 검증 이후의 변경이다.

## 환경 복원

임시 MCP 연결을 제거하고 원본 설정과 JSON 내용이 일치하는 것을 확인한 뒤
Claude Desktop을 재시작했다. 기존 사용자 설치본과 DB는 변경하지 않았다.

## 자동 검증

- 카드 전체 테스트: 최종 재검토에서 117개 통과. 빈 저장 공간 무전송, 명시적 신규 저장,
  입력·근거 변경 시 확인 초기화, 동일 저장 공간 재시도 키 유지 포함.
- Python 단위·stdio 통합: 30개 통과.
  annotation idempotency/origin, reading state, annotation/reading stdio 대상.
- 카드 번들 빌드 및 wheel 빌드·설치 성공.
- Python 테스트에서 기존 anyio BlockingPortal 폐기 예정 경고 1건.

서버→웹 동기화, 계정 간 접근 차단, 실제 질문 생성 후 완료 유지 및 Windows 검증은
이번 Desktop 합성 검증에 포함하지 않았다. #372 전체 종료 판단과 구분한다.
