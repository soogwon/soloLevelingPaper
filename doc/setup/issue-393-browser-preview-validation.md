# #393 로컬 업로드 미리보기 브라우저 검증

## 대상과 환경

- 기준: main `ce52f3d02776b07b25df6f625cf250ab5ece7254`, 2026-11-15 검증.
- macOS Codex 내장 브라우저, 로컬 `http://127.0.0.1:8765`.
- `ui/remote-upload-preview`만 정적 제공. 제품 웹·Claude Desktop 검증이 아니다.
- 합성 파일 `slp393-browser-fixture.pdf`(49 bytes)의 이름·크기만 선택했다. 실제 PDF 파싱·업로드·외부 AI 요청은 수행하지 않았다.

## 실행 순서와 관찰 결과

| 순서 | 실행 | 관찰 결과 |
| --- | --- | --- |
| 1 | README의 정적 서버를 실행하고 브라우저로 연다 | PDF 선택 안내, 대역 미리보기 안내, 비활성 동의·처리 버튼 표시 |
| 2 | 합성 `.pdf` 파일을 선택한다 | 파일명과 49 bytes 표시, 아직 서버로 전송하지 않았다는 안내 |
| 3 | `created` 선택 후 대역 상태 표시 | 업로드 의도 생성과 처리 접수를 구분 |
| 4 | `uploading` 선택 후 표시 | 서버 검증 완료 대기 안내 |
| 5 | `verified` 선택 후 표시 | 검증 완료와 외부 AI 동의·처리 접수는 별도임을 안내 |
| 6 | `failed` 선택 후 표시 | 같은 의도 조회 안내, 자동 재업로드하지 않음 |
| 7 | `expired` 선택 후 표시 | 의도 만료 안내, 자동 재제출하지 않음 |
| 8 | 파일 입력에서 Tab, 선택 취소에서 Enter | 취소 버튼으로 포커스 이동, 파일명·크기·이전 상태 제거, PDF 선택 안내로 복귀 |
| 9 | 취소 버튼에서 Tab, 상태 선택에서 Tab | 상태 선택 → 대역 상태 표시 순서로 포커스 이동 |
| 10 | 파일 없이 대역 상태 표시에서 Enter | 이전 파일·상태가 다시 나타나지 않음 |

다섯 상태 모두 서버 보관 동의·외부 AI 전송 동의·처리 접수 버튼이 비활성이었다.
`node --test ui/remote-upload-preview/upload.test.mjs`에 해당하는 Node 테스트 실행은 20개 통과했다.
브라우저 조작 관찰과 Node 모델/HTML 문자열 테스트 결과를 구분한다.

## 남은 검증

- 실제 인증 웹 adapter, 소유권 검증, presigned PUT, 서버 완료 조회, 원자 접수 연결.
- 실제 PDF의 내용·크기·SHA 검증과 네트워크 실패·지연·응답 역전.
- 파일 선택 대화상자 자체의 취소, 파일 교체, Windows 브라우저, 화면 낭독기·모바일 레이아웃.
- 같은 선택 세대의 서버 응답 순서 보장. 현재 대역 관찰은 서버 revision 검증을 대체하지 않는다.

이 기록은 #393의 전체 완료 근거가 아니며 티켓은 열어 둔다.
