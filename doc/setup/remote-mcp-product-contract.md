# #399 원격 MCP 제품 경계 준비

상태: #388 실측 전 계약/회귀 준비. 본 구현 완료나 공개 승인이 아니다.
#413/#415의 합성 스파이크를 유지하며 #424는 #416의 main 반영 누락을 보완한다.
#426의 인증 identity 연결은 별도 선행이다. 아래 세션 계약은 A 확인 전 제안이다.

## 단계별 허용 목록

| 단계 | 공개 가능 범위 | 선행 |
|---|---|---|
| 현재 | whoami, probe_card, probe_delay만 | 합성 스파이크 |
| 조회 | 명시적으로 검토한 context/근거 조회 | #388, #390 인증 owner/고정 출처 및 권한 회귀 |
| 업로드/유료 접수 | 승인된 업로드/접수·상태 도구만 | #393/#396 동의·예산·멱등 접수 |
| 질문 | 동일 키 접수/복구와 저장 결과 조회 | #395 + 검색/예산 계약 |
| 삭제 | 명시적인 서버 삭제 흐름 | #394/#368 |

로컬 파일 경로·로컬 PDF 열기는 노출하지 않는다. 도구 이름 denylist만으로 안전을 판단하지 않고
각 단계의 정확한 전체 도구 목록과 미허용 직접 호출을 함께 검증한다.
현재 회귀는 실제 제품 등록 함수의 목록이 정확히 3개인지 검사한다.
기존 동기화 API와 로컬 stdio는 다른 인증·저장 계약을 유지한다.

## A와 확정할 세션 계약

- 인증 요청에서 얻은 identity/owner에 서버 생성 세션을 결합한다. 세션 ID는 인증 대체물이 아니다.
- 요청마다 토큰을 검증하고, 매핑 폐기·접근 철회·세션 소유자 불일치 시 자료를 반환하지 않는다.
- 세션 TTL·idle/absolute 만료·폐기 시점·프로토콜 지원 버전은 #388 실측/A 정책으로 고정한다.
- 다중 인스턴스 공유 저장 또는 명시적 무상태 제품 설계 중 하나를 선택한다.
  프로세스 메모리 세션+우연한 sticky routing만으로 인스턴스 이동을 지원한다고 주장하지 않는다.
- 다른 계정과 미존재 세션의 응답은 존재 여부를 노출하지 않도록 같은 의미로 매핑한다.
- 세션 만료·재연결은 영속 job/요청 키 소멸이나 취소가 아니다. #395의 같은 실행을 재조회한다.
- 세션 처리와 영속 작업/결과 조회 권한을 분리한다. 세션을 새로 만든다고 유료 job을 만들지 않는다.

현재 스파이크는 모든 Mcp-Session-Id를 거부한다. 이 테스트를 상태 세션 구현/격리 성공으로 집계하지 않는다.
#388 통과 전 제품 데이터 도구와 상태 세션 구현은 진행하지 않는다.

## 오류와 롤백

무토큰/무효 토큰은 인증 경계에서 중단하며 클라이언트의 재인증 성공을 처리 동의로 승격하지 않는다.
미허용 도구는 목록에서 제외하고 직접 호출도 실패해야 한다.
MCP 전체 feature flag를 끄면 endpoint와 보호 리소스 metadata가 닫히고 기존 health/웹 인증은 유지한다.
#400의 유료 접수 차단은 전체 endpoint 중지와 다르다. 전자는 저장 결과 조회를 유지해야 한다.
