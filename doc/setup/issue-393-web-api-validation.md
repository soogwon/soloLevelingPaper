# #393 제품 웹 업로드 의도 API 연결

기준 main: `2eb7568bf5ced2cab43a7580d3b5c77d1e31b966`.
A의 #504 병합 및 #393 최신 코멘트를 기준으로 기존 기기 전용 업로드와 분리했다.

## 연결 범위

| 단계 | 이번 구현 |
| --- | --- |
| 파일 선택·지문 계산 | 최대 50 MiB, PDF 확장자/헤더/실제 크기 검사, 실제 SHA-256 |
| 업로드 의도 생성 | 인증 웹 API POST, 기존 쿠키/CSRF, 선택별 멱등 키 |
| 기존 의도 상태 조회 | 인증 웹 API GET, 같은 ID만 허용 |
| 생성 응답 유실 | 동일 화면·선택에서 같은 키/입력으로 재확인, 자동 재접수 없음 |
| 파일 교체·취소·세션 종료 | 선택 세대 무효화, 이전 성공/실패 응답 무시 |
| PDF 전송·완료 검증 | 미연결. 보관 동의 HTTP 계약 연결 전 차단 |
| AI 전송·처리 접수 | 미연결. PDF verified를 작업 완료로 간주하지 않음 |

UI의 파일 정보 전송 확인은 서버 PDF 보관 동의나 AI 동의 기록을 대체하지 않는다.
화면은 파일명·크기·형식·지문만 전송한다. URL·토큰·PDF 본문은 저장하거나 로그에 출력하지 않는다.
요청 키는 메모리 범위이며 새로고침·다른 origin·여러 기기 복구는 보장하지 않는다.

## 검증

- 웹 테스트: `node --test web/tests/*.test.mjs` — 42개 통과.
- 서버 계약: `python -m pytest -q tests/unit/test_remote_upload_routes.py tests/unit/test_remote_uploads.py` — 36개 통과, 기존 anyio 폐기 예정 경고 1건.
- `git diff --check` 통과. 두 테스트 묶음 모두 실패·skip 없음.
- 선택만으로 API 호출 0, 동의 후 JSON 메타데이터만 전송, CSRF/쿠키/멱등 키 확인.
- 생성 응답 유실/중복 클릭/상태 응답 유실/다른 ID 응답/만료·권한·충돌 거부 확인.
- 파일 교체·선택창 취소·로그아웃·인증 만료의 이벤트 연결 및 늦은 응답 차단 확인.
- 실제 바이트 SHA-256 계산과 잘못된 파일 헤더/크기/이름 거부 확인.

브라우저 전송은 fetch 대역으로 검사했고 서버 계약 테스트는 별도로 실행했다.
실제 staging/R2 업로드·인증된 두 계정·네이티브 파일 선택창·화면 낭독기 검증을 수행한 결과가 아니다.
제품 backend·동의 원장·R2 설정은 변경하지 않는다. #393은 열어둔다.

## 후속

1. A: 보관/AI 동의 발급 HTTP 경로와 고지 버전·대상/입력 결합, 철회·세션 변경 규칙 확정.
2. C: 그 계약으로 prepare→PUT→complete를 연결하고 URL은 화면/로그/영속 저장소에 남기지 않기.
3. 처리 접수 계약 연결 후 응답 유실 시 동일 작업 조회 검증.
4. 실제 R2·두 테스트 계정·만료 정리·로그 비노출 및 Windows/macOS 실브라우저 검증.


## A에게 필요한 동의 HTTP 계약

- PDF 서버 보관 동의와 외부 AI 전송 동의를 별도로 발급·조회할 경로, 요청/응답 스키마.
- 인증 owner, 업로드 의도·논문·버전, 파일 SHA-256, 처리 입력과 고지 버전을 서버에서 결합할 기준.
- 동의 없음·철회·고지 변경·대상 불일치·만료·사용량 미확정의 고정 오류와 기존 결과 조회 허용 범위.
- 동의 응답 유실 뒤 같은 의도로 조회/재시도할 멱등 키 및 수명. 클라이언트 확인란을 서버 승인 증거로 신뢰하지 않기.
- prepare/complete와 처리 접수에서 각각 다시 검사할 권한·동의 조건, 철회/삭제/동시 요청과의 원자 경계.
- 검증된 업로드에서 기존 처리 작업 ID를 조회하는 방법과 새 작업 중복 생성 방지 계약.

이번 UI는 위 계약을 새로 정의하거나 A 저장소를 변경하지 않는다. 서버에 보내는 파일 정보 확인란은
사용자에게 전송 대상을 설명하는 단계이며, 영속 storage/AI consent 원장의 승인을 대체하지 않는다.

재검토에서 화면 이벤트 테스트의 고정 10ms 대기를 제거하고 실제 비동기 완료를 기다리도록 바꿨다.
파일 교체 후 이전 요청의 늦은 403 오류도 새 선택을 덮지 않는 회귀를 추가했다.
