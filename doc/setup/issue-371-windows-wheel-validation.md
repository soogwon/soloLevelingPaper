# #371 Windows·wheel 재시작 복구 검증

검증일: 2026-11-16. 기준 main: `247333441790c6dc5ad95fef2b140c03a8e05ec0`.
Windows NT 10.0.26300.0 / Python 3.12.14 / Claude Desktop 5.11492.5에서 확인했다.
별도 worktree와 합성 SQLite를 사용했으며 실제 논문·번역·임베딩 API는 호출하지 않았다.

## 설치본과 시험 조건

- 소스에서 wheel을 빌드해 별도 venv에 `--no-deps --no-index`로 설치했다.
  서버는 `python -I`로 실행하고 모듈 경로가 해당 venv의 site-packages임을 확인했다.
- 의존성은 기존 개발 환경의 site-packages를 테스트 venv의 `.pth`로 재사용했다.
  따라서 새 PC에서의 의존성 설치 검증은 아니다.
- wheel SHA-256: `f7da40ce4950f831926e458846e5d715226fbf24cba813ec5e96dbc8de56989d`.
- 설치본 상세 카드 HTML SHA-256:
  `f61252b91c9af2553a836fe92a49b548b27c33a517526c61949b4e117c362c06`.
  제품 소스의 HTML과 일치한다.
- 합성 서버는 설치된 제품의 상세 조회·AnnotationService·SQLite 저장소를 사용한다.
  최초 생성의 실제 커밋 후 MCP 성공 응답에서 `annotation.revision`만 제거했다.
  키 발급·제품 HTML·저장 로직·호스트 저장 공간은 변경하거나 주입하지 않았다.
- 모델 서비스를 구성하지 않고 HTTP 요청과 외부 소켓 연결을 차단했다.
  Windows 이벤트 루프에 필요한 loopback 소켓만 허용했다.

## Desktop 실제 흐름과 결과

| 단계 | 관찰 및 검증 |
|---|---|
| 최초 저장 | 새 일반 대화의 실제 상세 카드에서 합성 메모를 입력하고 새 기록 확인 후 저장했다. DB에 메모 1건·요청 이력 1건이 커밋됐다. |
| 불완전 응답 | revision이 빠진 응답을 받은 카드가 저장 결과 미확정 안내를 표시했다. |
| 완전 재시작 | Desktop의 Exit로 종료하고 창과 테스트 MCP 프로세스 종료를 확인한 뒤 다시 실행했다. |
| 새 상세 조회 | 같은 일반 대화에서 상세 조회를 새로 호출했다. 새 카드가 표시됐고 origin은 종료 전과 같았다. 기존 메모 1건도 조회됐다. |
| 동일 입력 재제공 | 같은 내용을 다시 입력하고 새 기록 확인란을 선택하지 않은 채 저장했다. 두 요청의 키 SHA-256이 같고 두 번째 응답은 `reused=true`였다. |
| 데이터 불변 | 메모 ID `3477340f-fe51-4893-9c6a-51c3e50a4a41`, revision 1, 본문·생성 시각·수정 시각 및 요청 이력이 첫 커밋 직후 스냅샷과 완전히 같았다. 메모·요청 이력은 각각 1건이다. |
| 확정 후 추가 클릭 | 동일 내용을 다시 입력해 확인란 없이 저장하면 ‘이전 요청 키가 없습니다. 전체 기록을 확인하세요’ 안내로 차단됐다. 생성 도구 호출은 총 2회에서 늘지 않았다. |

같은 요청 키의 SHA-256은
`466f82e1c5e7d2f7068ce38d78e2b5f5d936848103c8e0379d36ade93ba2c0ed`이다.
원시 키·설정 백업·DB·실행 로그는 커밋하지 않는다.
입력 초안이 자동 복원된 것은 아니며 사용자가 동일 입력을 다시 제공하는 흐름이다.

Claude의 채팅 본문에는 카드가 보이지 않는다는 설명이 있었지만 실제 Desktop 화면과
접근성 트리에서 제품 카드와 메모 입력·저장 버튼을 확인하고 직접 사용했다.
초기에 설정 적용 전 생성한 별도 대화에서는 카드가 표시되지 않아, 설정을 적용하고
새 일반 대화에서 위 시험을 수행했다. 과거 카드의 즉시 재사용을 보장하는 결과는 아니다.

## 자동 검증과 환경 복원

- 생성 멱등성·작성 주체·실제 stdio 회귀 테스트: **26 passed, 경고 1건**.
  실행 범위는 `test_annotation_idempotency.py`, `test_annotation_origin.py`,
  `test_annotation_stdio.py`이며 소스와 개발 Python으로 실행했다.
  경고는 Starlette의 AnyIO BlockingPortal 폐기 예정 경고다.
- 설치 wheel의 실제 stdio 사전 검사: 상세 근거 1건과 HTML resource 읽기 성공,
  생성 호출 0회. 위 Desktop 저장·복구도 동일 설치 wheel로 실행했다.
- 테스트용 연결만 사용하는 동안 기존 Desktop 연결은 잠시 제외했다.
  실제 Claude-Data 설정과 Roaming 설정 모두 백업과 바이트 단위 동일함을 검증하고
  원래 설정으로 Desktop을 다시 실행했다.
- 기존 논문 DB의 SHA-256은 시험 전후 동일했다. 합성 DB와 증적은 무시되는
  worktree `runtime/` 아래에만 저장했다.

## 지원 범위와 남은 검증

Windows 설치 wheel에서도 같은 일반 대화·동일 origin·저장 공간이 유지되면
불완전 성공 응답 뒤 전체 앱 재시작과 새 상세 조회를 거쳐 기존 키·메모를 재사용했다.
이는 실제 패킷 유실 시험, 새 시크릿 대화·저장 공간 삭제·다른 origin·원격 계정·
여러 기기 복구 또는 깨끗한 PC 설치 검증은 아니다.
기존 [macOS 검증](issue-371-372-desktop-validation.md)의 origin 변경 제한도 유지된다.
#371은 로컬 생성 멱등성 범위로 종료된 상태이며 이번 검증은 Windows·wheel 증거를
추가한다. 원격 계정·여러 기기 복구는 #502, 서버→웹 종단 검증은 #375/#214의
별도 범위다. 해당 후속 검증의 완료를 뜻하지 않는다.
