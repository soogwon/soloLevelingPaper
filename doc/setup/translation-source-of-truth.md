# 번역문 판단 기준: translation_results (#30 후속)

번역 성공 여부와 번역문은 **번역 리비전별 결과 표(`translation_results`)** 가 기준이다. `chunks.text`는 이전 버전 호환용 사본으로만 남기며, 판단에 쓰지 않는다.

| 동작 | 기준 |
|---|---|
| 최초 등록 재개 시 번역할 청크 선택 | `translation_results`에 성공 행이 없는 청크(실패 행이 있는 청크 포함). 번역 리비전이 아직 없으면 모든 청크 |
| 같은 배치 재저장 | 같은 청크의 결과 행과 비교. 같으면 건너뜀 |
| 성공 번역 덮어쓰기 거부 | 결과 행에 성공 번역이 있으면 다른 내용으로 바꿀 수 없음 |
| 게시 전 성공 수 검증 | 지정한 번역 리비전의 성공 행 수와 게시할 청크 수가 같아야 함 |
| 기존 DB 이관(`init_db`) | `translated_text`를 채우고, 결과 행이 없는 옛 성공 청크(`chunks.text`만 있는 청크)를 성공 행으로 옮김. 사본은 그 번역 리비전이 가리키는 파싱 리비전의 청크일 때만 이관한다(다른 파싱 리비전의 사본은 무시). 이미 있는 행은 바꾸지 않음. 반복 실행해도 같음 |
| 게시된 색인의 성공 청크 집합(`search_index_chunks`) 복원 | 구버전 DB의 청크 소속은 현재 번역 성공 행이나 `chunk_count`로 추측하지 않음. `init_db`는 출처 표식이 없는 소속을 미확인 상태로 비우며 기존 답변·최종 근거·검증 이력은 보존함. 런타임이 실제 Chroma 컬렉션의 ID 개수와 각 항목의 색인·논문·버전 메타데이터를 모두 확인한 경우에만 정확한 집합을 복원하고 출처를 기록함. 확인할 수 없으면 참조 이력 저장은 `reference_mismatch`로 거부함. 반복 실행 결과는 같음 |
| 최초·복구 색인 게시 | 벡터 검증을 마친 청크 ID 집합을 게시 함수에 전달한다. 게시 트랜잭션에서 `failure_code IS NULL`이면서 `translated_text IS NOT NULL`인 정확한 DB 집합과 비교하고, 일치할 때만 그 ID들을 `search_index_chunks`에 기록한다. 개수만 같은 다른 집합도 거부하며 실패 시 색인·멤버십·상태 변경을 모두 롤백한다. |

## 하지 않은 것
- `chunks.text` 컬럼 삭제: 이전 버전과의 호환을 위해 이 변경에서는 지우지 않는다. 삭제는 별도 이슈에서 다룬다.
- 게시된 번역의 변경, 자동 재번역: 계속 금지한다.
