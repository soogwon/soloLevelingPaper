# #592 웹 동의·MCP 저장 역할 분리

실제 staging 변경 없이 로컬 격리 PostgreSQL에서 별도 비특권 로그인 두 개를 만들고 확인했다. 기존 자격을 재사용하지 않고 새 전용 역할에 적용한다. helper는 슈퍼유저·권한 생성·DB 생성·RLS 우회·권한 상속·다른 역할 멤버십을 거부하고, 같은 역할을 웹/MCP 두 프로필로 겸용하지 못하게 한다. 기존 다른 GRANT를 회수하는 도구는 아니므로 새 역할을 사용해야 한다.

- 웹: 고정 맥락 조회 및 `remote-reflection-v1` 저장 동의 INSERT/철회만 허용. 다른 목적/고지·철회 복원, 답변 쓰기 불가.
- MCP: 고정 질문/답변/요청 이력 조회·저장·CAS 갱신·삭제 본문 제거. 동의는 조회·행 잠금만 허용하고 실제 INSERT/UPDATE는 거부.
- 공통: 논문 행 잠금 권한은 수정 차단 trigger로 보호. 웹 세션·기기 자격·예산·dispatch 변경 불가. owner 격리는 제품 인증 계층에서도 계속 검사한다.

migration 0056은 역할별 동의 보호 함수를 추가한다. 신규 기능은 자동으로 활성화하지 않으며 DB 역할을 자동 생성하지 않는다. 비슈퍼유저 복구 SQL의 함수 허용/정리 목록도 갱신했다.

검증: 권한 종단·migration·백업/비슈퍼유저 복구 29개 통과, 강화한 역할 검사 후 권한 종단 재통과. AI 호출·실제 staging 변경 없음.

실제 적용 전에 승인할 범위: migration 0054/0056의 현재 상태 확인, 새 성찰 웹/MCP 역할 생성·최소 권한/접속 검사, 별도 자격 입력, Auth0 reflections:read/write 검증 계정 연결, 기능 flag·웹 배포, 합성 기록 저장/수정/삭제 검증. 서비스 설정 조립과 실행 스크립트/실패 복구 리허설이 준비된 뒤 별도 승인을 받는다. 기존 계정/기록/동의는 변경하지 않는다.

## 서비스 조립

`REMOTE_REFLECTIONS_ENABLED=true`, `REMOTE_REFLECTION_WEB_DATABASE_URL`, `REMOTE_REFLECTION_MCP_DATABASE_URL`을 모두 명시해야 조립한다. 기본값은 비활성이고 일반 DATABASE_URL로 대체하지 않는다. 두 URL은 같은 DB·검색 경로의 서로 다른 역할이어야 한다. 웹 API는 웹 풀, MCP 도구는 MCP 풀을 사용하며 시작 실패에도 두 풀을 정리한다. 오류와 repr에 자격을 노출하지 않는다. 설정/조립과 기존 메모·성찰 경계 대역 33개 통과.

## staging 이미지 기동 실패와 보완

2026-11-19 승인된 ab2dadd 배포에서 schema 검사는 통과했으나 이미지에
`solo_leveling.domain.reflection`이 없어 기동하지 못했다. 기존 e12961b 웹은
Live를 유지했다. 성찰 flag는 false로 저장하고 검증 계정의 성찰 허용 표시를
회수했다. Auth0 scope 정의와 클라이언트 허용 목록은 보존했으므로 전체 설정
원복으로 표현하지 않는다. 새 합성 답변 저장과 AI 호출은 실행하지 않았다.

Docker 허용 목록에 성찰 도메인과 MCP 모듈만 추가했다. 실제 설치 이미지에서
네트워크를 끄고 제품 조회·메모·취소·성찰 기능 조립을 함께 실행하여 네 가지
성공 표식을 확인했다. 성찰 동의 웹 경로와 5개 MCP 도구 등록도 검사한다.
이 검증은 DB 접속·인증 토큰·실제 저장 검증을 대체하지 않는다. 보완 이미지의
staging 재배포와 검증 계정 재허용, 재인증·합성 CRUD·동의 철회는 남아 있다.
