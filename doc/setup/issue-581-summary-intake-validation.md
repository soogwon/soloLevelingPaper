# #581 요약 접수·예산·결과 저장 검증

## 구현

- A: `generate_paper_summary` 작업으로 별도 접수한다. 동일 owner/요청 키는 단일 실행·단일 전체 예산 예약에 연결한다. 서버가 원문과 설정을 다시 읽어 준비 해시를 대조한다. 타 계정·삭제·철회·입력 위조·미승인 모델은 접수하지 않는다.
- B: 입력 snapshot은 변경 불가이며 결과 항목을 모두 구조 검증한다. 현재 lease의 알려진 generation 사용량 1건이 있어야 완료를 저장한다. 취소·기한 만료·이전 lease의 늦은 완료 및 미확정 사용량은 완료 게시를 거부한다.
- C: 동일 요청 키로 재조회하며 새 생성은 하지 않는다. 저장 결과 해시·판본·근거를 다시 검증한다. 기존 질문 worker는 요약 작업을 가져가지 않는다.

DB 원장의 목적 값은 공통 `storage`/`ai_provider`를 사용하되 **새 요약 전용
입력 해시와 `remote-summary-v1` 고지**로 구분한다. 계약 객체의
`summary_storage`/`summary_ai`는 제품 의미이며 기존 질문 동의를 재사용하지 않는다.

`server_question_budget_reservations`라는 기존 이름의 원장은 실행 ID별 전체
예약에 사용한다. 질문 전용 입력이나 worker를 재사용하지 않는다. 현재 실행
정책은 최대 호출 1회만 허용하며 수치와 모델은 신뢰하는 서버 설정에서 전달한다.
동일 정책 버전이라도 재접수 시 상한이 바뀌면 거부한다. 취소 시 아직 전송하지
않은 예약만 기존 원장 trigger로 반환한다.

새 `server_summary_inputs`는 실행 삭제 시 함께 정리한다. 비슈퍼유저 복구의
테이블/함수 명시 목록도 확장하며 RESTRICT를 유지한다.

## 검증

- 로컬 PostgreSQL 요약 접수·결과 회귀 20개 통과.
- 기존 질문 예산 회귀와 함께 19개 통과(결과 저장 추가 전 확인).
- 단위 계약·migration·요약 준비·제한 웹 계정·백업/복구를 포함한 109개 통과 후, 기존 성공 요약 보존과 재claim 늦은 완료 회귀 2개를 추가해 접수·결과 20개를 재확인했다.
- 전송은 대역 함수만 호출했다. 외부 API·staging 변경은 없다.

동시 동일 키/다른 키, 예약 초과 rollback, 취소 후 재조회, 재시작 결과 복구,
타인 접근, 조작된 원문/모델, 다른 고지, 철회, 늦은 완료, 잘못된 근거와
미관측 사용량 차단을 포함한다. 의미적 요약 품질 검증 통과로 간주하지 않는다.

## 남은 범위·실제 적용 전 승인

이 PR은 제품 공개/worker 활성화를 하지 않는다. 서버 소유의 준비/고지·동의
저장 화면, review 만료, 사용자별 허용 모델/호출·토큰·비용 상한 표시, 요약
전용 worker 조립·취소/실패 회수·만료 정리, MCP/웹 도구와 카드, 저장 근거
재조회·내보내기 연결이 남는다. 미완료 결과는 기존 요약을 덮어쓰지 않지만
최신 성공 요약 선택 UI도 후속 범위다.

실제 환경에는 migration 0052, 전용 역할의 최소 권한과 새 scope/기능 설정이
필요하다. 변경안과 복구안을 검토한 뒤 승인받아 적용하며 실제 생성 데이터,
모델·호출 수·비용 상한은 별도로 승인받는다. 이번에는 적용하지 않았다.
