# #587 번역 품질 복구·원문 폴백 검증

## 적용 범위

runtime 설정 v3에서 `translation_recovery_policy: "layout-aware-v1"`을 명시한 경우에만 활성화한다. 기존 v1/v2 설정은 추가 번역 호출을 만들지 않는다. provider 자체 재시도는 각 pass 1회로 제한하므로 품질 재시도를 포함해 청크당 최대 2회다. 참고문헌·번역 불필요 구간은 제공자를 호출하지 않는다.

첫 응답이 빈 번역·미변경 영어·대상 언어 불일치일 때 줄바꿈·하이픈 단서를 본문 없이 진단하고, 읽기 순서를 추측하지 않는 강화 지침으로 한 번 재시도한다. 요청 원문과 부모 청크는 변경하지 않는다. 기한이 지나면 재시도하지 않는다. PDF 블록 좌표에 기반한 실제 2단 읽기 순서 복원까지 구현한 것은 아니다.

## A·B·C 확인

- A: 기존 작업·동의·예산 원장을 유지한다. 재시도 payload도 별도 승인 상한과 영속 전송 키를 통과해야 하며, 예산 거절·응답 불명확·동의 오류를 원문 성공으로 바꾸지 않는다. 재시작 시 같은 논리 전송 키를 사용해 중복 전송을 방지한다.
- B: 최종 품질 실패는 원문과 실패 코드를 `original_only`로 보존한다. 성공 건수는 늘리지 않고 검색 가능한 상태와 번역 성공을 구분한다. 제공자 불가 상태는 폴백하지 않는다.
- C: 저장된 원문 폴백을 한국어 번역으로 제공하지 않도록 검색 출처의 번역 본문은 비워 둔다. 원문 검색과 기존 근거 ID를 유지한다. 게시 metadata에는 상태별 건수를 남긴다.

## 검증

- 번역·처리·설정 관련 714개와 하위 테스트 19개 통과.
- 대역 전송에서 동일 작업의 최초/재시도 키 구분, 다시 실행했을 때 같은 키, 두 번째 예약 거절 후 추가 HTTP 미호출 확인.
- 로컬 PostgreSQL에서 원문 폴백의 상태·실패 코드 저장, staging 복구·원자 게시·부모 검색을 확인했다.
- 실제 API 호출·PDF 전송·staging 변경 없음.

## 남은 범위

migration 0051, 실제 권한·runtime 설정과 추가 번역 호출은 별도 승인 이후 적용한다. 실제 논문의 PDF 레이아웃 개선과 번역 품질·검색 품질 비교, 기존 로컬 색인의 명시적 이관은 남아 있다. 이 PR로 #587을 종료하지 않는다.
