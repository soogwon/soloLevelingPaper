# 퀴즈 시도 목록의 동률 정렬 계약 (#176, #145 후속)

시도 목록(`list_quiz_attempt_page`, `list_quiz_attempts`)은 제출 시각으로 정렬하고, **같은 시각이면 영속 저장 순번 `attempt_seq`** 로 정한다.
최신순 조회는 시각 내림차순, 같은 시각이면 순번이 큰(나중에 저장한) 시도가 먼저다. `attempt_id`의 사전순과 암묵적 `rowid`는 쓰지 않는다.

- **순번 부여**: 시도를 저장하는 쓰기 트랜잭션(`BEGIN IMMEDIATE`) 안에서 `기존 최댓값 + 1`을 붙인다. 동시에 저장해도 중복·빈틈이 없다(유일 인덱스 `idx_quiz_attempts_seq`).
  한 번 붙은 순번은 바꾸지 않는다. 시도를 지워도 남은 시도의 순번은 그대로이고, 다음 순번은 남은 최댓값 뒤로 이어진다.
- **왜 rowid가 아닌가**: `quiz_attempts`는 `INTEGER PRIMARY KEY`가 없는 표라 암묵적 `rowid`는 VACUUM·복원·재적재 때 바뀔 수 있다는 것이 SQLite의 보장이다.
  순번은 열로 저장되므로 그런 작업 뒤에도 같은 순서와 같은 커서 위치를 준다.
- **기존 DB 이관**: `init_db`가 열을 더하고, 비어 있는 행에 지금 보이는 순서(제출 시각, 같은 시각이면 저장 순서)를 그대로 보존하도록 번호를 채운다. 반복 실행해도 같은 결과이며,
  이미 채워진 순번은 바꾸지 않고 비어 있는 행만 최댓값 뒤로 이어 채운다. 이관이 끝나면 순번 기반 인덱스를 만들고 이전 인덱스(`idx_quiz_attempts_context`, `idx_quiz_attempts_context_time`)를 지운다.
- **커서**: 형식은 그대로(이전 페이지 마지막 항목의 `attempt_id`)이며, 읽을 때 그 시도의 `(제출 시각, 순번)`을 찾아 `(submitted_at, attempt_seq) < (?, ?)` 행 값 비교로 인덱스 범위를 시작한다.
  행 값 비교에는 SQLite 3.15 이상이 필요하다. 커서가 가리키던 시도가 지워졌거나 범위 밖이면 기존처럼 `AttemptValidationError`다.
- **깊은 페이지 비용**: 같은 제출 시각의 시도 10,000건에서 20건 페이지의 SQLite 실행 명령 수(progress handler로 측정)는 앞쪽 커서 446, 뒤쪽 커서 418(`step=review`는 453과 228)이다.
  시각만 범위로 쓰고 순번은 OR로 거르던 이전 방식은 같은 조건에서 뒤쪽 커서가 70,258이었다.
- 순번은 저장·정렬용이며 MCP 응답에는 노출하지 않는다.
