# #396 제한 사유별 웹 안내

2026-11-17. #531의 공개 코드 대응 계약을 기준으로 기존 처리 상태 조회 화면을 보강한다.
서버의 기존 job/paper/version/status 검증 이후 failed 응답의 허용된 error_code만 안내에 사용한다.
코드가 없는 기존 응답, 알 수 없는 코드·잘못된 타입은 기존 일반 실패 안내를 유지한다.

| 공개 코드 | 안내 |
|---|---|
| storage_consent_required | 현재 PDF 보관 동의 안내·상태 확인 |
| ai_consent_required | 현재 외부 AI 전송 동의 안내·상태 확인 |
| budget_unavailable | 예산 또는 사용량 한도 확보 실패, 같은 작업 조회 |
| usage_pending | 사용량·비용 확인 대기, 미과금·환급 미확정, 같은 작업 조회 |
| provider_temporarily_unavailable | 제공자 일시 장애, 같은 작업 조회 |
| source_validation_failed | 원본 PDF 검증 실패, 입력 확인 |
| lease_expired | 실행 권한 만료, 같은 작업 조회 |
| processing_failed | 일반 처리 실패, 같은 작업 조회 |

동의 없음·철회·고지 변경은 이 코드만으로 구분할 수 없다. 철회됐다고 추정하거나 새 공개 코드를 만들지 않는다.
내부 DISPATCH 코드와 청크 provider_unavailable을 공개 제한 사유로 변환하지 않는다.
작업 상태는 오류 필드로 바꾸지 않으며 cancelled 안내도 그대로 유지한다.
retryable=true여도 명시 재시도 API 연결 전에는 재시도 버튼·새 키·접수·AI 호출을 만들지 않는다.
서버의 원시 오류·상세·추가 필드는 화면에 복사하지 않고 고정 문구를 textContent로 표시한다.

상태와 사유 분리, 추가 필드 비노출, 같은 의도 재조회만 호출, 조회 실패·대상 변경 후 안내 초기화를 검사한다.
