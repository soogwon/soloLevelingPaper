# #108 페이지 경계 보충 검증

2026-11-05 Windows에서 `origin/main`의 `08e4f1e`를 기준으로 기존 #108 초안을 통합했다. 검증에는 합성 데이터, 임시 SQLite·Chroma 및 제공자 대역을 사용했다.

| 범위 | 확인한 동작 |
|---|---|
| 6페이지 | 같은 섹션의 7페이지 첫 구절이 미완결 문장을 이으면 첫 문장 끝까지만 전달한다. 근거는 7페이지의 원래 청크 ID를 유지한다. |
| 6페이지, strict_pages=true | 7페이지 구절을 전달하지 않는다. |
| 6·7페이지 | 두 페이지 모두 일반 검색 대상이다. |
| 6·9페이지 | 6페이지 뒤의 7페이지를 범위 밖 보충 대상으로 사용하지 않는다. |
| 섹션 정보 누락·불일치 | 원문이 이어지는 것처럼 보여도 범위 밖 구절을 보류한다. |

기존 초안에서는 양쪽 섹션 ID가 모두 없거나 지정 페이지 사이에 공백이 있는 경우에도 보충되는 현상을 재현했다. 수정 후에는 마지막 지정 페이지에서만 같은 섹션의 다음 페이지를 확인한다. 공백 없는 마침표, 전각 종료 부호, 약어, 무관한 다음 조각, 표·캡션 또는 빈 줄이 구절에 끼어든 사례를 검사한다. 생성·검증·인용에는 같은 원문 발췌를 사용하며 번역 구절의 위치를 알 수 없으면 번역 인용을 비운다. 검증 이력의 원문 해시는 저장소 계약에 따라 전체 청크를 기준으로 계산한다.

페이지 밖에서는 `etc.`처럼 문장이 끝났는지 모호한 약어를 만나면 보충을 보류한다. `Eq. 3` 같은 번호 참조와 `.5` 같은 소수는 중간에서 자르지 않는다. 도메인 내부의 구절이나 소수점에서 끊긴 인용은 기존 추출 위험 판정을 유지한다.

## 오프라인 결과

- 검색·추출·생성·평가·검증 이력·MCP 단위 테스트 및 SQLite·Chroma 통합 테스트 566개, 하위 검증 56개 통과.
- 합성 평가 실행기로 전체 사례를 2회 반복해 48건을 집계했다. 같은 조건으로 한 번 더 실행해 비교한 결과 변경 사례는 0건이었다. 고정 응답 대역을 사용한 재현성 점검이다.

## 제한과 남은 검증

파서가 표·캡션·꼬리말 유형을 청크에 저장하지 않아 평문처럼 추출된 비본문을 항상 구별할 수는 없다. 페이지 밖 연결은 충분한 원문 겹침 또는 제한된 명사구 연결(sequence → length, path → length, representation → dimensionality)에서만 허용한다. 이 방식은 지원하지 않는 정상 연결도 보류할 수 있다.

실제 모델 품질 측정과 Claude Desktop에서의 범위별 확인은 별도 단계로 남아 있다.
