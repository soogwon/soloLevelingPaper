# 21. 팀원 3명 로컬 M1 개발 분담

작성일: 2026-09-07  
상태: 로컬 M1 전환 반영 / 실명 담당 미정

## 목표

기존 코드를 가져오지 않고, 3주 안에 Claude Code에서 로컬 stdio MCP를 사용해 PDF 한 편을 등록·질의하고 실제 페이지 근거를 확인한다. 공동 서버는 후속 단계다.

## 담당과 경계

| 담당 | 작업 | 첫 주 산출물 |
|---|---|---|
| A: PDF·데이터 | pdfplumber, 페이지 청킹, SQLite, Chroma 저장, sentence-transformers, 내부 색인 작업 | PDF→원문·페이지·벡터 저장 |
| B: 검색·AI | 범위 검색, 생성·검증 API, claims·근거, 요약·가이드 | 샘플 청크 기반 한국어 근거 답변 |
| C: MCP·실행 | stdio 도구, 로컬 설정·파일 범위, 설치 안내, 로그·오류, 통합 테스트 | Claude Code 도구 연결과 파일 등록 |
 
A와 B는 임베딩 검색 품질을 함께 평가한다. B의 가이드 작업은 A가 개념 데이터 검수로 지원한다. C는 OAuth·원격 배포·웹 업로드 대신 로컬 설치 재현·프로세스 수명·경로 접근을 맡는다.

## 먼저 합의할 계약

- local_profile_id는 서버 내부 생성이며 사용자 로그인이나 토큰이 아니다.
- version_id·parse_revision_id·chunk_id·translation_revision_id를 통일한다. text는 한국어 번역문, original_text는 추출 원문이다.
- 인쇄 번호 printed_page_label을 우선 표시하며, 없거나 불확실하면 'PDF 기준 N페이지'로 대체한다. pdf_page는 파일 위치용 1-based 물리 페이지로 보관한다.
- 첫 청크는 페이지를 넘기지 않고 section은 null을 허용한다.
- 원문 기준 데이터는 SQLite, 벡터는 Chroma이며 ID로 대조한다.
- 답변은 status·answer_ko·claims·citations·reason_code로 전달한다.
- 입력 경로는 import 루트 상대 경로만 허용한다.
- 작업은 queued/processing/ready/failed/interrupted로 구분한다.

번역은 A가 원문·페이지 매핑과 작업 상태를 연결하고, B가 번역 모델·프롬프트·수치/용어 품질을 담당한다. C는 '한국어 번역' 표기, 인쇄 번호 우선 표시와 파일 이동의 물리 페이지 사용을 연결한다. 등록 비용·시간에 번역도 포함한다.

## 주별 진행

| 기간 | 공동 목표 |
|---|---|
| 1주 | 샘플·모델·계약 고정 후 로컬 등록→검색→답변→출처 연결 |
| 2주 | 중단·삭제·경로 제한·근거 검증, 목적별 요약/가이드 |
| 3주 | 다른 팀원 PC 설치·고정 문항 평가·수정·시연 |

첫 주 말에 기본 Q&A가 안 되면 선수 개념 고도화를 멈추고 통합에 집중한다. 2주 말에는 기능 추가를 멈춘다. 각자 완성 후 마지막에 병합하지 말고 짧은 작업 단위로 통합한다.

## 교차 평가

세 명이 문항·검수를 분담한다. B가 조정한 답변의 최종 평가는 A·C가 교차 확인한다. 수치·비교·인과와 근거 부족은 2인이 확인한다. 설치는 작성자가 아닌 다른 팀원 PC에서 재현한다.

로컬 폴더 탈출·잘못된 버전 근거·삭제 자료 재게시·키 노출을 출시 차단 항목으로 둔다. 다중 사용자 격리 검증은 공동 서버 단계로 미룬다. 외부 참여자가 없으면 사용자 만족도를 검증했다고 표현하지 않는다.
