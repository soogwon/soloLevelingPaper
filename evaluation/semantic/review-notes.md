# 합성 기대 판정 검토 메모

2026-10-28 기준 모든 사례는 파일상 `draft`다. 아래 사용자 검토 의견을 받았으며,
판정 기준의 일관성과 보류 항목을 확정한 뒤 데이터에 반영한다.
아래는 검토할 쟁점을 정리한 메모이며 정답 승인 기록이 아니다.

## 검토 순서

1. 원문을 먼저 읽고 주장 전체의 조건·방향·인과·비교 기준을 확인한다.
2. 기대 판정과 사유가 원문으로 뒷받침되는지 검토한다. 모델 출력에 맞춰 정답을 바꾸지 않는다.
3. 합의한 사례만 `reviewed`로 변경하고 검토자·날짜·판단 근거를 이 문서에 기록한다.
4. 판정 경계에 합의하지 못하면 `ambiguous`로 지정한다. 내용 변경 시 데이터 버전도 올린다.
5. holdout을 지침 튜닝에 사용했다면 새 평가 자료를 확보한다.

## 우선 확인할 판정 경계

| 대상 | 확인할 내용 |
|---|---|
| temperature | only 조건과 모든 온도라는 주장의 명시적 모순을 단순 조건 누락과 구분 |
| direction·causality | 원문에 없는 방향·인과를 추가한 경우와 원문이 반대라고 명시한 경우 구분 |
| metrics | 순차 연산 수와 총 계산량을 같은 성능 지표로 취급하지 않는지 확인 |
| compound | 일부 절만 지원될 때 부분 지원으로 볼 범위 합의 |
| translation | 의도적인 오역 대신 원문을 기준으로 판단하는지 확인 |
| crosspage | 앞뒤 두 근거를 함께 읽어 조건을 복원하고 각 근거 ID 유지 |
| crosspage-error | n < d에서 성립한다는 원문만으로 n > d의 결과를 반증할 수 없음. 판단 불가와 부분 지원의 경계를 사람 검토에서 확정 |
| truncated | 뒤 조건절이 없을 때 변수 이름이나 '충분히 작다'만으로 조건을 완성하지 않음 |
| holdout | 숫자·지연·정보 부재·근거 결합 사례를 개발용 결과와 분리하여 검토 |

외부 API 실측 전 검토가 권장된다. 초안으로 예비 실행하더라도 검토 완료 점수로 취급하지 않는다.
이는 사람의 기대 판정을 별도로 확인하는 [평가 모범 사례](https://developers.openai.com/api/docs/guides/evaluation-best-practices)와도 일치한다.

## 사용자 검토 의견 — 2026-10-28

- temperature, direction, compound, translation, crosspage, truncated, latency, absence, combine: 현재 기대 판정에 동의.
- causality-error, metrics-error: `undetermined`로 수정 요청. 이에 맞는 사유·판정 기준 정리는 후속 작업이다.
- dose-error: `contradicted`로 수정 요청. 현재 원문은 다른 조건의 결과를 명시하지 않아
  부분 지원 유지 또는 원문 보강 중 어느 방향으로 정리할지 추가 확인이 필요하다.
- 페이지 밖 연결 문장 보충 정책에 합의했지만, 뒷부분이 주어지지 않은 truncated 검증 입력은
  여전히 판단 불가 사례로 유지한다. 검색 보충과 주어진 근거의 의미 판정은 별도 검사다.
