# 의미 검증 합성 평가 자료

`cases.json`은 실제 논문 인용 없이 이 작업에서 작성한 합성 자료다.
프로젝트 라이선스에 따라 관리하며 실제 논문·사용자 데이터의 재배포 허가를 뜻하지 않는다.
실행 방법은 [평가 안내](../../doc/setup/semantic-evaluation.md)를 참고한다.

## 기준

| 판정 | 기준 |
|---|---|
| supported | 실제 인용 원문이 주장 전체의 사실·방향·조건·인과·비교 기준을 뒷받침 |
| partially_supported | 일부 사실은 확인되지만 조건·방향·인과 등을 추가하거나 일부 절이 미지원 |
| contradicted | 실제 원문과 명시적으로 반대되는 주장 |
| undetermined | 무관하거나 잘린 근거 등으로 판단 불가 |

원문이 특정 조건만 말한다고 해서 반대 조건의 결과까지 반증된 것으로 보지 않는다.
번역이 원문과 다르면 원문을 기준으로 판정한다. 모델 출력은 정답을 결정하는 근거가 아니다.
사유는 기존 `SEMANTIC_REASON_RULES`의 허용 조합만 사용한다.

## 데이터 계약과 검토

- schema_version은 자료 형식, dataset_version은 내용 버전이다. 내용 변경 시 버전도 올린다.
- 각 사례는 하나의 주장(여러 절 포함 가능), 실제 인용한 근거 목록, 기대 판정·허용 사유·판단 이유를 갖는다.
- 모든 24개 사례의 기대값은 `draft`다. 사람이 검토 완료한 정답으로 표시하지 않는다.
- 검토자는 원문만으로 각 절의 의미가 확인되는지 읽고, 합의한 경우 `reviewed`로 변경한다.
  판정 경계에 합의하지 못하면 `ambiguous`로 지정한다. 애매한 사례는 점수에서 제외하고 실행 건수에는 남긴다.
- 초안 포함 수치는 잠정 집계다. 배포 승인이나 일반적인 모델 성능의 근거로 사용하지 않는다.
  실행 결과의 reviewed_summary는 검토 완료 사례만 집계하며, development/holdout별로도 분리한다.
- development 16개, holdout 8개로 나눈다. 같은 원문의 정상/오류 변형은 같은 group·split에 둔다.
- holdout은 지침 개발에 사용하지 않을 별도 평가용이다. 저장소에 공개되어 있어 비밀 평가 자료가 아니다.
  튜닝에 사용했다면 별도 평가로서의 지위를 재검토하고 새로운 자료를 준비한다.
- `text_ko`는 선택 번역이다. translation 그룹은 의도적인 오역을 포함한다.
- `follows_evidence_id`는 앞선 인용 근거를 가리킨다. 페이지를 넘는 조건도 별도 근거 ID와 페이지를 유지한다.
- 사례·근거 이름은 모델 입력에서 의미 없는 ID로 치환한다. 원래 ID는 결과 대응에만 사용한다.
- truncated 두 사례는 다음 조건절이 제공되지 않은 입력이다. 범위를 벗어난 원문을 보충하지 않는다.

## 검토할 범위

조건 누락·방향성 추가·인과관계 확대·계산량 혼동·복합 주장 일부 충족·번역 불일치·
여러 페이지 조건 결합·잘린 조건·숫자 모순·정보 부재·여러 근거 결합을 포함한다.
이 작은 합성 세트로 실제 PDF의 추출·번역·검색 품질까지 판단하지 않는다.
